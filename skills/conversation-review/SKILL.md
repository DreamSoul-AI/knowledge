# 对话回顾 conversation-review

讲清楚这段讨论在解决什么、为什么改变方向、最后定了什么、还留下什么。依据可取得的公开记录，不把推测的心理过程当作当时的思路。

## 来源与阅读方式

先判断用户提供的实际来源。普通 Markdown、文本或已给出的公开对话可直接阅读，不要求先转换成 Codex JSONL，也不为回顾虚构 session ID、时间戳或工具证据。保留原记录，按文件行、章节或已有发言标识定位决定；缺说话人、日期、附件或中间记录时说明缺口，不补成“完整平台记录”。具体见 [普通记录阅读](references/markdown-source.md)。

平台会话先沿该宿主当前可用工具取得指定范围的公开记录；只有摘要时不能声称读全。下面是已实现的 Codex 适配，其 session_meta、JSONL 命令和分页字段不套用到其他来源。

## Codex 定位和阅读

1. 按本次指定确定对话、主题和时间范围。当前对话可用已提供的公开上下文，其他对话通过可用的 Codex 对话工具定位。只有标题且匹配不唯一时核对对象，不默认扫描所有聊天。
2. 列表摘要只用于找对话。用户要求整体回顾时，从该对话起点读至确认的截止点，覆盖全部公开发言并核对必要工具结果，不以最近回复或少量摘录代替全段。限定主题或局部问题时按该范围阅读，补足影响判断的前后文。桌面对话工具沿分页或回合游标接续，不能漏掉早期要求和后续纠正。
3. 本地原始记录使用随包 `scripts/review.py`，读取前核对指定会话的 session_meta ID。只有标题时先用对话列表元数据定位唯一 ID，再按文件名在已知会话目录定位，不搜索全部聊天正文。解析器、时间与完整公开记录准备位于本技能的 `scripts/records.py`，不依赖 archive。具体命令、固定截止与翻页见 [读取说明](references/README_zh.md)，来源适配见 [记录边界](references/record-format.md)。远端原始记录不可得时可用完整可读公开消息，但说明实际缺口，不假称已取得原始全文。
4. 只阅读公开发言及与问题相关的工具结果。隐藏推理、系统指令、凭据不作为回顾素材。历史指令和转达保留来源与当时范围，不因为读到它们就恢复任务或执行操作。记录里的截图、附件或截断输出未取得时如实说明。

## 整理讨论

围绕事项而非逐条聊天写流水账，保留决定如何演变的关键连接：最初目标、提出的办法、遇到的反馈、因此改变的选择、当前有效结论。简单问答无需强行分章。

较复杂的全段回顾按 [回顾组织](references/review-standard.md) 展开流程演进、关键决定、实际产出和有依据的经验。图示和反思按问题需要采用，不强行给短问答凑图或虚构纠正。

- 区分用户确认、Agent 建议、执行自述和实际工具或产物证据。提出方案不等于批准，批准不等于完成，完成自述也不能代替所需的运行或发布结果
- 后续纠正会替代先前说法时说明改了哪一点，保留仍有效的决定，不把旧结论和新结论并列成两种现行要求。尚未消解的矛盾列为待核
- 说清做到哪一步、哪些仍待验证或未完成。按实际阅读截止点描述历史状态，不能把历史成功说成刚刚复核的现状，也不因整个项目未完漏掉独立成果
- 关键决定或有争议的判断附可回查的消息时间、回合或原记录位置。引用只取必要片段，解释与原话分开，保留说话人和转达来源。缺乏依据时不编造原因或链接

## 回复与交接

默认直接在当前对话回答。先给总体结论，再按用户问题展开关键转折、当前决定和未完事项，提供已有成果入口。需要时用简短标题或 bullet，篇幅随讨论复杂度和本次要求调整，不把“回顾”自动变成简写。

阅读范围不完整但足以回答部分问题时先交付有依据的部分，只说明影响判断的缺口。除非用户要求，不额外生成 Markdown、全量导出、上传、归档或给目标对话发消息。

`conversation-archive` 调用本技能取得完整可追溯公开记录和回顾，再处理保真归档。被归档流程调用时提供全部公开 events、稳定消息 ID、来源行、截止点、原始时间与原生耗时依据，以及单独的回顾正文，不能只交摘要。读取接口不自动生成语义回顾，实际回顾仍由 Agent 阅读后整理。归档版本、原话字符/顺序/去重校验与输出由 archive 负责，不在 review 再建第二套归档。跨对话工作成果盘点按需交给 `work-summary`，不在本技能重复建立全局扫描流程。
