# 工作区更新 Workspace Update

负责把一轮 Workspace 更新推进到实际采用和交付完成。用户说「看一下、检查」时给预览；要求更新时，先根据项目已有采用记录、发布配置及本次要求确定完整清单，再合并、发布和同步。范围明确为单项目时只更新该项目；整轮更新覆盖清单内所有已采用项目和配套位置，沿用既定排除项。清单不明确且会扩大写入范围时先确认。交付给使用者能核对的版本、变化及实际生效状态。

## 确定整轮范围

- 读取模板采用记录和发布说明，列出本轮来源、接收项目、目标分支、本地采用目录、云端原版与阅读版、模板、教程和下载包。区分已完成、待更新、排除及受阻项；按各对象实际适用范围采用。清单、采用版本、排除及未完成事项更新到项目已有采用记录，临时目录保存原始回执。整轮更新还核对已使用的 Skill 及其依赖，已有适用版本可记录无需更新。
- 跨仓库逐个读取当前规则、仓库专有配置和已有 PR，保留项目差异及分支关系。明确采用的下游分支从约定上游同步并单独验收。机器路径与真实个人文件继续留在本人本地配置。

## 找到当前在用的入口

- 读取项目 AGENTS.md、REPO.md 和已有更新记录。定位实际采用的通用或研发模板、适用规范和本轮需要更新的文件。Workspace 的模板、教程和已接入项目分别有版本。DreamSoul 先查 [Workspace 使用教程](https://github.com/DreamSoul-AI/workspace/blob/main/%E4%BD%BF%E7%94%A8%E6%95%99%E7%A8%8B.md)，其他项目使用自己的来源。
- 从项目规则、任务配置或使用者指定范围定位本轮 Skill 及实际读取目录。区分项目副本、用户安装和平台内置技能。同名有多个副本时核对优先级及直接路径。只处理已采用或明确指定的 Skill。共享安装目录影响多个项目时，核对本次范围后再写入。
- 默认取对应来源的正式发布版或已配置版本。明确指定的工作分支或提交可用于试用，写明该引用。固定所读版本及来源，避免在一次更新内混用不同快照。来源不可访问时说明该项当前无法核对，并继续处理独立项。

## 比较并准备落盘

- Workspace 按文件核对已采用的模板、项目现稿及目标模板。旧版本有依据时可在临时目录用 `git merge-file -p --diff3 <项目副本> <旧模板> <新模板>` 做三方比较。检查合并结果与项目适用性，保留现有专有规则和入口。旧版本不明时，基于两边正文逐条选择有依据的更新，保留拿不准的差异。现有 USER.md 和本地凭据保持本地，个人条目沿用本人填写。模板新增字段可列给本人选填。
- Skill 以完整安装目录为单位核对 `SKILL.md`、元数据、引用及实际依赖。先将目标包放进临时目录验证结构，把安装目录与已知旧版和目标版比较。文本比较可统一换行符，资源按原始内容核对。识别本地定制，核对旧版已经停用的文件和包内相对链接。需要人为取舍的重叠改动保留现稿并列出差异。确认可应用后再以完整目录切换，保留可恢复的本地副本。
- 同轮检查两边的依赖。新版 Skill 需要新规则而该规则仍有冲突时，将受影响 Skill 一并保留待处理。无关项可继续。实际写入前核对文件仍与预览一致，先合并适用内容，再按格式和改动范围写入，保留原编码及换行格式。失败时恢复受影响项，并明确报告结果。

## 验证能否用上

- 回读最终文件，核对项目规则及个人配置、相关入口、Skill 包内引用和关键变更。用一个已有任务确认它会找到适用规则和目标 Skill 目录。若运行器同时发现多个同名 Skill，验证行为时使用本轮目标的明确路径。分别汇报文件更新、运行器发现、实际调用的结果。
- 复跑同一来源版本应得到无需变更。报告注明来源、版本、实际落盘位置、处理结果、未处理的冲突和需要重新加载的地方。

## 发布、分发与收尾

- 按已取得的授权和各项目流程完成提交、推送、PR、检查与合并；已有同范围 PR 就地更新。授权已覆盖整轮时连续推进，确有尚未授权的操作或阻塞再说明具体事项。依赖其他技能、CLI 或平台工具执行的配套操作仍由本技能跟进到核验完成。
- 模板发布后，继续同步清单中的采用仓库、本地规则、云端原版和阅读版、模板、教程及下载包。逐仓比较适用内容，记录实际来源和采用范围，单项更新保留原整版基线。正式分发使用空白个人模板或经授权示例，保留已有个人填写。
- 逐仓回读目标分支，核对项目专有约定、必要检查及实际入口；逐项回读云端和本地成果，下载包核对内容，需要字节一致时回下载比较。保留当前任务之外的修改，清理本轮已合并且不再使用的临时分支，保留长期分支。
- 最后按清单分别报告远端分支、本地工作区、技能安装与实际调用的更新及核验状态，附 PR 与入口。有未提交改动而保留的本地工作区记录为待同步。只有所有适用对象已完成或已明确说明例外，才结束整轮更新。

例如，`用 $workspace-update 更新这个项目已采用的 Workspace 模板和 Meeting Minutes，保留项目规则与个人配置，核对日常任务实际读取的版本。`
