# 工作区更新 workspace-update

负责将本轮选择范围内的Workspace更新到实际采用并核对结果。默认更新明确目标工作区的本地规则、模板和已采用能力，不因采用记录列有其他仓库就自动向它们分发。用户说「看一下、检查」时只给预览；要求更新时，先合并适用内容，再按已选范围落盘或交付，保留项目和个人设置。

## 选择更新路径

**本地更新，默认。** 根据当前目标和采用记录更新本地规则、模板及已采用能力。可以读取GitHub正式版作为来源，但不因此提交、推送、创建PR或更新其他仓库。没有选择远端交付时，本地更新及回读完成就是本轮交付，不把远端发布、云端或ZIP变成默认尾项。

**同时更新组织仓库，可选。** 本次明确说“同时更新组织仓库”等自然要求，或实际运行配置已选此路径时，沿已有配置与采用清单取得organization、repo、目标分支和排除项，按下文跨仓流程处理。清单存在不等于选中了分发，不要求用户每轮重列已知目标，也不把组织名理解为遍历全部仓库。配置可用 `github_distribution.enabled` 表达该选择，这是配置字段，不是CLI参数。组织分发不自动包含云端或下载包，这些交付按本轮另行选定的范围进入原有流程。

结合本轮目标、使用者维护职责和上下文，必要时简短提示可同时分发，不固定追加确认问题。用户未选择时继续默认本地工作；目标或授权的关键歧义只影响对应分发项，不拖住独立的本地更新。

## 确定整轮范围

- 读取模板采用记录和发布说明，先列本轮本地目标和来源，再按已选交付范围纳入接收仓库、分支、云端原版与阅读版、教程和下载包。区分已完成、待更新、排除及受阻项；按各对象实际适用范围采用。清单、采用版本、排除及未完成事项更新到项目已有采用记录，临时目录保存原始回执。核对本轮已使用的Skill及依赖，已有适用版本可记录无需更新。
- 选择组织仓库分发时，逐仓读取当前规则、仓库专有配置和已有PR，保留项目差异及分支关系。明确采用的下游分支从约定上游同步并单独验收。机器路径与真实个人文件继续留在本人本地配置。

## 找到当前在用的入口

- 读取项目 AGENTS.md、REPO.md 和已有更新记录。定位实际采用的通用或研发模板、适用规范和本轮需要更新的文件。Workspace 的模板、教程和已接入项目分别有版本。DreamSoul 先查 [Workspace 使用教程](https://github.com/DreamSoul-AI/workspace/blob/main/%E4%BD%BF%E7%94%A8%E6%95%99%E7%A8%8B.md)，其他项目使用自己的来源。
- 已采用的Knowledge技能和工具默认交给 `knowledge-update`。先找到当前环境可读的该技能；同一分发中的入口是 [knowledge-update](../knowledge-update/SKILL.md)，也可使用本次已给出的实际路径。缺少依赖时说明具体入口缺口，继续独立的模板工作，不另写一套技能更新逻辑。
- 默认取对应来源的正式发布版或已配置版本。明确指定的工作分支或提交可用于试用，写明该引用。固定所读版本及来源，避免在一次更新内混用不同快照。来源不可访问时说明该项当前无法核对，并继续处理独立项。

## 比较并准备落盘

- Workspace 按文件核对已采用的模板、项目现稿及目标模板。旧版本有依据时可在临时目录用 `git merge-file -p --diff3 <项目副本> <旧模板> <新模板>` 做三方比较。检查合并结果与项目适用性，保留现有专有规则和入口。旧版本不明时，基于两边正文逐条选择有依据的更新，保留拿不准的差异。现有 USER.md 和本地凭据保持本地，个人条目沿用本人填写。模板新增字段可列给本人选填。
- 同轮默认调用一次 `knowledge-update`，传入检查/更新模式、目标工作区、已有采用清单和实际位置、固定来源版本、授权、排除项及需保留定制；已有文档或自然语言均可，不让用户重新列范围。只检查Workspace时也只检查Knowledge，不写目标。没有采用项时如实记为无需处理。同轮已完成的相同实际目标复用结果，不重复全扫或安装；`knowledge-update` 不反向调用本技能。
- 同轮检查两边的依赖。新版 Skill 需要新规则而该规则仍有冲突时，将受影响 Skill 一并保留待处理。无关项可继续。实际写入前核对文件仍与预览一致，先合并适用内容，再按格式和改动范围写入，保留原编码及换行格式。失败时恢复受影响项，并明确报告结果。

## 验证能否用上

- 回读Workspace最终文件，核对项目规则、个人配置及相关入口；Knowledge部分复用 `knowledge-update` 返回的逐项来源版本、实际位置、保留差异、更新/无需变化/冲突失败和验证结果，接入已有采用记录。文件更新、运行器发现和实际调用分别汇报，不能以依赖技能的一句完成代替实际回读依据。
- 复跑同一来源版本应得到无需变更。报告注明来源、版本、实际落盘位置、处理结果、未处理的冲突和需要重新加载的地方。

## 发布、分发与收尾

- 本节只处理本轮已选的远端及配套交付。默认本地路径不进入提交、推送和跨仓分发；选择组织仓库时只处理已确认清单及分支，云端、ZIP等沿各自已选范围处理。
- 按已取得的授权和各项目流程完成提交、推送、PR、检查与合并；已有同范围 PR 就地更新。授权已覆盖整轮时连续推进，确有尚未授权的操作或阻塞再说明具体事项。依赖其他技能、CLI 或平台工具执行的配套操作仍由本技能跟进到核验完成。
- 本轮包含模板发布时，继续同步所选交付清单中的采用仓库、本地规则、云端原版和阅读版、模板、教程及下载包。逐仓比较适用内容，记录实际来源和采用范围，单项更新保留原整版基线。正式分发使用空白个人模板或经授权示例，保留已有个人填写。
- 逐仓回读目标分支，核对项目专有约定、必要检查及实际入口；逐项回读云端和本地成果，下载包核对内容，需要字节一致时回下载比较。保留当前任务之外的修改，清理本轮已合并且不再使用的临时分支，保留长期分支。
- 最后按清单分别报告远端分支、本地工作区、技能安装与实际调用的更新及核验状态，附 PR 与入口。有未提交改动而保留的本地工作区记录为待同步。只有所有适用对象已完成或已明确说明例外，才结束整轮更新。

例如，`用 $workspace-update 更新工作区` 默认更新明确本地目标；`同时更新组织仓库` 则复用已有配置选择组织分发，不需要背固定调用话术。
