# 通用会议纪要

从会议原始记录整理可追溯的纪要，适用于评审、研讨、项目会、业务沟通和例会。按实际会议系列分类，不把所有会议默认归入例会。

## 安装与环境
安装整个 `skills/meeting-minutes` 目录，保留 `SKILL.md`、`agents/` 和 `references/`。本技能无需安装本仓库的其他技能。

读取飞书材料需要已有 `lark-cli`、当前用户的资源权限，以及流程所引用的日历、会议、文档和共享飞书技能；这些服务工具不包含在本包中。直接处理本地转录无需先查询日历。执行遵循当前项目规则与授权。

## 使用
```text
使用 $meeting-minutes 整理本周已结束的产品架构研讨，保留原始记录，按实际会议系列归档。
```
也可提供会议、妙记或文档链接、明确标识、本地转录。按需指定日期范围、时区与输出位置。未指定范围的自动扫描默认处理用户当地今天已结束的日程，DreamSoul 默认时区为 Asia/Shanghai。

## 传入材料与规范
支持在调用中提供正文、本地文件或可访问链接，无需固定参数格式：
- 原始材料：本场转写或会议笔记，保留来源及实际覆盖范围
- 补充材料：前次纪要、项目背景、相关记录和人工更正，保留各自日期及事实边界
- 适用规范：本次或项目的整理、格式和交付要求，模板可选

```text
使用 $meeting-minutes 整理这场会议。
原始材料：./材料/本场转写.md
补充材料：./材料/前次纪要.md、./材料/项目背景.md
适用规范：./规范/会议整理要求.md
输出位置：./会议成果/
先保存本地。
```

先读规范正文及本场相关引用，按其要求组织成果和核对。专项规范可以要求建议、周回顾或采用其他结构，通用大纲只补未规定部分；没有专项规范时沿用适用项目规则或技能默认做法，没有模板不影响整理。只有本场材料也可直接使用。

补充材料用于理解背景，旧决定不写成本场新决定。材料或规范不可读、相互冲突时明确缺口及影响，不补造内容或声称已按缺失规范完成。规范中的上传、通知、修改源资料和调度安排仍按本次实际授权执行。

项目可提供独立的通用会议规范，并在其适用范围内叠加专项规范，分别通过“适用规范”输入传入。规范正文留在项目中维护，不复制为技能包的私有必需文件；没有项目规范时技能仍可独立处理材料。

## 流程与成果
日程实例关联实际会议后，获取 Note 或 Minutes 的原始逐字稿，并核对手工绑定笔记中的更正。保留原始材料和来源映射，再完整阅读原文，按议题组织决定、汇报、行动及待确认问题。[来源链路](sources.md) 说明不同产物的读取方式。

未知说话人不补身份，负责人或期限缺失时保留待确认，条件与撤回不遗漏。日程存在不等于实际参会，引用有效不等于语义正确。再次运行先比较原文、已有成果与人工修订，避免重复创建或覆盖。

面试或招聘沟通按项目当前招聘规范及可选的 [面试类会议整理](interviews.md) 处理，无需额外安装面试专用技能。

## 自动化边界
一次调用完成一次扫描整理。安装本技能不会启动定时任务、加入或录制会议、上传文档或发送通知。同步和定时执行按用户当次明确范围配置。

已做格式、引用与合成场景流程核查；不同环境的真实日历、录制权限和逐字稿端到端获取仍需实际验证。

## 可选交付处理器
整理与交付分开：可提供处理器、目标、上传规范和交付记录位置，本地成果检查完成后再按本次授权交付。可选择 document-sync 并提供外部交付配置，会议交付明确使用 upload 方向，不自动启用下载，目前实现飞书，其他平台需对应适配或处理器；这不是必装依赖。未指定时保留原调用方式，交付失败也保留已完成的本地文件。
