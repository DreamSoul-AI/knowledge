# Codex 连接 Grok Bot

本页把原飞书教程的 CLI、MCP 和故障判断整理成可离线阅读的步骤。上游是社区项目，桌面端登录仍依赖实际环境。[原接入教程](https://dreamsoul.feishu.cn/docx/Sqsdd69p7osKAqxx5UwcJeOEn1e) · [上游项目](https://github.com/ScriptedAlchemy/grok-bot-cli)

## 优先复用已验证入口

本次明确指定 MCP 或其他入口时，先沿该要求核对可用性。否则看项目已有入口及明确指定的本机配置，查找已验证的运行入口，例如配置中的 `verified_local_cli`。只在已知范围定位，不扫描全盘找修复副本。把以下信息合起来判断，文件存在不等于当前能力已验证：

- **入口及依赖**，核对入口、解释器与相邻依赖是否完整，相对依赖沿入口或配置的实际约定解析
- **版本及证据**，查看配置关联的版本、修复说明和最近有效回执，区分帮助正常、名单成功和真实会话回读
- **运行方式**，读取必要的工作目录、环境变量及参数。专用适配器可能用名单命令触发回读，省略只读模式也可能进入发送分支，不能只看命令名称
- **本次能力**，核对已验证的是哪些目标、历史标记回读、通用会话读取、游标还是发送。部分修复不能推成所有接口均正常

入口适合本次操作、依赖齐全且证据仍适用时，按配置复用。需要当前状态时，在本次授权内做必要只读核查，不能把历史回执当成刚完成的读取。目标的名称、账号、数字 ID 与 agent UUID 按相应接口和实际返回绑定，不相互替换，也不靠重名猜测。

入口缺失、依赖不齐、证据失效或能力不匹配时，说明具体哪一段不可用，再按下节的现有安装或故障说明诊断。不要静默退回已知会失败的全局入口，或覆盖、迁移正在使用的修复副本。个人路径、标识、凭据和修复副本位置由本机配置维护，共用技能不保存这些值。

## 安装和只读验证

未配置有效的适用入口时，再检查普通 CLI。在运行 CLI 的设备打开 Grok Bot 桌面端，使用同一操作系统账号，并确认桌面端可见目标 Bot。Node.js 要求为 22.19.0 或更高。先检查现有安装，缺失时按本机环境安装上游包。下例固定到曾核对的版本。

```text
node --version
npm install --global grok-bot-cli@0.12.5
gbot --help
gbot doctor --json
gbot bots list --json
```

只检查安装时运行帮助即可。诊断和名单查询依赖本机桌面会话和实际资源权限。若 Windows 找不到命令，重新打开 PowerShell 后用 `Get-Command gbot` 检查。若从 knowledge 工具目录启动，将命令中的 `gbot` 替换成 `node gbot.mjs`，并按工具 README 安装依赖或指定已有包。

## 一次收发验证

只有在用户已经指定实际目标并授权发送时才运行发送。使用唯一短编号，取得回执后从同一会话查找该编号对应的回复。回执证明受理，真实回复才证明此次往返有效。

```powershell
$bot = '<已核对的完整 Bot 名>'
$marker = 'Codex 连通测试 ' + [guid]::NewGuid().ToString('N').Substring(0, 8)
gbot send $bot "请回复 $marker" --json
gbot thread $bot --json
```

暂未回复时只继续读取。发送状态不明时先查编号是否已出现。连续读取可以使用 `gbot thread --after <条目 ID>`，游标失效要按返回标识处理，不能把重新出现的历史消息当成新增。

## MCP 和 Windows 路由故障

使用已安装的 Grok Bot 插件时，先检查当前 Codex 会话加载了哪些工具。只读先使用 `gbot_thread`，需要正文时按当期工具参数打开全文。已授权发送才使用 `gbot_send`，支持时选手动回读，再用相同目标读取真实回复。插件入口和版本条件见[上游说明](https://github.com/ScriptedAlchemy/grok-bot-cli#plugins)。

如果帮助正常而 `bots list` 或 `gbot_thread` 返回旧网关路由 404，先核对配置是否已有适用修复及其有效回执，再记录系统、桌面端版本和 CLI 版本，查看 `doctor` 的认证来源状态，比较[上游问题 #168](https://github.com/ScriptedAlchemy/grok-bot-cli/issues/168)。原飞书教程保存了 Windows 隔离副本的完整步骤和脚本，建立在 0.12.5 的特定日志和环境上。知识库的启动器直接调用上游 CLI。不要从示例复制账号、设备标识、会话凭据或真实目标。

若只需排查 Windows 0.12.5 名单查询，从 knowledge 的工具目录运行 `node gbot.mjs --windows-roster-fix`。复用已安装包时在该参数前加 `--package-dir <已安装包目录>`。这条路径与飞书教程采用同一修订方法，范围只包含名单读取。

普通全局版 0.12.5 仍可能在 `listAgents` 返回 404。`--windows-roster-fix` 的名单成功不能证明会话读取、发送或实际回复已修复。若配置记录了另一专用回读入口，应按其能力及运行方式使用，不将固定历史标记冒充通用消息游标，不把旧询问视为本轮新发送。只需读取时不发送新询问，发送仍按本次明确授权处理。

历史 Windows 试跑分别验证过从 Codex 发出消息和由 Codex 主动读回回复。Bot 主动向 Codex 回传属于单独路径，需要按目标设备与会话重新验证。逐段报告实际结果。
