# 项目进展同步 project-progress-sync

[English](README.md) | 简体中文

可选输入接口见[配置示例](inputs.example.yaml)，日志、表格、规范、别名和前次报告都由实际项目提供。比较新旧快照时只比较两边实际读取的共同字段。「未读取」与空值、0 是三种不同情况。接续旧报告先核对版本及原范围的修订，未变快照可复用，对新增证据重新判断，不将旧建议视作已采纳。

适合成员更新总表前自查，也可用于按指定范围汇总多人日志。可以用现有日志链接、总表链接，或者本地日志和表格快照。安装时复制整个 `project-progress-sync` 目录到项目的 `.agents/skills/`，也可以直接把 [SKILL.md](../SKILL.md) 交给 Agent 试用。

```text
用 $project-progress-sync 对一下我本季度开始至今的工作日志和项目总表。
逐日核对工作日志，也检查总表里我负责的任务。结合会议及交付证据，
列出建议新增的项目或任务、已有记录的完成度调整和待校准事项。
只读核对，每条建议附依据及原记录入口。
```

默认按本季度开始至对账日处理，也可指定其他日期。总表有多个视图时，提供实际项目和任务子表或有权访问的范围。已有任务 ID、已确认别名和上次报告都可随输入给出。用导出快照时说明导出日期、视图和过滤条件。在线读取受当前账号和平台权限约束。

例如，两天日志分别写了「报表导出」和「导出缓慢的问题已定位」。项目和交付物都指向总表中现有的「报表导出优化」，就合为一条建议，附两处日志来源并把「已定位」作为进展。若总表还有另一条同名任务但属于另一个项目，关联证据不足时就列出两条候选。即使日志项打了勾，交付状态仍需独立证据。

查出漏记时，先看现有项目能否承接。提出新项目时给出独立目标、交付及拟归属，提出新任务时给出所属项目和独立交付。完成度调整列「现值 → 建议值」及证据。只有明确进展时，说明已完成和剩余工作，请负责人校准比例。先交一版只读建议，再按项目集中讨论需要决定的事项。复跑以当前总表为准。

## 可直接审阅的更新稿

需要本人手动核对时，按工作主题串起日志事项、总表具体记录、修改理由及剩余疑问。旧值与拟值或已写值分清；同轮已实际写回并回读的标明已更新，其余保留原值或待校准。复用快照时标明读取时间，不冒充重新在线查询。具体证据放对应明细，日志关键词只用于定位，不代替交付依据。

先用一页短表说本次最值得先改什么，再按事项给出「字段及现值 → 拟改文字或值 → 理由及来源」。总表建议和日志待办建议分开，旧候选标明承接去向。篇幅较长的说明放表外，证据留在对应条目或附件。

例如，总表「导出优化」已有描述“定位耗时环节”，日志随后记有修复及有限验证。可建议在任务描述追加“已修复所定位环节，样本验证通过；全量验收未完成”，而不是另建一条同义任务或把完成度改成100%。日志季度待办可接续为“导出优化：完成全量验收”；当天“修复导出”已勾仍保留。

若负责人已将上述阶段补入描述，并手动增加下一步计划，复跑保留这段人工内容，把补记建议标为已对应，仅列尚缺的验收。确有新成果时追加必要信息；冲突处单独讨论，不覆盖整段描述。仅核对时不执行写回；明确要求同步后按已确认范围执行，写前再读最新目标，写后回读。

完整对账从所选季度第一天查到约定截止日。当前季度可以直接查到今天，交付时列出缺失日期。结合季度目标、会议和交付回执检查实际各工作线。季度封账后，把结转前进度、当前表值及真实交付分开核对。某项封账变成 100% 且下季已有承接时，保留阶段成果和下季入口。上期完成度空白、当前表填了 0% 时，保留两个原值。需要建议比例时，依据已交付和剩余里程碑给出待校准的估计。

## 两种使用方式

只想核对时，可说“核对这个范围，先给我看差异，不写回”。需要执行时，可说“把已经确认的变化同步到对应任务和日志”，沿现有清单和授权处理，不必逐条重复确认。未确认的大范围调整单列，其他明确项继续。

同步前读取最新来源与目标，以稳定记录ID、任务关联和日志位置定位。当前值已等于拟值时不再写；无关人工字段保留；同字段与旧基线冲突时核查或集中校准。按字段或原文片段局部修改，不整份覆盖。新增任务先再次查重，写入结果未知先查询，成功后回读并保存实际对应关系，重跑只补剩余差异。

例如已确认任务进度由30%改60%，但写前读到负责人改成80%并追加验收计划：保留80%和计划，核对证据，不拿旧60%回退。总表中独立入职任务已完成时，日志可补“入职已完成，招聘继续”，不把“招聘及入职”整条机械勾完。适用项目规范、个人格式和平台权限仍从外部接入。

本轮隔离本地文件写入与真实平台同步分开判断。此技能不捆绑飞书、特定公司或个人路径，也不提供平台原子事务。旧本地候选名为log-table-reconciliation，现仅保留project-progress-sync一份技能入口，历史报告保留旧名来源身份。
