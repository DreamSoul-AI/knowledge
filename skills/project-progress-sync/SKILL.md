# 项目进展同步 project-progress-sync

对照工作日志和正式项目、任务总表，说明总表应补记什么、日志待办应怎样接续。优先利用已有任务保留独立成果，给出可审阅的拟改文字或值。本技能属于项目管理，可独立使用，也可由上层项目管理流程按需调用。核对模式只读，建议不等于已确认或已写回；明确要求同步时按已授权范围执行，不因名称改变扩大写入。

## 确定输入和覆盖

- 确定日志、正式总表、对账对象和日期。按用户指定的季度、范围和主题处理。未指定时，以项目时区从本季度第一天查到对账日；明确指定已结束季度且未给截止日时查到季末。可传入适用规范、项目映射、别名或上次报告，项目已有入口可直接沿用。
- 使用本地日志、表格快照或已授权的在线来源。核对正式项目和任务子表、身份、筛选、版本和分页。个人视图、仪表盘和副本有各自的覆盖范围。分别识别日志作者、执行人、表中负责人及关联人，按当前受众权限展示证据。
- 读取适用的项目管理、数据维护和文档规范，按当前字段类型组织建议。状态、进度和日期是公式或汇总时，追到可维护的来源字段，不建议直接覆盖派生值。
- 完整对账时，逐日读范围内的可用正文，并对照对象在总表中的全部任务。按日志实际出现的工作线，从日志找漏记的交付，从总表找有新进展的已有任务。结合季度目标、会议背景、会议总结、交付物或验收回执解释简写、责任及决定。没有日报的日期记入覆盖说明，相关会议或交付可以补证。
- 区分已做的工作、明确待办、想法、例行提醒和单纯标题。记录可追溯的日期和位置，明确本人负责、协作参与或他人负责。日志勾选、条目日期及文件时间只能作为线索，完成状态、实际完成日和负责人变更需要相应证据。

## 匹配和去重

1. 先按同一个真实可交付事项归并跨日重现的日志，保留各日期来源。同名但交付物、负责人或所属项目有实质差别的分别保留。父级主题和已有子任务分别找对应层级，同一变化只建议写到最合适的一处。
2. 优先核对明确记录链接或稳定 ID，确认它属于本次总表。再用已确认的别名、名称、交付物、项目、负责人、周期和上下级关系交叉匹配。文字相似只用于找候选。个人视图内找不到时，在本次允许范围内核对相关项目或协作者的任务，避免另建已存在的事项。仍有多条合理候选时列出各自链接及差别，保留待确认。
3. 先核对现有项目及其任务是否已覆盖工作内容。有持续价值的变化可建议补到原记录，指出具体字段、现值、拟补内容及依据。本人协作沿用原负责人和已有记录。新增任务需有独立交付或跟踪价值，并写明拟归属项目、负责人依据及查过的范围。只有现有项目无法承接，且该工作有相对独立的目标、产出和持续跟踪需要时，才提出新增项目；写明拟归属的上层目标及首批任务，依据不足的字段留待校准。覆盖足够且查无等价记录时列为「建议新增」，范围未确定的写「待确认」。
4. 重跑以当前总表为准。按总表、子表及稳定记录 ID 复用已匹配结论，按日志来源位置和实际工作事项归并重复建议；收到新证据或表内容变化时重新判断受影响项。旧建议已采纳时转为已对应或只列剩余差异。不要求在日志里看到总表每一项，近期日志未提及某任务也不能据此判定滞后。

## 判断完成度及其他字段

按原任务的交付范围核对已完成、待完成或已改变的里程碑，再比较表中的完成度、状态、负责人、预计和实际完成时间等相关字段。明确每项「字段、现值、建议值或待校准、依据」。有负责人确认或可复核计算口径时采用对应数值。用户要求给出判断时，可根据已交付和剩余里程碑给出用于校准的估计，说明采用的任务范围及验收条件，仍缺关键依据的保持待核。完成日期以确认的验收或完成事实为准。先核对项目及母项完成度是公式、汇总还是手填，提出相应层级的建议；公式项应追到来源字段，手填值由对应负责人校准。

有上次正式总表的同源快照时，按稳定记录 ID 比较两次读数，列出表内已新增、已调整的字段和范围变动，并与本次建议分开。优先呈现影响判断的完成度、归属、范围和日期；批量关联人等同类变动可汇总。留空与明确填 0 分开记录，新增到某人范围时核对原快照是否已有该记录。

比较前核对两次快照的字段投影、视图和筛选范围。只将两边实际读取的同一字段作值比较，某次未读取的字段标为「未读取」，不能补成空值或 0 后报告为业务变更。接口明示不支持的字段独立列为覆盖缺口。记录 ID 没出现在旧的过滤快照中，也不直接等于新建任务。

接续旧报告时，覆盖仍以本次约定的完整日期范围为准。核对来源版本或可用变更记录；未变部分复用有效快照，有变化时补读受影响范围。不能可靠定位变化时，再核对原范围，不能只查新日期而漏掉历史修订。保持未变证据的来源日期，新增和修订部分重新判断。旧建议不是已采纳决定，不因重跑重复提出同一任务，也不把未经重新核实的建议比例写成当前事实。当前范围和配置可参考[输入示例](references/inputs.example.yaml)。

已结束的季度如果结转过，优先对照结转前的同源快照、结转依据和当前表。区分已交付、因封账调整为完成、同一记录迁入下季、另有下季承接任务。分别保留原进度、结转后的字段和实际交付证据。承接判断要核对范围和负责人，已承接的沿用对应记录。历史 ID 查不到、承接关系或业务进度缺少证据时，注明缺口和可查的候选。

## 校准和交付

- 先用一页总览回答本次需要更新什么，按当前最值得先处理的顺序列短表。表内保留事项、现状、拟处理及必要数值，完整拟改文字、理由和来源放后面。按使用者已采用的文档规范组织，不用密集大表代替说明。
- 本人手动核对时，按工作主题展示「日志事项 → 总表对应记录 → 改动理由 → 剩余疑问」，并列旧值与已写值或拟值。日志条目只作定位时说明，成果依据另附直接入口，不把关键词匹配当验收。同轮已写回且回读确认的事项标为已更新，未改项、待校准项另列；保留上次读取时间，不把历史快照说成当前重新查询，也不让用户猜哪些仅是建议。
- 日志到总表：逐项给出记录入口、字段、现值和拟改文字或值，区分保留、修订、归并、补阶段成果和必要新增。描述补记时写清应追加的内容，保留现有有效说明及人工修改；同一成果在最合适的任务记一次，其他相关项引用。旧候选逐项接到已有记录、合并后的候选或待核项，不整批再列为新增。项目整体未完，也保留其中独立交付的成果。
- 总表到日志：分清逐日活动与季度待办，给出原条目和拟保留、改名、关联已有任务或补后续动作的具体文字。当天做过、整项交付、后续仍需维护分别判断；保留历史原话、本人勾选和强调，不把总表未完成直接变成当天未做，也不把当天勾选变成季度完成。只提出当前差异，不因生成建议而替用户转日或重建日志。
- 完成度有依据时给出拟值及口径；只能确认阶段时先给可用的进展文字，说明提高比例尚缺哪项验收或范围判断。日期和负责人也分别核对，不能为填齐表格造数。另列总表已实际发生的变化，注明读取范围、缺失日期和未覆盖资料。
- 继续处理有证据的事项，把影响归属、是否独立立项或进度值的疑点按项目集中给当前使用者或指定负责人校准。说明现值、候选选项、倾向及缺的证据。用户回答后，只更新受影响的建议并保留确认依据；结论分清有依据、本人已确认和仍待确认。没有回复时留下可继续讨论的清单。
- 同轮接续时比较最新现值、前次基线和已审建议，已采纳内容转为已对应，只列剩余差异；新的人工作业和计划调整优先保留，冲突处单独校准，不用旧整段覆盖新说明。在当前对话汇总必要问题。用户明确要求写回后，按下节同步流程处理已确认改动；核对、已授权待写、写入结果未知和回读完成分别报告。

## 核对或同步

默认先核对差异；本次明确要求更新、同步或已有仍适用的写回授权时，处理对应方向、对象及字段，不逐条重复索要相同确认。模式也可从实际配置读取，配置本身不产生业务授权。新增项目、改变任务范围或缺少依据的进度与归属集中校准，其他明确项继续。实际平台操作使用其现有读写工具，本技能不另建表格服务。

### 写入与回读

1. 将已确认内容形成局部改动：目标稳定ID或日志条目位置、方向、字段/原片段、预期值、拟值及依据。日志到总表优先补原任务与独立成果；总表到日志只处理对应待办或范围说明，不抹掉历史活动、本人勾选和格式。公式字段追到可维护来源，不用旧建议造比例或完成日。
2. 写前取得最新目标，并核对来源是否仍支持该改动。比较上次基线、已确认拟改与当前值：已相同则复用；无关字段或追加的人工作业保留；同一字段/片段已被人工改变时，不用旧值覆盖，也不机械取最大比例，先核查新证据或集中校准冲突，继续无冲突项。新增前按稳定关联与实际交付重新查重，避免重试创建同义任务。
3. 仅写本轮已授权的局部差异。支持版本条件或原子写入的接口按实际能力使用；不支持时缩小写入窗口并在写前再读，仍无法可靠保护的项单列，不假称事务或完全防并发。写入结果未知先查目标再重试，不为补回执重复新增。
4. 写后重新读取实际内容，核对值、上下级归属、必要原文及人工改动。按已对应关系保留来源位置、目标ID、读取版本、已确认差异、实际回读和剩余项。记录可以沿已有报告或状态文件，不强制另建服务或固定格式。部分失败保留已成功项，接续只补剩余项。

双向同步不是复制两份全文或让所有完成状态一致：当天活动完成不代表季度任务全部完成，总表完成也不能回写成某天做过。两方向引用同一成果时复用其身份与已写回记录，不把刚同步的文字再次识别为新成果。冲突和无法读取的方向明确保留，不把单边成功写成全部完成。
