# 飞书授权复用

让当前对话尽可能沿用已有授权，先查明不可用的原因，再处理必要的失败调用。切换聊天不等于需要重新登录；工作区规则可以统一调用方式，但不能改变操作系统的凭证访问权限。

## 核对已有授权

先定位当前环境的 `lark-shared` 技能，读取其身份与权限参考；执行命令前核对当前 CLI 用法。缺少该技能或 CLI 时说明具体依赖，不自行建立另一套认证实现。

```powershell
lark-cli auth status --json --verify
lark-cli whoami --as user
```

核对服务端验证、实际用户及 token 状态。`identity=user` 但 token 为 `missing` 仍不可用。身份有效时直接复用；代表用户访问业务资源时显式使用 `--as user`，按目标业务技能和原任务授权继续。只检查授权的请求不额外读取业务资源来证明成功。

## 先解释差异，再处理失败

遇到 `missing` 或其他对话可用、当前对话不可用时，按需读取 [诊断与验证边界](references/README_zh.md)。比较实际系统用户、CLI、应用、profile 及配置来源；环境变量相同不能代替实际进程身份，配置可读也不代表凭证可读。只保留必要的非敏感诊断字段，不打印原始配置、token 或密钥。

已有用户凭据仅在另一获准运行环境可用时，沿执行工具的正常审批处理这一次必要调用，说明具体操作及读写影响。获准后重新验证实际身份；不要复制凭据、关闭隔离或让所有命令无条件提升权限。审批拒绝时保留具体阻碍，不换入口绕过。

同一环境仍失败，再分清应用配置、用户授权 scope、目标资源权限与真实过期错误。用户身份有效但某份文档被拒绝，不等于未登录；应用缺权限也不靠用户反复扫码解决。仅在确需新增同意或既有登录无法恢复时，调用 `lark-shared` 对应流程，展示本次生成的链接与二维码，待用户完成后接续；不默认全量授权、注销或切换 bot。

## 接续与回报

只接续原任务中尚未成功且已获准的操作。写入结果不明时先回读，避免把认证重试变成重复写入。检查完成后说清当前可否复用、已核实的原因及具体未决项；不要只让用户再扫码。

多个对话需要采用时，各自使用本技能核对自己的实际环境。本对话检查成功不代表其他对话已核验。用户明确指定要联测的目标后，才沿可用对话工具发送限定请求并核对回执；没有目标授权时不主动向其他工作对话发消息。向 Workspace 交接的是调用入口与适用条件，不是凭据或未审的全局规则。

已验证的依据是同机、同实际用户环境中的两个独立进程实读，以及受限进程的身份差异。未证明所有桌面聊天自动选对环境、跨设备复用或真实过期刷新。CLI 的刷新机制与本次实际刷新结果分别报告。
