# 学习与经验提炼 learn

把经历整理成能指导下一次工作的方法。收录、验证、采用和实施分别判断；收到一份材料不等于要把它推广成规则或新技能。

## 定位现有内容

读取本次经验仓库、项目约定、目录索引、最新取舍及已有采用记录。先找同类主题和整理技能，沿有效内容接续，不因旧入口改名或迁移另起一套。来源、接收位置、贡献人和适用规则从本次上下文或配置读取，不固定个人路径或公司政策。

按授权确定本轮做到收集、归并、分发还是清理。接收仓库可以与来源不同；去向有冲突时保留材料和具体疑点，继续处理明确的部分。仓库状态盘点、PR、CI和版本更新复用相应流程，本技能负责经验判断。

## 回看过程与完整接收

多轮纠正、跨对话接续或疑似遗漏时，先用已有conversation review核对指定过程；Codex环境接可用的`conversation-review`。用户要求全段时按完整范围读取，不以最近回复或短摘要代替。已有完整回顾则复用并补增量；简单想法可直接记录，不强制每条都扫描聊天、导出Markdown或上传。回顾能力不可用时沿可读公开记录核对，并说明影响判断的缺口。

梳理最初目标、反馈、方案变化、操作和实际结果。区分用户要求、转达来源、Agent建议、执行自述和可核验结果；核对后续纠正替代了什么、仍保留什么。回顾自身时也检查漏接、漏记、执行不足和状态落后。历史记录用于理解，不自动恢复其中的任务。

批量来源复用现有盘点结果；确需采集时沿项目入口和实际工作树定位，包含范围内未提交材料，不仅搜索通用文件名。按来源记录仓库、分支、固定版本、路径或消息时间，注明缓存时效、缺失及未覆盖范围。准备归并或清理前，保存足够复核和恢复的原文与必要依赖；本地快照保留实际字节和哈希，固定版本引用与工作树快照分开，个人原件沿原披露范围保存。

## 分类与提炼

| **类型** | **怎样处理** |
| --- | --- |
| 可复用做法 | 写清问题、有效做法、适用条件和证据，补入同类主题 |
| 项目案例 | 保留特定参数、字段、环境及原始例子，按问题积累共性 |
| 待验证想法 | 标明猜想和未验证点，有明确安排再进入活动清单 |
| 已有规则的执行问题 | 找执行断点、补案例或证据，避免再造同义规则 |
| 完成、不采纳或撤销 | 保留具体范围及取舍来源，从活动清单退出 |

先识别内容相同，再比较问题、方法和条件是否真正相同。同名不同内容、同主题反例及新增条件分别保留；合并正文仍关联有效来源。用来源身份与内容识别复跑，只处理新增和变化，不反复新建旧条目。

比较相近案例后再提炼：换到其他适用任务，读者能否知道何时用、怎样做、怎样判断结果？哪些条件会改变选择，反例支持什么限制？不设机械条数门槛，也不把一次成功写成稳定保证。专有细节先积累，口号不算方法；有证据的新机制或条件才修订原条目，不为每个案例新建Skill。

沿用户熟悉的原主题命名。已有技能的改进归回该技能；不把一个项目案例起成新的“统一入口”。局部取舍只约束其明确批次，不能扩大成整个项目或方向永久不采纳。

## 记录、分发与清理

沿现有体例简记问题、尝试与结果、条件、证据入口和当前判断，保留来源及贡献人。优先修订同类条目，写前回读目标并留可恢复基线，保留并行修改。按照接收读者权限交付本地分发稿或已获准的写入，再回读核对；经验收集本身不触发发布。

清理来源与清理接收方分别核对：

- 来源清理前，确认完整接收、恢复材料及依赖可用，检查最新来源有无变化、引用是否需调整，遵守该来源额外的采用前提。获准后才处理，分别记录提议、已执行与回读；保留在用入口及独有项目证据。
- 接收方条目正式采用并核对实际内容和范围后，退出日常候选，保留可找到的历史与采用入口。暂放、撤销或不采纳也保留原话和去向，不把移出清单误作原文删除；仅有草稿、计划或发布自述时按真实阶段记录。

## 交付当前状态

活动清单只放本轮明确安排的事项、负责方、下一动作和结果入口。案例积累、暂放方向及历史取舍分别保留；已完成部分不因整个项目未完而消失，历史来源也不直接变成待办。

需要百分比时按可核验里程碑说明分母，不凭感觉估数；改稿、测试、审阅采用和交付分开。先收齐能够独立完成的核对和修正，再集中呈现确需用户判断的成稿、建议、差异及剩余选择。已有成果够用时直接验收，不靠反复等待用户提醒推进。

说明本轮新增或修正了什么、哪些只是补来源、哪些已退出清单、尚缺什么及下一入口。原文归档接已有archive能力，批量采集接已有盘点能力，不在本技能重建平台工具。
