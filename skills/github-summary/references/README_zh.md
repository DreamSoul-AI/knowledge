# GitHub 汇总

分步读取指定仓库、分支和本地 Learnings，完整接收经验原文，按最终接收方整理候选，并结合适用外部规范检查仓库状态。适合 Learnings 汇总、跨仓库经验接收和已采用条目的收尾。

## 开始使用

从 knowledge 的 `skills/github-summary` 安装完整技能目录，也可显式提供本技能的 [SKILL.md](../SKILL.md) 使用。SKILL、元数据、引用、脚本、测试和许可证一起保留。

~~~text
$skill-installer
请安装 https://github.com/DreamSoul-AI/knowledge/tree/main/skills/github-summary
~~~

```text
用 $github-summary 盘点 A 仓库的 main/dev 和 B 仓库的 main，
加上我指定的本地 Learnings，采用我提供的《团队仓库使用约定》。
先说明每步会读写什么，再把完整原文接到这个本地工作区，
按原定接收方归并，列清已采用、待审阅和建议清理的条目。
同时检查适用的 Actions、PR、分支和文档入口。
这次来源只读，原文和报告仅写到指定临时目录，不改正式 Learnings、不发布。
```

请把 A/B 换成实际仓库，提供接收位置。可补充旧接收记录、已确认去向、固定提交、外部规范和允许的清理范围。规范可以是本地文件、可读文档链接或项目既有入口，不强制另填配置文件；未提供专有要求时使用通用流程，不推定公司名单或例外。

## 步骤和影响

默认完成本轮范围内适用的步骤，明确限定只读或某一阶段时遵循当次要求。开始前说明哪些会落盘、哪些需要修改来源或远端对象，已有明确授权不重复申请。

| 步骤 | 做什么 | 写入范围 |
| --- | --- | --- |
| 明确范围和规范 | 确定来源、接收位置和规则 | 本轮范围记录 |
| 盘点固定版本 | 读取分支和来源原文 | 本轮来源记录 |
| 接收并归并 | 保存原文、索引及经验条目 | 指定本地接收位置 |
| 检查仓库 | 读取 Actions、PR、分支、导航 | 本轮检查记录 |
| 展示结果 | 给出变化、发现和处理建议 | 本轮报告 |
| 授权收尾 | 跟进修改、采用或清理 | 已确认的具体目标 |

保存快照和归并经验不等于 Git 分支合并。只读来源时可以写获准的临时接收目录，但不改源文件、正式 Learnings、分支或平台设置。执行来源清理、合并或删除分支、停用 workflow、提交发布时，分别核对该动作的授权和影响。

外部规范保持独立维护。例如团队对私有仓库的 CI/CD、部署例外或来源公开范围有要求，提供对应正文后按适用仓库判读，不把团队名单和机器路径塞进技能。当前要求可以收窄本轮动作；规范中的命令或示例不自动授权执行。具体规则见[外部规范接口](curation.md#三外部规范接口)。

## 得到什么

报告先给简洁总览：统计范围、合并分支、PR、提交、Actions 用量及计费、关键节点，再按仓库展开重要变化和待处理项。用量和计费在同一项展示，分别说明实际依据；详细过程和证据放后面，只补充影响理解或行动的内容。本轮实际操作与窗口内已有变化分开计数；提交注明区间或版本范围并去重，未取得的数据不填 0。

总览也交代 Learnings 的新增、有效更新、已采用和待处理情况；后文按主题给出问题、做法、条件、依据及去向。仓库数字不代替经验汇总，历史已采用内容不当成新成果。

- 实际仓库、分支、固定版本和未覆盖部分
- 完整原文的接收入口及内容核对依据
- 去重后的经验、适用条件、证据、接收方和状态
- Actions／CI/CD、PR、分支和导航的实际发现、适用规则及覆盖缺口
- 已完成事项的真实采用入口，尚需确认的缺口
- 本轮外部操作与接续位置，仅做盘点时明确未清理

整理流程的详细判断见[经验汇总规范](curation.md)。工作区模板采用继续用对应更新流程，本技能不在汇总时顺带重新分发模板或修复所有 PR。

检查 workflow 时，文件存在、平台启用和近期运行分别报告，按实际 job／step 判断用途。运行时长不直接等于费用，没有计费依据就保留未核。各步区分已完成、待确认和未执行；只写了临时报告时，不把正式接收或来源清理标为完成。详见[仓库检查](curation.md#七仓库状态和外部规范检查)。

后续明确允许清理时，Agent 先核对原文完整接收、恢复条件和来源当前版本，再按项目流程处理。清理范围以本次授权为准，读取权限不自动扩大为写入权限。

## 可复跑的接收与恢复

已有本地 Git 仓库时，可从本技能目录执行：

脚本需要 Python 3.10+ 和已有 Git，使用标准库，不自动安装依赖或拉取仓库。纯远端读取可通过现有连接器取得原文，再用 ingest 接收。

~~~text
python scripts/github_summary.py collect --repo <仓库路径> --name owner/project --ref main --ref dev --out <接收目录>
~~~

先按项目约定选择来源，自定义路径加 --source-path；脚本默认检查登记的其他 worktree 和被忽略的经验原文。--exclude 可声明缓存或其他本次排除，--nav 可补相关目录页。接收目录不要放进任何被扫描工作树的经验目录。

普通 `.tmp`、tmp、temp 默认排除，登记在其中的独立worktree仍从自身根读取。显式--source-path可覆盖默认排除，显式--exclude优先。返回结果、last-run.json及intake.md会列实际排除位置和原因；coverage记录默认及显式排除，避免把排除当成已经扫描。output是否排除按项目用途配置。

相同输入重跑不会新增同义条目；有变化时，查看 last-run.json 的 changes、errors、exclusions 和 navigation，再由 Agent 逐条判断。objects/ 保存可恢复字节，index.json 保存分支、固定提交、工作树与历史身份。保留这些接续材料；它们可能含私有原文，不随技能分发。

未完整枚举的远端清单会标记 coverage_complete=false；它可以完成有限接收，但不能据此声称覆盖整个分支。路径迁移有多种可能时保留独立来源，交由 Agent 核对。

远端读取后可用 ingest 接收带版本和哈希的完整原文清单。restore 可将接收原文恢复到新的目录，拒绝覆盖不同内容或经重定向路径写入。check-cleanup 仅检查当前源是否仍匹配，永不删除；正式采用、恢复位置和授权继续核对。完整参数及 manifest 示例见[经验汇总规范第六章](curation.md#六脚本与接续)。

脚本只负责机械接收与定位。摘要、逐条价值判断、接收方选择、当前采用状态和受众范围仍由 Agent 核对；导航发现也不自动成为修复任务。
