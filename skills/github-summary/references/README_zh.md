# GitHub 汇总

读取指定仓库、分支和本地 Learnings，完整接收经验原文，按最终接收方整理候选与采用状态。适合 Learnings 汇总、跨仓库经验接收和已采用条目的收尾。

## 开始使用

从 knowledge 的 `skills/github-summary` 安装完整技能目录，也可显式提供本技能的 [SKILL.md](../SKILL.md) 使用。SKILL、元数据、引用、脚本、测试和许可证一起保留。

~~~text
$skill-installer
请安装 https://github.com/DreamSoul-AI/knowledge/tree/main/skills/github-summary
~~~

```text
用 $github-summary 盘点 A 仓库的 main/dev 和 B 仓库的 main，
加上我指定的本地 Learnings。把完整原文接到这个本地工作区，
按原定接收方归并，列清已采用、待审阅和建议清理的条目。
这次只读远端，不改来源、不发布。
```

请把 A/B 换成实际仓库，提供接收位置。可补充旧接收记录、已确认去向、固定提交和允许的清理范围。Agent 可以复用项目配置，不强制另填配置文件。

## 得到什么

- 实际仓库、分支、固定版本和未覆盖部分
- 完整原文的接收入口及内容核对依据
- 去重后的经验、适用条件、证据、接收方和状态
- 已完成事项的真实采用入口，尚需确认的缺口
- 本轮外部操作与接续位置，仅做盘点时明确未清理

整理流程的详细判断见[经验汇总规范](curation.md)。工作区模板采用继续用对应更新流程，本技能不在汇总时顺带重新分发模板或修复所有 PR。

后续明确允许清理时，Agent 先核对原文完整接收、恢复条件和来源当前版本，再按项目流程处理。清理范围以本次授权为准，读取权限不自动扩大为写入权限。

## 可复跑的接收与恢复

已有本地 Git 仓库时，可从本技能目录执行：

脚本需要 Python 3.10+ 和已有 Git，使用标准库，不自动安装依赖或拉取仓库。纯远端读取可通过现有连接器取得原文，再用 ingest 接收。

~~~text
python scripts/github_summary.py collect --repo <仓库路径> --name owner/project --ref main --ref dev --out <接收目录>
~~~

先按项目约定选择来源，自定义路径加 --source-path；脚本默认检查登记的其他 worktree 和被忽略的经验原文。--exclude 可声明缓存或其他本次排除，--nav 可补相关目录页。接收目录不要放进任何被扫描工作树的经验目录。

相同输入重跑不会新增同义条目；有变化时，查看 last-run.json 的 changes、errors、exclusions 和 navigation，再由 Agent 逐条判断。objects/ 保存可恢复字节，index.json 保存分支、固定提交、工作树与历史身份。保留这些接续材料；它们可能含私有原文，不随技能分发。

未完整枚举的远端清单会标记 coverage_complete=false；它可以完成有限接收，但不能据此声称覆盖整个分支。路径迁移有多种可能时保留独立来源，交由 Agent 核对。

远端读取后可用 ingest 接收带版本和哈希的完整原文清单。restore 可将接收原文恢复到新的目录，拒绝覆盖不同内容或经重定向路径写入。check-cleanup 仅检查当前源是否仍匹配，永不删除；正式采用、恢复位置和授权继续核对。完整参数及 manifest 示例见[经验汇总规范第六章](curation.md#六脚本与接续)。

脚本只负责机械接收与定位。摘要、逐条价值判断、接收方选择、当前采用状态和受众范围仍由 Agent 核对；导航发现也不自动成为修复任务。
