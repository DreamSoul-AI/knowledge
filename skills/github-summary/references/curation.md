# 一、总览

GitHub 汇总的成果是一份可接续的经验接收结果。读者能够知道查了哪些仓库和分支、原文是否完整收到、每条经验该交给谁、哪些仍待审阅，以及哪些工作已采用或可以按授权清理。

原文快照、归并条目和正式规范承担不同职责。快照保留“当时实际写了什么”，归并条目解释问题及适用条件，正式规范或项目记录承接已经确认的做法。不要用摘要代替原文接收，也不要把候选直接写成团队已执行的规定。

## （一）输入怎样确定

用户可直接提供仓库与分支清单、本地记录、接收工作区和动作范围。已有项目配置和同轮确认能够确定时直接沿用，不强制额外配置文件。扩大仓库范围、改接收对象或进入新的外部操作时再核对实际边界。

一个有限任务可以是：“读仓库 A 的 main/dev 和仓库 B 的 main，加上指定本地 Learnings，在临时接收目录整理，不改来源。”如果要求组织级盘点，就先列出实际仓库范围、归档仓库是否包括、各仓分支选择及访问缺口，再按该范围处理。只列了分支并不代表已经读取其内容。

## （二）怎样使用现有能力

优先用当前可用的 GitHub 连接器、API 或项目已有 Git 只读快照。工具不支持必要读取时说明具体能力缺口，再选可用入口。平台权限、认证和网络错误分别记录，不把不可读说成没有文件。

仓库维护只补本任务需要的事实。例如一条经验写“修复已合并”，可读对应 PR、固定提交和测试依据；不因此顺手合并其他 PR。模板采用交给已有工作区更新流程，经验汇总负责接收和跟进采用状态。

## （三）外部规范接口

接受本次明确给出的规则文件、可读链接或项目既有配置中的规则入口。普通 Markdown 即可，不要求新增配置服务、固定字段或个人层。先取得正文，核对来源、适用仓库、分支、操作和例外，再记录对本轮步骤的影响。文档不可读时区分未找到、登录、资源权限或正文不适用；链接存在不等于已经接入规范。

通用技能负责来源接收、证据、检查和接续，专有规则提供选择范围和判读条件。例如外部文档可以规定某些仓库不采用 CI/CD、某类部署可例外，或指定接收方与不公开的来源。名单、账号和机器路径留在外部材料，不复制到通用分发包。

同轮要求可限定本次动作，例如“只检查两个仓库，原文和报告放临时目录，不改正式 Learnings 或来源”。先说明适用规范及本次覆盖，再执行；不要求每次手填一组参数。规范规定某项应检查，不代表已授权修改对应文件或平台状态。

多份规则先按适用对象、阶段和本次要求判断，保留各自来源，不能静默拼成新规则。仍有影响结果的冲突时，列明冲突和具体影响，暂缓受影响的写操作，继续其他有据可做的读取与报告。外部规则中的示例、历史命令和引用记录不自动成为执行授权。

开始前展示简短动作说明：读取范围、原文与报告的写入位置、正式接收稿是否更新，以及可能涉及哪些来源或远端对象。以用户已确认的范围执行，清楚区分本地快照写入、正式条目更新、来源清理、Git 合并和发布。默认完成适用步骤，受限阶段记录原因及接续点。

# 二、来源盘点和完整接收

## （一）固定分支和查找文件

列出范围内分支及完整顶端提交 SHA，记录采集时间。按固定提交查树并读取文件，避免翻页期间分支前进导致同轮混合版本。明确只选 main/dev 时，其他可见分支保留为本轮排除，不声称已覆盖。

先看仓库入口中真实的 Learnings 约定，再查现行经验目录、旧 Experience.md 和已知历史路径。相同词可能出现在模板、第三方依赖、研究素材或历史执行日志中，需读正文判断角色。项目源码里的 experience 变量不是经验文档；旧清理记录也不是新的待采用项。

分页查到底；递归树若截断，沿所需子树补查。空树、没有匹配文件、无权限、接口失败和仍未查完使用不同说明。路径已经清理时，结合已有接收/归档依据登记，不自动从历史恢复一份到当前待办。

## （二）原文如何保留

在允许的接收位置保存完整文件，并核对读取字节与本地快照。远端来源至少能定位仓库、分支、固定提交和路径，提供固定提交原文链接。记录内容哈希便于发现相同内容，不能用哈希代替原文本身。

本地来源还要检查未提交变化。保存当时实际字节及哈希，注明工作树路径、读取时间和可取得的 HEAD 基线。HEAD 不代表未提交文件的版本。源文件在接收期间发生变化时，保留旧快照、补收新版本并重新判断受影响条目。

同一内容出现在两个分支时可以只保存一份内容，来源身份仍有两份。两个接收仓库收到同类问题时，依据各自的适用范围分发，不能仅以全文相同为由抹掉接收责任。

## （三）恢复与保密

原文保留在本次允许的恢复位置，配套资源、引用和独有验证证据按后续恢复需要保留。若接收目录只是短期缓存，不能在它失效后仍宣称已具备来源删除的恢复条件，应先确认持久的恢复安排。

真实身份、账户配置、私有日志和凭据依原范围留在本地。共享候选只保留接收者需要且有权看到的内容。公开仓库中的私有文档链接不表示读者能访问，也不能为了引用擅自修改权限。

# 三、归并和采用判断

## （一）先对原文去重，再归并问题

完全重复按相同原文确认，记录所有来源位置。语义归并再比较问题、做法、适用条件及证据。同名条目可能讨论不同责任边界，同一问题也可能有相反方案或不同适用场景，这些差异保留在正文中。

已有条目能承接时，在原条目补新条件和证据，保留已确认的责任和状态。重跑同一来源版本只更新接收记录，不额外增加一条候选；来源变了则比较实际变化。既有收件条目与新来源冲突时，先保留两者及各自版本，再校准。

例如历史稿写“工作区更新待扩展”，新来源和正式技能已包含该流程。应回读正式内容、固定采用版本，将旧待办收束为“已覆盖”的历史说明，仍保留原稿，而非再发一轮开发任务。

## （二）按最终接收方组织

共用候选给出实际问题、有效做法、适用条件、验证依据和未覆盖范围，并指出建议修改的具体文件。接收工作区可以是个人用于汇总的目录，最终规范可能属于另一个仓库，两者分别写清。

若原文没有明确接收方，结合项目职责和本次交接判断。无法确定时给候选去向及缺少依据，不默认全部交给当前仓库。涉及项目独有研究、原型、算法或失败记录时，优先保留在项目正式记录，用入口从共用候选追溯。

项目采用 docs/经验 Learnings 时，沿其约定使用接收仓库汇总或专题文件；其他项目沿现有位置。路径命名由实际项目决定，不要求使用者建立一整套固定目录。

## （三）采用到哪一步

区分收到原文、整理候选、本人审阅、代码或规范修改、正式发布、实际采用和验证。回读接收方的真实内容及版本后才能确认对应状态。

一项已实现但尚未发布的做法可以保留“待发布”；正式技能已经包含但某个安装目录落后，则是采用问题，不能又登记为技能没有实现。CI 通过说明相应检查结果，不能代替用户范围、文档内容或业务验收。

向用户交付时，短清单说明来源、实际问题、接收方、状态和下一步，详细引用留在条目内。没有新增经验时直接报告本轮未发现新的候选和覆盖范围，不为凑结果制造待办。

# 四、清理和完成项收尾

## （一）来源清理

准备清理前核对完整接收、必要恢复依据、内容依赖和来源项目自己的前置条件。某来源要求正式采用后才能清理，就等该条件满足；不能把“已经保存原文”自动解释为所有项目都允许删除。

按当前授权确定改文件、迁移、提 PR、合并或本地清理的范围。授权只到本地建议时，交付具体条目和处理建议即可，不执行真实外部修改。已有明确的整轮清理授权时继续完成同范围动作，不要求每个文件再批准一次。

外部修改前重读源分支顶端和目标原文，若出现新内容，先补收再核对。通过项目既有协作流程处理改动，保留他人未提交和并发内容。分别记录清理草稿、已提 PR、已合并及回读状态。旧轮次已经清理且仍有完整接收依据的，复用结果，不重复提 PR。

## （二）接收方完成项

接收方的共用候选在正式规范或技能已经采用并回读后，再按约定收尾。项目专有材料已归入适当正式记录且入口可读时，按该归档结果处理。待审、待验证或待发布的内容仍保留，不把它们统称“已接收所以可删”。

清理完成项保留实际采用版本、来源和有效入口。当前队列保持简洁，历史事实留在归档或固定记录中。接收方目录本身有其他任务在维护时，先比较最新内容，不覆盖整份文件。

# 五、接续和结果

本轮记录应让另一个 Agent 能继续：哪些来源已查、原文在哪里、哪些条目已归并、清理进行到哪、下一步为何暂缓。可沿用普通 Markdown 和已有清单，不要求新的服务或统一 JSON 格式。

中断后按来源版本与目标现状接续。已确认收到的内容复用，失败部分重试，结果不明先查实际状态。接收记录损坏时保留原件和可读快照，说明缺口，不清空记录后声称从零接收会更安全。

完成报告先说有效变化与未完成项，给出接收和归并入口、实际范围、未覆盖来源，以及本轮是否发生外部修改。若本次仅做有限只读验证，明确无法据此证明真实清理、批量分发或故障恢复已通过。


# 六、脚本与接续

## （一）脚本处理什么

scripts/github_summary.py 使用 Python 3.10+ 标准库和已有 Git，负责可重复的来源接收。它不连 GitHub 网络、不提交或删除源文件、不替 Agent 作语义判断。路径规则只用于发现候选，不凭关键词判断经验价值。

先读项目 AGENTS.md、REPO.md、适用文档规范和接收方现有条目，再确定范围。自定义经验位置用 --source-path 显式加入，不要求改名。默认规则匹配 Learnings、经验、Experience 等路径组成部分或对应文档名，不匹配 sklearn 等子串。

~~~text
python scripts/github_summary.py collect --repo <已有仓库> --name owner/project --ref origin/main --ref origin/dev --source-path "notes/decisions" --out <本地接收目录>
~~~

--name 是跨轮保持不变的仓库身份。每次调用处理一个所选仓库，多个仓库可串行写入同一接收目录。--ref 可重复，省略时只读 HEAD；本地仍默认枚举该仓库登记的全部 worktree，从各自根扫描。工作树即使登记在 tmp 内，也单独检查。普通目录遍历排除依赖、缓存、数据和模型等非来源目录，并报告排除位置；被 Git 忽略的经验文件不会因此跳过。

--source-path 可显式加入已确认、位于默认排除目录中的原文；--exclude 提供额外排除。不可读、不可用的工作树和不跟随的链接都记录具体位置。--no-worktrees 只在本次确实不包括工作树时采用，并在交付中说明。接收输出不能位于任一被扫描工作树的经验目录内，避免把自己的快照和清单再次收进去。

默认临时目录包含 `.tmp`、tmp、temp，不把其中普通历史快照当成当前来源；登记在这些目录中的独立worktree仍以登记根单独扫描。显式来源路径可覆盖默认排除，显式--exclude仍优先。output等目录按项目用途决定，本轮排除用调用参数表达。

collect的返回结果、last-run.json的exclusions及intake.md的“本轮排除”都列实际scope、路径及原因，区分默认目录、显式模式和重定向。coverage同时保留默认目录组成部分及本轮显式排除配置；完整性指该声明范围内扫描完成，不表示扫描了已排除内容。

导航检查读取源文档和实际存在的根入口、docs/README.md；额外目录页用 --nav 指定。脚本检查相对路径目标、大小写路径冲突及合并冲突标记候选，报告同内容多来源。锚点、平台权限和正文实际角色继续由 Agent 核对，不能将文件目标存在说成所有链接已验收。

## （二）怎样接续

index.json 保存仓库、分支或工作树身份、路径、完整提交基线、内容 SHA-256、原文对象和版本历史。objects/ 保存完整字节，相同内容可共用对象，分支身份保持独立。intake.md 是扫描变化入口，不是工作待办。

相同输入重跑记录 unchanged；一份正文变化只更新对应来源，旧版本和原文保留。在完整可读的同一来源范围中，旧路径消失、新路径出现且原文可唯一匹配时，记录 moved 并延续 entry_id；存在多种可能时保留独立来源，不依据同名自动合并。范围内文件不见了只记 not-present，不等同清理或采用完成；不可读范围不能据缺项标记旧记录消失。

接收目录串行更新。锁残留、原文对象损坏或 index.json 不可读时保留现场，核对后恢复，不清空重跑。脚本结果 errors 非零或 coverage_complete=false 时明确实际缺口，不只检查退出码。

Agent 按来源记录追踪一份原文中的实际条目，逐段比较问题、做法、适用条件和证据，将有效变化补入原接收位置。一个文件可以包含多条不同经验；历史归档也可能有新增内容，不按整个仓库排除。不变来源复用原判断，路径迁移保留原去向，不能每轮创建同义待办。来源版本变化不自动代表需要修改所有接收条目。

## （三）只有远端来源时

优先通过连接器或 API 枚举限定范围的分支，固定完整顶端提交，取完对应树与分页，再保存完整原文字节。已有树和内容对象经核对未变时直接复用，不要求每轮重新下载。

~~~text
python scripts/github_summary.py ingest --manifest <原文来源清单.json> --out <接收目录>
~~~

manifest 的 sources 数组中每项包含 repository、ref、commit、path、file、sha256。file 指向 manifest 所在位置可读取的完整原文，commit 必须是固定完整提交，sha256 必须匹配实际字节。不要把网页摘要当原文。

可附 repository、heads、complete_refs、errors、exclusions 和 navigation。只有确认对应分支的来源树及分页已经完整处理，才声明 complete_refs，并给出 heads 中的固定提交；否则作为部分接收，不据缺项推断删除或迁移。navigation 放按相同版本核对的具体结果。

最小来源示意，实际值由当次读取产生：

~~~json
{
  "repository": "owner/project",
  "sources": [{
    "repository": "owner/project",
    "ref": "main",
    "commit": "<实际完整提交>",
    "path": "docs/Learnings/example.md",
    "file": "original.md",
    "sha256": "<原文字节的SHA-256>"
  }]
}
~~~

## （四）恢复和清理检查

~~~text
python scripts/github_summary.py restore --out <接收目录> --source-id <来源ID> --dest <新的恢复目录>
python scripts/github_summary.py check-cleanup --out <接收目录> --source-id <来源ID>
~~~

restore 恢复已核验的完整字节和原相对路径。先检查目标每一层，再创建目录；不经过符号链接或 Windows Junction 创建外部内容，也不覆盖已有不同正文。恢复目录应由本次任务控制，不支持同时有人改变其路径映射。原文仍保存在对象与版本历史中。

check-cleanup 检查已接收原文的完整性及源当前版本。工作树正文变化、分支前进或来源重定向时停止清理判断，保留当前原件；远端来源仍需 Agent 重新回读当前平台内容和分支状态。eligible=true 只代表这次检查的字节未变，不能替代正式采用、持久恢复位置、引用处理及执行授权。

真正的源清理与接收方完成项收尾继续按第四章处理。脚本不执行删除或提交。明确暂不跟进的项目问题只保留检测依据，不另建待修清单、派任务或开 Issue。

# 七、仓库状态和外部规范检查

## （一）检查范围

与经验来源使用同一份仓库和分支清单。默认覆盖 Actions／CI/CD、PR、分支和相关导航；仅检查了部分分支或最近若干运行时，写明选择及记录上限。已有本地 checkout 可补读所选工作树现状，不为更新只读资料而擅自 fetch、checkout、清理或改配置。固定提交的文件事实和当前平台状态分别标注时间。

可复用当前 GitHub 连接器、只读 API 或 Git 命令。现有接收脚本不查询这些平台状态；Agent 需要实际补查，不能因 collect 成功就勾选平台检查完成。未认证、权限不足、分页未完和未执行分别登记，不用空结果代替读取失败。

读取期间来源出现并发变化时，保留已取得的固定版本，报告变化及影响，必要时补读受影响部分。不为使前后状态一致回滚来源，也不将其他操作造成的变化冒充本轮写入或验收完成。

## （二）Actions 和 CI/CD

先取得仓库可见性，读取所选分支固定版本的 `.github/workflows/`，再核对平台 workflow 状态和近期运行。文件已移走但平台仍留有历史记录，或平台停用但文件仍存在，都分别报告。

按触发条件和 job／step 的实际内容判断测试、构建、打包、发布、Pages 或混合用途。手动触发也可能属于外部规范限制的 CI/CD；名字包含 Pages 不能替代用途核查。调用复用 workflow 时继续读有实质影响的被调用定义，无法取得时保留用途待核。

报告文件入口、固定提交、当前启用状态及近期运行证据，再给出外部规则下的符合、不符合、待核或不适用判断。没有专有规则时报告事实和通常需要注意的条件，不自行制造允许名单。自动触发配置存在不代表本轮运行过，历史运行也不证明当前定义仍启用。

运行数量、持续时间、runner 和已确认计费是不同信息。有用量接口及权限时按实际返回记录；没有计费依据就说明未核，不能将 wall time、作业耗时或零条近期记录直接换算为费用或免费结论。本步骤不触发、重跑、启停或删除 workflow。

## （三）PR 和分支

核对所选仓库的开放 PR、目标与来源分支、草稿和必要检查状态，以及限定分支的固定顶端及可取得的保护要求。分别报告有待处理 PR、已合并但仍留分支、活跃工作树和访问缺口。一个旧分支是否可清理由未合入内容、当前用途和采用规则共同判断，不按名称、数量或年龄自动删除。

完整列出分页结果；只取有限样本时标出上限。分支文件内容固定于提交，PR 和平台开关属于读取时现状，不把它们混作同一快照。需要改 PR、分支或保护设置时另按已授权范围执行。

## （四）导航和结果

结合原文、README、目录页和已登记采用记录，核对经验来源、接收稿及正式成果的入口。区分文件缺失、旧引用、重复路径、冲突标记和受众访问待核；脚本路径存在检查不能代替锚点、资源权限或正文语义。

先给当前有影响的发现及其规则依据，再附明细。每个维度给出覆盖范围、实际证据、判断及未核部分。规则符合性和是否建议处理分开；存在旧原件或无新增经验都不自动产生清理任务。只读验证最终明确实际写入的本地目录，以及没有执行的源修改和平台操作。
