# GitHub 汇总

把分散在仓库、分支和指定本地记录中的经验完整接到接收工作区，交付能追溯来源、区分待审与已采用的汇总。仓库运行情况可作为判断依据，但不以一张 PR 或提交数量报表代替经验接收。

## 先明确范围和影响

结合本次请求、项目约定和已有采用记录确定仓库、分支、本地来源、接收目录及允许动作。分支可以明确列出，也可以按用户指定覆盖全部现存分支；列清实际覆盖和排除范围，不从几个样例推广到整个组织。缺项会改变接收方、数据范围或外部动作时集中核对，其余工作继续。

先读取相关 AGENTS.md、REPO.md、适用文档规范，以及接收工作区已有条目。可接入本次提供的规则文件、可读文档链接或项目既有规则入口，按[外部规范接口](references/curation.md#三外部规范接口)说明哪些要求适用于哪些仓库和步骤。公司例外、名单和机器路径不写死在技能中。区分汇总工作区和经验最终接收仓库，不能因当前对话属于某仓库就把经验全部归给它。

开始前用具体动作交代影响：将读哪些来源、在哪保存原文和报告、是否更新正式 Learnings，以及哪些来源文件、分支、workflow 或发布设置可能被改动。不要用“接收归并”统称这些动作。已有明确授权直接沿用，无法确定且影响外部改动的事项集中核对，其他可读工作继续。

“来源只读”允许在本次指定的本地接收目录写快照、索引和报告，不等于所有文件系统位置均不落盘。仅要求预览、不保存原文时按其范围执行。临时报告和正式接收目录分开说明；只读盘点不改来源仓库、正式 Learnings、分支或平台设置。

## 默认流程

默认完成本轮范围内适用的全过程，步骤用于说明影响和接续，不要求用户逐项选择后才能开始。本次明确缩小范围时遵循限定；缺少修改授权的步骤先交付可审阅建议，不把未执行说成完成。

| 步骤 | 主要产出 | 会写到哪里 |
| --- | --- | --- |
| 1. 明确范围和规范 | 来源、适用要求、允许动作 | 本轮范围记录 |
| 2. 盘点并固定版本 | 来源清单、提交、覆盖缺口 | 本轮来源记录 |
| 3. 接收原文并归并经验 | 原文、索引、归并条目 | 已确认的本地接收位置 |
| 4. 检查仓库状态 | Actions、PR、分支、导航发现 | 本轮检查记录 |
| 5. 展示结果和建议 | 实际变化、问题、下一步 | 本轮报告 |
| 6. 按授权收尾 | 修改、采用或清理回执 | 逐项明确的本地或远端目标 |

原文接收、语义归并和 Git 分支合并是不同动作。现有接收脚本只处理快照、来源索引及恢复检查，不会合并分支、修改 workflow 或发布。各步骤保留输入、产出和状态；已成功部分优先复用，避免重开整轮。

## 盘点并完整接收（步骤 2—3）

按[经验汇总规范](references/curation.md)查找项目 Learnings、旧 Experience 及有依据的历史目录，先固定各分支完整顶端 SHA，再按该版本读取。项目约定优先；按路径组成部分发现候选，不用宽泛的 learn 子串将 sklearn 等第三方内容当作经验。自定义来源按实际约定显式补入，不要求改名。

本地接入先枚举所选仓库登记的全部 worktree，从各自根检查未提交和被忽略的经验原文。主仓库的 tmp 排除不能漏掉登记在其中的独立 worktree；缓存、历史快照、其他克隆和不可读目录分别登记边界，不全盘扫描。处理远端分页和树截断，区分无匹配记录、读取失败和未扫描完成。工作树的实际字节是版本，HEAD 只作为基线。

普通 `.tmp`、tmp、temp 临时目录默认排除，结果列出实际排除位置和原因；登记在其中的独立worktree仍从自身根检查。已明确的来源路径可越过默认排除，显式 `--exclude` 优先；output等项目目录是否排除按实际用途配置，不另加通用禁令。

可复用 [接收脚本](scripts/github_summary.py) 的 collect、ingest、restore 和 check-cleanup，参数与验收见[脚本与接续](references/curation.md#六脚本与接续)。它维护原文、来源身份和增量，不自动判断经验价值、接收方或正式采用。已有 Git checkout 可只读盘点；只有远端时用连接器/API固定版本和完整正文，再交给 ingest，不强制另装 GitHub 客户端。

先保存完整原文和可恢复依据，再摘要。为来源保留仓库、分支、完整提交、路径、内容哈希和证据入口；相同内容可共用快照，所有分支身份仍须保留。敏感原文和个人配置遵守本次接收及披露范围，不进入可分发技能。

## 归并经验和采用状态（步骤 3）

先识别完全相同的原文，再按问题、有效做法、适用条件和证据归并语义重复。名称相似只用于找候选，不丢掉不同方案、负例或适用限制。从已有接收条目增补有效变化，重跑复用同一来源版本，不能每次另建一份汇总。

候选讲清解决什么问题、怎样做、适用于哪里、证据是什么、还没验证什么，并定位应接收的规范、技能或项目文档。逐条判断，不按整个仓库一概排除；同一归档中的新增段落也可能有可复用变化。以来源清单接续相同条目，未变来源复用，修改只核对应条目，路径迁移保留原身份和原去向，不每轮生成同义待办。实际采用需回读正式内容及版本，不能凭“已完成”标签、旧清单或发布计划关闭条目。

同时核对相关 README、目录页、旧路径引用、重复正文及冲突痕迹。原文接收成功不等于入口完整；脚本结果只是定位线索，回到固定版本验证。明确暂不修复的项目只保留检测依据，不另建待修清单或派工。

模板和项目规则的采用更新复用现有 workspace-update 或项目流程，不重新实现 Broadcast。

## 检查仓库状态（步骤 4）

默认检查本轮所选仓库的 Actions／CI/CD、PR、分支和相关文档入口，按[仓库检查](references/curation.md#七仓库状态和外部规范检查)执行。公司或项目的使用限制从外部规范接入；未提供专有规则时仍报告实际状态，不自行补出禁止或例外。

workflow 文件存在、平台是否启用和近期是否运行分别核对。Pages 等部署用途按实际任务步骤判断；文件名或一次 CI 通过不能代替规范符合性。近期运行时长和已确认计费分开，没有计费依据就标为未核，不换算成确定费用。

分支和 PR 核对实际状态及必要依赖，不将数量多等同于应删除或合并。固定版本的源码与当前平台状态分开记录时间；未覆盖分支、历史记录上限、权限和读取失败如实说明。检查是读取，发现问题不自动授权修复、停用、删除或发布。

## 展示结果和建议（步骤 5）

开头用简洁总览交代统计范围、总体结果和需要人处理的事项，便于扫读。优先呈现已合并分支数、PR 状态、提交数、Actions 用量及计费和关键节点，再按仓库展开重要变化；用量与计费合在同一项展示，但按实际口径注明。详细步骤、原文、命令和证据放后文或链接，不在总览重讲执行经过。总览后的补充只展开影响理解、决策或接续的问题，没有相关变化的仓库可合并说明，不逐项堆零值。

总览同时保留经验收获：新增或有效更新的 Learnings、值得复用的做法、已采用及待处理事项。仓库状态数字不能代替经验汇总。后文按主题说明经验解决什么问题、有效做法、适用条件、依据、接收方及采用状态；没有新经验时交代实际覆盖范围，历史已采用内容不重新包装成新增。

数字说明统计口径：本轮实际操作与时间窗口内已有变化分开，合并 PR 数不冒充合并分支数；提交明确时间段或固定版本比较范围，跨分支汇总按提交身份去重。Actions 分开报告运行次数、耗时及可取得的计费用量和费用；未统计、无权限或未取得数据写明未知，不填成 0。每个仓库先给一句状态或关键节点，再列相关 PR 入口、重要变化和待处理项；无依据不补造里程碑。

先说本轮实际收到什么、有哪些有效变化和需要处理的问题，再给按接收方归并的条目、仓库检查结果及接续入口。没有新增经验时直接说明，不为凑条目制造新待办。事实、规则判断、建议和未核项分开，检查缺口不写成“没有问题”。

逐步列明已完成、待确认、未执行及其原因，并回报实际写入的位置和外部动作。仅写了临时报告时，不宣称正式 Learnings 已更新；只有读取与建议时，不宣称来源清理或分支维护完成。

## 按授权收尾和接续（步骤 6）

分别判断来源清理与接收方完成项清理，具体条件见[经验汇总规范](references/curation.md#四清理和完成项收尾)。来源要有完整接收和恢复依据，满足其项目额外条件及当前授权后再处理；接收方的候选要在正式采用或完成适用归档并回读后再收尾。

外部修改前重读目标和分支状态，保留并发新增内容。原文快照完整且当前源未变只是清理前置条件，正式采用、持久恢复位置、引用处理及执行授权仍须分别满足。check-cleanup 不执行删除；来源变化、恢复副本损坏或入口不完整时保留原件，先补收再判断。修改来源、合并或删除分支、停用 workflow、提交发布分别说明目标和影响，不相互推定授权。已获授权的同范围操作接续到实际回读，不机械重复申请；仅请求盘点或本地试稿时不写远端。旧清理已经完成时复用结果，不再次删除、重复提 PR 或重做模板分发。

记录实际来源版本、接收位置、归并与采用状态、外部操作结果和剩余项。中断后从已有接收和目标现状继续，结果不明先核实，不清空记录后全量重发。对话里给出成果入口和具体缺口。
