# Codex 实验执行

从一句验证问题出发，自主设计、准备、运行和核验实验，回答实际发生了什么、是否有用，以及结论适用于哪些条件。机制探测可直接验证，效果比较再安排对照；不默认把所有问题做成 A/B 或完整研发项目。

## 确定最小可判定实验

先读当前项目约定和有关材料，复用已有能力、实验和有效证据。将问题转成可观察的行为，说明什么结果会支持或改变判断，选择能回答它的最小实验。只有缺失信息会改变对象、授权、成本或判读时才补问。

区分界面、CLI、App Server、模型表现和工具实际行为。选用能观察目标机制的入口；涉及当前产品用法时核对本机帮助、可用工具和官方文档。需要独立上下文才启动隔离测试会话，沿用当前模型和资源条件，模型或其他条件的变更依据本次问题确定。长任务按项目约定评估目标模式，短探测直接执行。

## 准备并实际运行

使用一次性目录和合成材料，或本次明确允许的真实输入。默认保留现有环境、个人配置和业务内容。执行边界、外部写入及资源开销按本次授权判断；测试请求不产生发送消息、清理数据或发布的授权。

比较实验尽量保持模型、版本、材料和工具条件一致，单独改变研究变量。核对各组实际收到的指令、材料、权限和启动参数，避免旧上下文、同名技能或共享产物污染。无法控制的差异进入限制说明；随机性可能改变结论时，用必要的重复或反例校验。

按本次范围实际跑完，保留命令、工具结果、错误和产物。子会话自述只是线索，回读实际文件、事件或外部状态核验。启动失败、认证问题、超时和权限拒绝分别判断，不能当作模型或方案失败。结果不足时有针对性地补探测；出现反复相同失败、需要扩大授权或超出合理成本时停止受影响部分，说明缺口。

CLI、App Server、隔离及取证细节按需读 [执行参考](references/execution.md)。

## 判读和交付

先回答用户的问题，再简述做法、直接依据、适用条件和剩余不确定性。区分观察、解释和推断；一次成功说明本次路径可行，不能证明稳定性或其他产品界面也成立。退出码、最终回复和实际产物分别检查。格式检查不能代替行为实验。

简单验证直接在回复中交付。需要复跑、多人审阅或追踪失败时，再沿用项目实验或运行记录位置保存简短报告、必要输入、脚本和证据；不用为每次探测新建整套文档。记录实际阅读和执行日期、入口与版本、关键条件、结果及未覆盖范围，不导出凭据、私人配置或内部推理内容。
