# 个人日志 personal-log

这是本人的个人技能，发布不代表已安装或启用。收到草稿修改或建议请求时，只修改草稿；实际维护日志须有对应的执行请求。技能不创建定时任务。

## 一、入口与标记含义

从当前项目的 `USER.md` 获取本人身份和个人日志地址，读取项目约定及日志最新内容。操作飞书时使用现有 `lark-doc` 技能及用户身份，遵循项目的文档编辑与恢复要求。

本人的日志使用以下含义：

- 勾选表示当天做过或有阶段进展，不自动表示整个项目已经结束。
- 加粗事项默认是下一天仍需接续的重点；下划线表示正在推进。保留本人设置，不自行重评优先级。
- 母项可能只是分类，不能因为母项已勾就把整组子项判为完成。
- 下面按年月和日期排列的是历史日志，最新日期在前；顶部 TODO 是当前工作清单。日期相同也不能把两处混为一处。

这些是本人的个人规则，不推广为其他用户的日志习惯。

## 二、先判断做到哪一步

根据本次请求及日志实际结构，选择所需范围：

- **完整转日**：保存旧日、归档到下面、推进顶部日期、准备新一天清单，再清理旧日。
- **只清理旧日**：本人已经挪好或复制好，只清理指定历史日期，不改顶部日期或新一天的勾选。
- **只准备新一天**：本人已保存旧日，只处理明确指定的新日日期及清单。

“清理22号”不自动等于完整转日。先定位指定历史节；无法唯一确定目标时集中询问。已有归档、日期调整或清理结果应复用，不能重复插入、再推进一天或覆盖人工改动。

## 三、完整转日

### 1. 先保存旧日

读取并保存旧日完整状态与恢复依据，包含日期、条目层级、勾选、加粗、下划线、删除线、颜色、链接及相关资源。旧日未保存并核对前，不重置顶部勾选。

原有评论、引用或资源可能受移动影响时，按文档编辑规范保留恢复依据；工具不能可靠保留时，说明具体限制，不以丢失历史信息换取转日完成。

### 2. 归档与年月结构

将旧日记录归入下面对应的年月 section，沿用现有标题级别、日期格式和倒序排列方式。同一天已有归档时先比较，保留已有内容，不覆盖或重复创建。

跨月或跨年时，核对并补齐本轮所需的年月 section。旧日按旧日日期归档，例如 11/30 转到 12/01 时，11/30 的记录仍归 11 月。

### 3. 推进顶部日期

本人指定日期时使用指定日期；仅要求“转到下一天”时，在原工作日期上加一个自然日。使用北京时间理解日期，不因为系统日期更晚就连续跳日或制造多天日志。

### 4. 准备新一天清单

根据保存的旧日状态处理具体事项：

| **旧日事项状态** | **新一天的处理** |
| --- | --- |
| 已勾且加粗 | 取消勾选，保留加粗及其他原有格式，作为继续事项 |
| 已勾但不加粗 | 保留原勾选，加删除线暂留，交本人检查，不直接删除 |
| 未勾选 | 保留条目和原有格式，继续接续 |

判断加粗以条目本身的文字为准，不把上级分类的加粗套到所有子项。部分加粗导致含义不清时，保留并集中询问。已有删除线不自行恢复或删除。

分类母项根据子项接续：只要下面还有未勾待办，新日母项就应未勾；不对分类套用“已勾且不加粗就划掉”的事项规则。母项本身另有独立任务含义时，结合原文判断，拿不准则保留。

先用保存的旧日原始样式判断并生成新日继续事项，核对新日清单完整后，才能清理历史强调。不能先去掉旧日加粗再据此选择新日事项。

## 四、清理下面的旧日

完整转日到此继续执行；若本人已经手动挪好，则从这里接续。

1. 保留旧日已勾事项及其必要分类层级，去掉指定历史日期的加粗和下划线。保留勾选、其他原有样式（含颜色）、名称、顺序和链接，方便回看昨天做过什么；不把历史清理套到顶部新日继续事项的加粗。
2. 旧日未勾的具体事项，确认已完整带到后续清单后才删除。核对分类路径、文字、链接及子项，不能只凭同名或相似名称判断已转移。
3. 未找到明确承接位置、带有独有备注或转移不完整的条目先保留；不能把“未勾选”当作可以丢弃的依据。
4. 未勾母项下有已勾子项时，保留母项作为分类。分类下只剩本日做过的记录后，为必要母项补勾；不能把没有完成记录的整组直接勾上。
5. 清理没有保留事项的空分类，仅限本次旧日范围。保留未解决疑问所需的结构。

旧日不执行新日的取消勾选或删除线转换。旧日清理已经转走的未勾待办及历史加粗、下划线，不抹掉当天已勾记录和其他格式。

## 五、周分隔与范围

按周一至周日为一周，在周日与下一周周一之间核对分隔线。沿用既有样式，缺失才补，不重复添加；跨月时结合月 section 判断现有分隔是否已经清楚，不机械叠加。

不顺手修改想法、Q3.5、Q4、远期、例行或其他日期；不改名、添加成果说明、插入调研链接或从其他对话推定完成。不做工作留言、权限变更或其他发布。

## 六、写入核对与回报

实际执行前重新读取目标，保留并行人工修改。优先局部修改，完成后回读并核对：

- 日期、年月归属、排列顺序正确，无重复归档或重复转日。
- 旧日已勾记录、层级、颜色、链接和其他格式保留，加粗、下划线已清理；顶部新日继续事项未勾且保留加粗。
- 新日非加粗已勾事项只加删除线暂留，没有直接删除。
- 旧日被删的未勾事项均有明确承接；母项与子项层级正确。
- 无关章节、日期和人工内容未被改动。

中途失败时保留已完成进度与恢复依据，先判断实际完成到哪一步再接续，结果不明时不盲目重试。拿不准且影响含义的事项集中问，其他独立且明确的步骤继续完成。

回报只说明转到了哪天、旧日清理结果、暂留给本人检查的删除线事项及必要疑问，附日志入口，不把执行过程写进日志正文。
