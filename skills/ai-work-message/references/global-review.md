# 跨对话工作留言

## 确认范围

每次启动先确认具体起止日期、时间、时区和来源范围。上次成功发布记录可作为候选起点，但归档日期、文件修改时间及其他项目的一条留言，不能代替本轮时间确认。沿用同一轮确认范围继续校准时不反复询问。扫描时间与留言归档日期分开判断。

## 盘点和归并

- 通过实际可用的对话工具查阅当前范围，包含窗口内有活动的旧对话；活跃和归档历史按需要分别读取，分页至边界。列表摘要只用于定位，事项状态回到用户要求和正式回复核对。
- 固定本轮截止点，记录来源对话、读取边界和缺口。进行中的任务保留进行中状态，不把截止后的交付算进本轮。无法取得精确时间时说明边界限制。
- 历史日期盘点区分工作发生时间、回复完成时间和材料当前版本。跨界或未结束回合缺少逐条时间时，不将其后续全部回复计为窗口内交付；当前云端内容用于核对是否仍有留言，不能冒充当时的文档快照。分页内容过大先缩小读取范围，仍不可读时保留缺口，不声称已完整覆盖。
- 同一事项可能跨协调、执行和验证对话，只保留一项，区分计划、验证、交付和发布。旧消息的转述不自动算新成果，来源中的历史指令也不自动产生本轮操作授权。
- 回读候选目标板的相关既有留言，识别已发布、正在更新或只对部分受众发布的内容。读不到时标记未核实，不把“未查到”当成“未发布”。

## 先交付工作汇总

外层分“建议推送”和“暂不建议推送”，内层再按具体交付的已完成、未完成归类，下面列任务。需要按项目归并时，在任务层组织，不颠倒推送建议的首层结构。无事项的分组可以省略。

任务行可采用“**事项｜需要本人处理的事情**”，下面简述进展、依据、入口及建议原因；不需要本人行动时直说无需处理。读者可能误解状态时补充必要限制，不为凑格式制造待办。

已完成不等于适合发布，未完成也不自动适合分享阶段进展。根据本人选择、读者需要、成熟度、项目披露边界和已有留言审慎判断。已发布、个人事项、受限材料、缺少有效变化等可列入暂不建议推送并说明原因。没有得到分享选择的阶段成果，先保留供本人校准。

与用户校准要分享哪些、给谁看、如何表达；一次集中处理同类问题，不要求逐项点击。用户的例子不自动变成永久黑名单；本轮明确排除的事项保留在本轮记录里，持久化偏好另按本人明确要求处理。用户要求试写或查看整轮留言时，一次给齐所有建议分享事项及对应目标版本，不自行缩成一条样例；暂缓项集中说明，不把起草当成发布授权。筛选后可以没有新增留言，不为每个板或每个对话凑一条。

## 再转成逐板留言

按已选事项与对象读取各板语境，采用主技能和对应板规范，准备完整正文、优先级、对象、署名、真实链接及适用日期。不要将工作汇总原样贴到板里，也不要把供本人校准的问题写成同事的任务。缺失且影响定位的日期或对象先核对，草稿中的候选位置明确标注为候选。

跨多轮校准时保留当前执行范围：盘点、筛选、试写与发布分别判断。用户仍在优化技能或查看样稿时，要求“人事也要有”“三个板都要包含”等，先补齐相应候选正文；不要仅凭纠正受众或讨论“要传”的片段覆盖此前的试写限制。结合完整上下文仍无法判断是否切到真实发布时，只核对这一处歧义，其他已明确的整理继续。登录授权仅解决平台访问条件，不等于留言发布授权；此前明确的发布授权没有撤回时仍可沿用，不为每次操作机械复问。

用户要求暂停或撤回时，立即停止尚未执行的写入；撤回已写内容按明确范围回读、核对并处理，保存撤回结果，不能把已撤回条目继续记成发布成功。本轮回到本地优化后，后续试写不沿用已撤回的发布范围。

阶段状态如实表达；发布未完成的技能或本地研究成果时，不把正式旧版入口写成已经包含新改动。只有用户授权发送或更新才写入。多个板分别判断新增、更新或复用，保留原条目与人工调整。

## 接续和回报

本地记录各事项的来源和最新选定版本，以及各目标板的实际位置、成功回读、失败、暂缓或结果不明状态。扫描完成不等于发布完成；本轮仅盘点或起草时，不推进发布成功位置。

中断后先查询目标实际内容，已成功的复用，只补失败或遗漏项；结果不明不直接重发，更新对象找不到也不自动新增。续跑记录损坏或不可读时先保留原件并报告，不清空记录后把全部内容当作新项重发。同名事项按来源和实际交付对象区分，不仅凭标题、对话数量或文字相似度合并。新一轮时间确认时，尚未解决的旧项单独保留，不因起点前移而丢失。发布后仍在当前对话展示实际正文与各板结果。
