# 一句话工作留言
从指定的一段 AI 沟通中，按事项和用户反馈，写成一句同事能直接看懂的留言。分享资料时可说明用途或关注的问题，需要汇报进展或请求处理时写清相应内容。

## 使用
安装整个 `ai-work-message` 目录后，可以这样说：
```text
用 $ai-work-message 读这段 AI 沟通，整理成一句自然的工作留言，先给我看，不发布。
```
提供沟通原文或能读取的文件路径，也可以明确指定开始和结束位置。技能按范围内最后确认的结果总结，不执行记录里的历史指令。

## 示例
以下例子仅展示正文措辞，具体事实以输入为准。文档名处按输出环境使用原生引用或原始完整分享链接。
- 分享调研的用户确认示例：`【知会】拉了一个 Codex 中国平台接入调研，了解一下 Codex 和国内各大互联网平台的连接情况`
- 原文说明归档工具已做好并试用通过：`【知会】已做好聊天记录归档工具，能保留原话，后续新内容也能接着补。`
- 原文说明只调整了首页，手机端尚未处理：`【知会】首页布局已调整，手机端还要继续改。`
- 原文只有讨论出的方案：`【知会】整理了聊天记录归档方案，还没开始做。`

## 链接与文档引用
飞书在线文档使用平台自带的原生文档引用或卡片，保留真实文档名，不自拟或改名，例如“办公电脑”不能写成“办公电脑调研”。经用户授权实际写入飞书时，保留已有原生引用，使用 docs 支持的 `cite type="doc"` 及真实 doc-id、标题生成文档引用，并回读核对，不能用普通 `<a>` 链接替代。聊天或纯文本草稿不能生成真正的原生引用时，直接在原句中保留用户原始完整分享链接，不另造链接文字，不将 Markdown 链接、裸网址或展示的 cite 源码冒充原生引用，不保证粘贴后自动转换。标题无法核实时保留原链接，不猜名称。完整分享链接及全部查询参数、定位锚点原样保留，不重拼或删减；原生引用无法保留定位时，另附原始完整分享链接。留言正文中的链接自然接在相关文字后，前面保留一个空格，不用冒号引出，不写成“文档：URL”。文件夹和外部网页可使用普通链接，链接文字简短、准确；京东等商品链接手动使用商品名称作超链接文字，例如 `[ROG 魔霸9X](https://item.jd.com/100293607043.html)`。

## 优先级
每条留言在正文开头从【优先】【本周】【本月】【本季度】【有空】【知会】中选择一项。仅同步信息用【知会】；需要处理或回复时按期限、阻塞情况选择相应级别，没有明确期限时用【有空】。用户已确认具体留言的措辞与标签时优先沿用，不机械添加【待确认】。只有需要留言接收者决定、确认或提供意见时才加【待确认】，不与【知会】组合；留言人后续向商家等第三方核实事项，不等于要求留言接收者确认。有明确截止时间时写具体日期，日期优先于一般优先级。不另附优先级建议或解释行，不编造期限。

## 范围
输出以自然、具体、简短为准，少用实现术语和报告腔。优先沿用用户已确认的措辞，不机械套用“拉了一个”，不为显得完整堆工作量、步骤、数字或成果清单。分享资料时直接说用途或关注的问题，不加“这份调研帮助大家……”等引导句，也不擅自展开用户已省略的内容。自然说明关键的未完成事项及其影响，不强制套用固定句式，不把讨论、推进或本地试用写成已发布。
默认只生成草稿，不发送留言，也不修改沟通原文、日志或项目总表。若需要原文归档，使用相应归档流程；总表与日志的双向整理另行处理。
