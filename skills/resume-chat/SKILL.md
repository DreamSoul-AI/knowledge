# 中断恢复 resume-chat

先判断工作是否仍需继续、当前是否获准继续，再选择足够恢复的最短消息。已有上下文清楚时无需重新写一份长交接，恢复后仍以真实进展和产物判断结果。

# 一、核对断点

按本次指定的任务、项目、对话或时段限定范围。当前 Agent 读取足以判断的状态、最近相关回合及必要产物，不为一次恢复另起独立判断会话，也不默认扫描全部历史。

**任务和授权。** 找到原目标、已完成部分、剩余事情及最新要求。用户暂停、终止的任务不能因列表显示空闲或回合中断就自动唤醒。用户现在明确要求恢复原暂停事项时，按这次恢复授权处理，保留仍有效的限制，不机械再询问一次。

**状态和停因。** 列表的 idle、未加载、更新时间用于定位。最近相关回合的 `interrupted` 提供中断线索，不能独自证明是执行故障。结合用户原话、中断记录、报错和后续回合判断是否意外中断、已续跑、仍在运行、等待必要输入或审批。原因不明时只补查影响决定的记录，不能自行填成执行中断。

**回合和任务。** `completed` 只说明一个回合结束，可能是任务完成、提出问题等待回答，或完成一个阶段后仍有已授权待办。结合正文和产物判定，不把回合结束当成整个任务完成，也不因此重复已完成操作。

运行中的目标先观察或等待，避免并行发送重复指令。等待必要输入或审批时处理该依赖，不用 `resume` 绕过。发现目标已完成或已被后续执行接替时，直接说明现状，不制造恢复工作。

# 二、选择接续方式

## （一）当前对话继续

在本对话直接接回已授权目标和实际断点，继续必要工作，无需给自己发送 `resume`。上下文压缩、环境切换或规则已更新时，先重读当前适用规则及必要目标文件，再继续原任务。规则重读是重新取得依据，不是恢复工具本身，也不意味着丢弃已确认的任务事实。

## （二）指定其他对话

用当前环境可用的对话工具定位并读取正确目标，核对项目和对话身份。发送消息前确认本次恢复范围，选择消息：

- 目标、要求和下一步在目标上下文中已清楚，直接发送 `resume`
- 有新约束、方向纠正或必需输入，只补本次变化，不重述目标已知的整段背景
- 缺少继续所必需的输入，先问具体缺口，不向目标发送一个无效的恢复消息
- 用户指定发送原文时采用原文，仍按实际授权和目标状态判断执行边界

发送工具可能添加来源包装，提交的正文只有 `resume` 不代表模型收到的整个载荷只有一个词。遇到 active writer 先确认实际运行者，不能强行抢占。归档状态本身不说明可以解除归档，按本次请求及工具实际能力处理。

## （三）CLI 会话恢复

用户明确在 CLI 环境恢复已有会话时，先检查本机 CLI 帮助和真实会话身份，按当前支持的 `exec resume` 或相应入口执行。CLI 恢复既有会话与桌面对话发送消息是不同入口，不能用一次成功冒充另一种方式已验证，也不为恢复新建一份替代业务会话。

示例：原任务要求输出若干平方数，要求未变时 `resume` 已足够。若当前改为计算较短范围的立方，只补“改算指定范围的立方，其他要求沿用”。若改用新名单却没有名单，先问“请提供新名单”。这些示例说明如何选消息，不固定任务、数字或输出格式。

# 三、发送后核验

区分已提交、已接受、开始运行、回合结束和任务完成。回读最新消息、运行状态及实际产物，核对是否满足本次要求，不能以发送成功或 `completed` 代替结果验收。

发送结果不明时，先查目标是否收到和开始执行，再决定是否补发。文件写入、发布等有副作用的任务还要核对已执行范围，避免重复操作。恢复本身不扩大原任务授权，遇到新出现的必要输入、审批或执行限制按当前情况处理。

在请求方对话简短回报哪些实际继续、哪些无需恢复、哪些仍被具体问题阻碍，以及结果和下次入口。不要把已发送写成已完成，也不承诺不存在的后台监控。

# 四、可选批量粗筛

需要处理规范化快照时可用 [classify.py](scripts/classify.py)。每项包含 `thread`（id、按时间正序的 turns）和调用者核实的 `stop_intent`。脚本只读 JSON，不获取对话、不推断真实意图、不发送消息。

`execution_interruption`、`user_pause`、`user_stop` 或 `unknown` 必须忠实记录来源。若用户后来重新授权恢复，保留历史停因，当前 Agent 另按新授权判断，不能把历史暂停伪装成执行故障来通过脚本。

返回的 `closed_or_waiting`、`review`、`excluded_by_user` 等只是粗筛标签，不是最终任务判断。例如 `completed` 仍要读正文，已重新授权的暂停项也需结合当前请求判断。脚本输出不能代替本技能前三节。

使用、样例和证据边界见 [中文说明](references/README_zh.md) / [English guide](references/README.md)。
