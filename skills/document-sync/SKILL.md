# 文档同步

一个入口管理同一对文档的映射、传输、比较基线和冲突；upload、download、both 是方向，不是独立技能。支持单文档或明确列出的多个文档，不递归扫描目录，不传播删除或自动合并冲突。

## 输入与配置
接收本地文件路径、外部配置，以及必要时的已有云文档完整链接。路径可以尚不存在，但父目录及下载范围须明确。配置见 [飞书样例](assets/feishu.example.yaml)：
- `platform`：当前仅 `feishu`，其他平台待确认
- `direction`：`upload / download / both`，须明确；本次明确的方向可覆盖配置并记入记录，不因“同步”一词猜方向
- `conflict: stop`、`delete: false`：首版只支持停止冲突和保留缺失侧；其他策略待确认
- `rules`：实际适用的上传与文档规范，可省略未指定项并按下节定位，引用原文而非复制规则
- `directories`：精确的本地父目录到云端目录映射，子目录不继承
- `receipt`：同一对对象的状态与基线记录位置

配置内的本地路径相对配置文件目录解析，不依赖终端当前目录。显式目标优先，但仍核对平台及真实归属；既有文档用稳定对象标识关联，不用同名证明同源。配置不保存凭据，不扩大写入、共享或通知授权。旧上传配置缺 direction 时先确定方向，不静默转换为双向。

## 规范接入
在调用任务所属项目中核对适用的 AGENTS.md 及项目入口，不从技能安装目录向上继承 knowledge 仓库的要求，不假定安装者拥有公司私有资料或登录权限。

明确给出的 rules 按其路径或链接读取，显式来源失效时停止受影响项，不静默换另一份规范。未指定的规范项，沿当前项目 AGENTS.md 的相关链接或索引定位并读取正文，仅追查本次相关引用。配置路径相对配置文件，AGENTS.md 和索引中的相对链接相对各自文件，不能混用。

显式来源仍须与当前任务和适用项目要求一致，不能用配置绕过已有要求。冲突无法消解、必要规范缺失或无读取权限时返回 needs_confirmation，列明缺口，不写入。通用外部项目使用其自身规范，不强制采用公司规范；公司规则不随技能私自复制或公开。

逐项记录规则的实际路径或完整链接、发现入口和适用范围、本次读取的内容指纹或版本。规范变化即使文档未变也需重新核查，不能只凭旧基线直接 reused。规则定位是 Agent 的执行步骤，状态脚本不会解析自然语言规范或自动读取飞书。

## 明确清单的批量处理
清单可以提供每项 id、本地文件、目标目录或已配对云文档、独立 receipt，以及本次方向和必要的逐项规范。共用配置可复用，不能共用一个成功基线。先列出全批位置与配对，核对同名文件的真实归属、本地目标、云端定位键和回执是否相互冲突；批次歧义先停止全批，不边猜边写。

按平台限制串行传输，成功一项就保存其回执。单项冲突、权限或规范缺失时保留该项及其依赖，其余无依赖项继续，批次汇总逐项状态。启动前发现上次 pending_verification 时，先查已知对象和上次实际写入内容，核实后恢复该项基线，不重新创建或盲目重发。

批内引用先落实目标身份和映射，再写依赖正文。首次创建可先建立必要空壳并立即记下实际 ID，循环引用须等相关身份全部落实。缺失的清单外资源不自动上传，引用目标失败的依赖项不能标记完整交付。下载继续保存原始导出、引用映射和长期依赖。

只读批量决策输入为 JSON 的 items 列表，字段沿用单文档快照，并增加 id、local_path、receipt、remote_key。remote_key 是平台加稳定文档 ID，未创建时使用核实目录标识加目标标题，不能仅用标题。路径相对 JSON 文件目录，CLI 用法仍是 python scripts/sync_state.py snapshot.json。脚本检查清单冲突并逐项调用原决策，不执行目录发现、传输、规范定位或恢复。

## 比较与方向
先读适用规范，再按 [飞书适配](references/feishu.md) 取得两端实际内容、对象身份、位置及快照。分别将本地指纹与本地基线比较、云端指纹与云端基线比较，不能跨格式直接比较两个哈希。含资源时指纹须覆盖正文及实际依赖、源码和必要元数据，不能只比较 Markdown 或带只读占位的导出正文。保存指纹口径及资源清单；口径变化须重新核验基线，不把旧正文哈希直接当作资源清单哈希。

可用 [状态判断脚本](scripts/sync_state.py) 对 JSON 快照作只读决策；它不执行传输或写基线。输入字段为 direction、local、remote、baseline，缺失侧为 null，baseline 为已验证的 local/remote 指纹对象。

| **实际状态** | **处理** |
|---|---|
| 无基线，只有一侧存在 | 在允许方向内初始化，保存来源与身份依据 |
| 无基线，两侧均存在 | 核对配对及初始基线，不自动选一边覆盖 |
| 两侧均未变 | 复用成果，不写入 |
| 仅本地变 | 允许上传时局部更新云端，否则待确认 |
| 仅云端变 | 允许下载时更新本地，否则待确认 |
| 两侧均变 | conflict，保存双方及差异，不覆盖或自动合并 |
| 已跟踪的一侧缺失 | 待确认，不删除另一端或自动重建 |

发生冲突时保留原始两端及上次成功基线；重复运行仍应报告冲突，不能把观测到的冲突内容直接写成新基线。人工解决或明确选择结果后，再核对两端内容并建立成功基线。

## 执行与基线提交
适配复用已有平台工具处理读写、格式和引用；遇到无法完整保留的资源先停止受影响写入。写入前重新核对目标及原快照，避免覆盖扫描后产生的修改。结果不明先查已知对象，不盲目重建或重试。

成功后回读两端并验证，保存配对身份、实际采用的规则及必要的本地正文、云端结构化正文、Markdown 和引用元数据快照，再原子更新状态中的双侧基线。基线保存失败时保留旧基线与 pending_verification，不以完成标记掩盖；失败接续先查实际状态。

状态至少包含 platform、本地路径与云端标识/URL、实际目录、成功双侧基线及其快照位置、最近核查结果和待处理操作。路径相对记录位置或明确根目录解析。规则或映射变化先重新核验适用范围和身份，不能仅因文件未变就跳过。

## 结果与组合
返回 uploaded、downloaded、reused、conflict、needs_confirmation、pending_verification 或 failed，附实际路径/链接、有效方向、变化依据、核验范围及冲突材料位置。

Meeting Minutes 等上游提供本地成果和配置，交付场景明确使用 upload；不因接入此技能自动启用下载。传输失败保留上游内容，不重新生成会议材料。不创建定时任务、发布留言或调整权限。
