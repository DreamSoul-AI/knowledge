# 文档同步

一个技能内按配置上传、下载或双向同步单个 Markdown 与云文档。目前实现飞书，需要已有 lark-cli、lark-doc、lark-drive；安装完整技能目录。确定性状态判断用 Python 标准库，无额外第三方依赖，也不执行传输。

## 首版与本地安装
当前为 v0.1.0，面向飞书单文档的小范围使用。实际传输由执行 Agent 读取技能及外部规范后调用现有工具完成，附带脚本只判断状态，不是独立同步服务。已验证文字、表格、引用、单张 PNG、单个原生 Mermaid 及资源单独变化；多素材、带评论的组件替换和并发编辑尚未覆盖。

将完整 document-sync 目录安装到 Codex 个人技能目录，保留 SKILL.md、agents、references、assets 和 scripts，排除 __pycache__、运行记录和个人配置。安装后下一轮对话即可发现技能；当前轮需要显式读取新安装的 SKILL.md。示例配置中的路径与目标均需替换，不能把占位配置当成真实归档位置。

接续已有 Meeting Minutes 成果时，可由调用者明确提供已有纪要、来源、交付配置、同源云文档链接和既有归档记录。先执行同源成果检查，再交给 document-sync，交付方向使用 upload。已有成果和基线未变就复用，不重新生成纪要，也不为了验证交付而另建副本。

## 使用
```text
使用 $document-sync 处理 ./会议成果/会议纪要/评审.md。
配置：./交付/feishu.yaml
这次只上传；若两边都已改过，保留双方并报告冲突。
```

下载时明确已有云文档链接、本地目标以及 download 方向；双向时明确 both。样例见 [配置](../assets/feishu.example.yaml)，本地路径均相对配置文件目录，源文件按调用上下文定位。显式本次方向优先并记录，未明确方向不猜。规则只引用实际适用规范，不在配置中复制正文或存凭据。

## 变化与首次配对
保存上次成功的本地指纹和云端指纹，各自比较。无变化则复用，只有一侧变化就在允许方向内处理；双边变化停止冲突，保留双方与旧基线。一端缺失不会删除另一端。没有基线且两侧已存在时先确认配对及初始内容，不选一边直接覆盖。

目录映射只精确匹配文件父目录，子目录不继承。位置或身份不确定时待确认。飞书 Markdown 下载可能包含 DocxXML 扩展，原始转义、引用映射与资源不能丢失。含资源时指纹覆盖正文及依赖和原生源码。保留原始导出，并将已核实的 PNG 和原生 Mermaid 转为本地相对资源与代码围栏；未覆盖资源需先确认，不能承诺只存文字即可往返保真。

## 组合与验证
Meeting Minutes 完成本地整理后可交给 document-sync，交付方向明确为 upload，不自动开启下载。其他上层任务也可使用同一配对和配置。download 与 upload 是内部方向，共享目录、状态和冲突处理，不独立创建新技能。

状态判断可运行 `python scripts/sync_state.py snapshot.json`，字段见主说明；脚本只输出决策。单元验证运行 `python scripts/test_sync_state.py`。真实平台验证另按实际记录判断，不能以单元检查代替读写与格式验证。

当前默认 conflict 为 stop、delete 为 false；不支持批量目录、自动合并、删除传播、其他平台或定时调度。
