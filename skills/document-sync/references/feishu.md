# 飞书同步适配

仅在 platform 为 feishu 时读取。使用现有 lark-doc、lark-drive、lark-cli，沿项目使用教程、上传规范和文档规范执行。单个 Docx 与本地 Markdown 配对；完整保留资源不能确认时先停止写入，不以只取纯文字代替完整文档。

## 位置与身份
核对实际用户，全程显式 --as user，先读当前命令参考。隔离环境读不到凭据时先排除运行环境问题，不自动重新登录或切机器人。

读取配置指定目录的完整分页及真实父子关系。云文档必须确在核实目录中，类型、标题、稳定标识与源文件配对一致。已有回执优先定位，标题仅用于发现候选。已跟踪文档被移动、无法读取或同名不明时待确认，不另建副本。

已有 Docx 可由调用者完整 URL 或回执指定；初次下载需要明确本地目标及配对。首次上传本地 Markdown 默认创建在线文档，不上传原生 .md；缺少目标不放根目录。示例及旧目录 token 均不作为默认。

## 快照与比较
读取 --detail full 的 XML 正文、实际 revision，以及同一 revision 的 Markdown 与 reference_map，记录实际覆盖。分别保存本地字节指纹和云端结构化正文指纹，不能要求 Markdown 与 XML 哈希相等。无外部资源时可用完整 XML 指纹，结构或格式变化也会触发核对；不声称它只识别语义修改。

有本地图片等依赖时，构建稳定排序的清单，包含正文指纹、相对资源路径及资源内容指纹。云端除完整 XML 外，还需把实际资源标识和原生文本绘图的 component_type_id、完整 record 等正文未承载的内容纳入清单。分别对两侧清单确定性序列化并取指纹，记录采用的口径。重跑也要核对这些依赖，不能因主文件或只读占位未变就跳过。资源缺失、读取不完整或观察期间变化时停止，不提交新基线。

用上次成功的双侧基线判断动作。旧上传回执可在核实源路径、实际用户、目录和文档后接续，其中 sourceSHA256 对应本地基线，cloudSHA256 对应其当时回读的云端基线；不能把新的云端内容强行改成旧基线。缺少完整依据时待确认。

## 上传
实际读取配置中上传规范、文档规范及其适用引用的正文，记录来源与内容指纹或版本，不以文件存在代替已应用规则。必要规范不可取得时停止受影响上传，返回 needs_confirmation。

按当前源文件与规则准备独立上传稿，保留源文件，上传不自动改写本地原稿。格式与引用转换由执行 Agent 按规范完成，不声称 CLI 会自动修整。分别保存原稿与上传稿快照、转换说明及指纹，本地基线取原稿实际字节，云端基线取验证后的实际结构化正文，不能把格式转换差异直接认作新的本地修改。

飞书文档引用按规范使用原生引用，保留真实分享链接；未确认的本地引用如会使成果不可用则先待处理，不能顺手批量上传依赖。

经授权随该文档交付的图片等依赖，先按源 Markdown 位置解析，再转成平台工具可接受的安全路径并保留顺序、说明及映射。Mermaid 按所接入规范创建为原生可编辑组件，不能仅上传代码围栏；回读原生 record 核对源码。重跑沿配对及资源映射复用，不重复插图或创建组件。

不存在远端时按授权创建到指定目录，立即保存返回的标识和 URL。已有文档仅本地变化时，对照成功快照和当前正文选择最小局部修改，使用 lark-doc 的更新流程并保护原生引用、资源和评论。写前回读并传最新 revision，存在并发变化、评论定位不清或不能保真时停止；不能为简化同步而 overwrite。

修改可能影响评论锚点时，依上传规范读取所有评论及回复和定位；保留原区块，确需改变锚点时先满足恢复条件。只有整篇替换已明确授权且保护要求满足时才考虑重建，不作为首版的自动路径。

图片文件单独变化时，向原图片 block 上传新素材后原地替换资源，回读核对尺寸、说明、顺序及其他区块，不用再次插图代替更新。若现有工具不能原位修改 Mermaid record，不能声称保留原组件 ID；本轮无评论样例验证了备份后仅替换单一原生区块的路径。实际替换须符合授权范围及前述评论、资源保护条件，验证新组件后再移除旧组件，并更新 block 映射；保护条件不满足时停止。

回读后按实际适用规范核对标题、层级、列表、表头、公式、引用、资源和实际父目录，检查警告与降级提示；记录逐项结果及未验证范围，未核验完成时保留 pending_verification。写入结果不明时先查已知文档、目录和当前版本，不重复创建或盲目重发。

## 下载
使用 docs +fetch 的 Markdown、完整 XML 和 reference_map 保存原文。Markdown 可能含 DocxXML 原生引用和其他扩展，记录格式为 Lark-flavored Markdown，保留转义与元数据，不通过去标签把它变成缺资源的纯文本。

下载前核对本地目标及基线。已有文件只在它仍等于先前观测值且方向允许时写入，保留旧版恢复依据，先写同目录临时文件再原子替换；不能覆盖扫描后出现的本地编辑。指定不存在的文件可以初始化，但已跟踪后消失的一侧要待确认，不从缺失推导删除或重建意图。

图片、附件、画板、文本绘图及未知资源按相应工具保留源内容、引用映射和长期依赖，不能只存只读占位。正文之外的原生块须按同一版本读取完整数据并保存。PNG 图片下载实际文件并核对内容指纹，原生文本绘图保存完整 record 和 Mermaid 源码。

保留未经改写的 Markdown/XML 导出和元数据，再根据已核对的 block、token 与顺序映射生成本地稿：图片使用已下载依赖的相对路径，Mermaid 使用从原生组件取得的代码围栏，原生文档引用及转义继续保留。不得按占位符外观猜源码或顺序；无法唯一对应、未识别组件或其他资源不能完整保留时，停止受影响下载。当前真实样例覆盖单张 PNG、单个原生 Mermaid 文本绘图及文档引用，不能据此承诺所有素材保真。

先保存经过验证且不会覆盖旧依赖的资源文件，再原子替换 Markdown 入口，最后提交资源清单与双侧基线。保留旧入口和资源用于恢复，不自动清理旧依赖。仍记录 Lark-flavored Markdown，普通 Markdown 查看器不保证显示原生文档引用。

## 双向、冲突与提交
both 沿用同一组比较规则：单侧变更只执行对应方向，双侧变化一律 conflict。保存两个当前快照、原成功基线和差异；不自动选本地或云端，不生成替代业务文档，不推进成功基线。

单侧传输后再次核对未写入的源端是否仍匹配原观测、目标是否符合预期。保存成功的本地正文与云端 XML/Markdown/引用元数据，再原子更新状态指向新基线；原基线保留用于恢复。任一阶段不明则 pending_verification，接续先核实两端，不把失败转成成功。

回读与接口校验不代表已验证全部客户端显示。不得自动调整权限、传播删除、启动定时任务或发布留言。
