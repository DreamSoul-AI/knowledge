# 中断恢复 conversation-resume

本技能帮助 Agent 接回已有上下文中的工作。它先看任务和停下原因，再决定直接继续、补一条变化、索取必要输入，或保持当前状态。

# 一、使用

调用名为 `$conversation-resume`。旧名 `resume-interrupted-chat` 安装版迁移时先保留个人修改，再切换完整目录，仅保留一份可发现的技能入口。

- “恢复这个对话刚才中断的任务，原要求不变”
- “继续那个对话，但输出改成 JSON，其他要求沿用”
- “检查这些对话哪些是意外中断，先告诉我，不发送消息”
- “此前暂停的事项现在恢复，沿原有范围继续”

当前对话可以直接续做，不必发送消息给自己。其他对话先核对实际对象，已知要求未变时发送 `resume`，发生变化时只补必要变化。只要求检查时不顺便恢复。

**暂停和等待。** 历史暂停不能被自动恢复。本轮明确恢复授权可以改变暂停状态，但不能伪造历史停因。正在执行或等待必要输入、审批的任务，需要观察或处理该依赖，而非不断发送 `resume`。

**回合和任务。** 一轮 `completed` 可能只是已经问了一个问题，也可能只是做完一阶段。要读正文及产物，不能看到状态就说整个项目完成。

# 二、可选快照粗筛

脚本是只读筛选助手，不能自动恢复任务，也不判断自然语言里的真实意图。

```json
[
  {
    "thread": {"id": "synthetic-a", "turns": [{"status": "interrupted"}]},
    "stop_intent": "execution_interruption"
  }
]
```

```text
python scripts/classify.py snapshots.json
```

输入路径由调用方提供。`stop_intent` 必须有已核实的依据，未知时保留 `unknown`。脚本将 `completed` 标为 `closed_or_waiting`，不能据此得出任务完成结论。用户明确重新授权的暂停任务也由当前 Agent 判断，脚本标签不构成阻止新授权的永久规则。

# 三、结果和边界

交付区分发送、运行和实际完成。结果未知时先回读，再决定是否重发。有写文件或发布等副作用的工作，按实际执行证据确认断点，本技能不提供恰好执行一次的事务机制。

此前有限合成实验支持按已有上下文选择简短恢复消息。观察到的是目标恢复轮少量输入差额，不能证明整套流程净省 token 或金额，也不能据此承诺缓存收益。复杂业务写入、审批和长上下文压缩恢复没有因此获得完整验证。

安装时保留完整技能目录中的 SKILL、agents、references 和 scripts。使用已选择来源的固定版本，实际读取与恢复结果分别核验，不将源码目录可读等同于已经安装或自动发现。
