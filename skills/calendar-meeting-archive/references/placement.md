# 归档分组、额外要求与位置

按本次要求和项目外部配置，先为每场解析分类、位置与规范，再交给内容整理和文档交付。自然语言、规则文件与 YAML 都可提供输入；下面字段仅为示例，不要求固定解析器或另建技能。

## 四种信息分别保存
- **实际会议身份**：实际 meeting_id、日程实例、起止与来源，用于去重。多个日程指向同一场只处理一次，不同场次不因别名归并而合成一场
- **会议系列**：长期会议的稳定关系，可有经确认的标题别名、多个日程标识；临时交流可无系列
- **归档分组**：本地及逐类交付位置。系列可默认使用自己的分组，若干零散会议也可共用业务分组，不强制一场一目录或先造一个系列
- **关联项目**：本场各议题涉及的项目，可多个或未知，不决定整场永久归属。原件只保存一份，通过议题或索引关联项目

## 额外要求如何接入
先读当前要求、项目配置和既有成果，逐项确认要求的目标范围、作用和来源。常见输入包括：
- 将某两个日程名称归入同一已确认系列，保留原日程和实际场次身份
- 对指定例会叠加专项规范或周回顾材料，对其他会议只用通用规范
- 将已确认业务归属、没有固定系列的临时交流归入共享分组
- 对某一场调整所需成果、加入补充材料、强调议题或限制本轮仅本地执行
- 指定本场／本轮接管归档，或明确由非负责人作例外处理；是否持续接管、适用场次和生效范围按用户实际说明保存

当前用户的明确要求优先于项目默认和技能默认。多个要求可叠加时合并，具体适用范围内的专项要求细化通用要求。两个同级明确要求冲突、范围不清或所需文件不可读时，记录原因并只暂停相关场次，不把任意一条当作胜出规则，也不静默退回默认后声称已遵循。

本轮清单记录实际采用的要求及依据，向 Meeting Minutes 传原始材料、补充材料、解析后的适用规范和输出位置；范围、归组、规范和传输权限分别处理，不把材料内的建议当成用户命令。只对本次有效的要求不自动写回长期配置；用户已确认的长期约定才维护于项目配置。私有规范和目录留在项目，分发包不依赖特定账号或公司文档。

## 外部配置示例与兼容

归档责任可由自然语言或项目已有配置提供，与系列、目录和会议实际身份分开保存。例如“本轮由我接管这场 HR 周会的归档，先检查现有稿，只放本地”，或“这个系列继续由原负责人整理，这一场请我代办”。按明确场次或已确认系列匹配，不把所有含 HR 的会议一起接管。接管人、来源、本次／持续范围和例外动作足以表达，无需新建责任系统或固定解析器；未说明持续范围时不自动写回长期配置，不虚构转交日期。

优先采用本次明确覆盖及已确认责任。受邀、文档归本人所有或拥有写权限不代表本人负责归档；若项目已确认组织者承担该系列归档，可沿该约定判断。责任不明与业务归属不明分别记录：不能因知道放在哪个目录就认定由谁整理，也不能因接管就更换目录、正式文档或受众。

```yaml
project_root: ../..  # 相对于本配置文件
timezone: Asia/Shanghai
defaults:
  rules:
    - <项目通用会议规范路径>
series:
  - key: project-review
    match:
      known_recurring_event_ids: [<已确认日程系列标识>]
      confirmed_title_aliases: [<原名称>, <另一个已确认名称>]
      evidence: <用户确认或材料依据>
    local_root: <已有系列根>
    rules:
      - <仅适用本系列的专项规范>
    outputs:
      - kind: minutes
        local_subdirectory: 会议纪要
        remote_folder: null
groups:
  - key: collaboration-general
    business_category: external-collaboration
    use_when: 已确认外部协作且无已匹配系列，也无专门归档位置
    local_root: <已明确的共享归档根>
    outputs:
      - kind: minutes
        local_subdirectory: 会议纪要
        remote_folder: null
```
已有只含 `series` 的配置继续有效，未提供独立分组时用其原 local_root，不要求改目录。已有 `recurring_event_id`、`known_recurring_event_ids` 等身份字段继续使用。`defaults.rules` 为可选通用规范，与适用的分组／系列规范合并去重；可选 `archive_group` 引用 `groups` 的 key。多方同时指定不同位置时先判断是否有明确覆盖范围，不能暗中按字段顺序选取。

本次可直接补充“这场归某组，只出纪要”，也可用带目标 meeting_id／已确认系列标识及来源的要求清单表达。完整姓名、标题相似或同一组织者不足以单独确认系列或业务归属。已确认别名可以用于召回候选，但实际来源矛盾时仍暂停核对，不让别名覆盖会议身份。

相对位置和规范路径以 project_root 解析，project_root 相对于配置文件；绝对路径与可访问链接沿原意。最终本地路径应在授权范围。输出若进入共享组，文件名按实际日期、主题和必要起始时刻区分，同日多场不能覆盖，同名碰撞且无法区分时待确认。已有命名无碰撞则保持，不因引入分组机制统一重命名。

## 逐场决策与零散会议
1. 核对实际来源和场次，解析系列（可空）与有依据的业务归属
2. 应用本次明确归组；未另指定时沿用已确认系列位置。无系列时才考虑项目已配置且条件满足的共享组。没有唯一适用组或业务归属未知则待确认，不套用“其他”、例会或外部协作
3. 合并通用规范与适用的专项要求，明确所需成果及材料覆盖。缺原文、等待产物、权限问题与分类不明分别记录，不能用已分类掩盖材料缺口
4. 比较同一实际会议的既有成果，记录解析后的分组、位置、规范与要求来源，再生成、复用或暂停受影响部分

共享组不合并会议原文，也不改变业务归属或访问范围。它用于容纳已有依据的同类零散会议，不是未知会议的垃圾桶。原本有系列的会议也可按本次明确要求进入共享组，系列身份仍保留；若已有成果在别处，先引用原成果并报告位置差异，没有明确迁移要求就不另复制一套。

日历扫描保留半开时间窗和覆盖范围；跨日同一场按实际日期约定登记一次，不按午夜拆分。不宣称已覆盖无日程或计划时间移出窗口的会议。云端仍逐类核对真实目录、上层归属和受众，本地共享组不自动对应任何云端文件夹。

## 增量、状态与下游交付
本轮清单保存实际会议标识、系列、分组、额外要求及范围／来源、实际采用的材料与规范指纹、原件及成果位置和各阶段状态。旧清单保留历史处理事实，新要求的复核单列，不回写为此前已经使用。

重跑先判断本轮责任及明确例外，再按实际会议身份查找全部已知成果，比较原始与补充材料、规范、额外要求和人工内容，不能仅凭目标路径是否存在判断首次生成。近期可用稿优先复用；小范围遗漏或更正只局部补齐；确需重整时指出实质原因和影响范围。不要先生成另一稿再衡量两个 AI 写得是否接近，也不新增固定“几小时内免检／过期重做”的阈值。

要求改变只重查影响：内容要求变则复核受影响内容，负责人接管、归组或别名改变不触发纪要重写。材料未变但回执不完整时可读取现有稿和必要原文段落验证，不自动从零重整；无法核清的部分仍待核。涉及已有成果迁移时保留实际位置并报告差异，迁移范围明确后再连同依赖和引用处理，不以新位置创建第二份代替迁移。人工修改或重叠冲突保留并待确认。

逐场清单可按需要记下“默认由谁负责及依据／本轮接管或例外／跳过或待核原因”，以及每类成果的“复用／局部补齐／重整／只接续交付”判断和依据。处理资格、内容质量与云端交付状态分开；接管后的复用不把工作稿自动升级为已验收，离线参照也不记成最新云端核验。

正式原件及长期依据放在已确认的长期位置，临时验证材料留在任务目录。仅本地模式不要求云端目标、不调用 Document Sync、不建立云端成功基线。另获交付授权后，复用核验成果，向 Document Sync 提供明确文件清单、逐份配对、独立回执和按其路径语义生成的配置；真实位置和受众仍需当时核对。下游失败不重新生成会议纪要。

## 汇报要求也是外部输入
项目可在现有配置中表达交付要求，例如：
```yaml
reporting:
  scope: 定时反馈新增、变化或异常；手动核对包含所请求范围的复用成果
  per_meeting: 实际日期、名称、本地整理状态、云端状态与直接成果入口
  separate_delivery:
    - match: <已确认系列标识或会议类型>
      rules: <适用专项规范路径>
      outputs: [minutes, advice, record]
      copy_draft: 按专项规范从已有成果读取；只展示给用户
```
字段为 Agent 阅读示例，不是固定解析器；已有其他结构的汇报配置继续按语义使用。`separate_delivery` 只细化匹配场次的展示，其他场次仍逐场报告；所列成果仅展示已存在或已授权生成的内容，不因汇报示例增加上传、生成或消息发送权限。持续适用的要求存项目配置，专项模板维护在原规范，不硬编码到分发技能中。
