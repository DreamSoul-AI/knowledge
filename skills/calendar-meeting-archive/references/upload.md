# 上传与增量归档

只在本次任务要求上传或已有明确上传配置时读取本节。复用当前安装的 lark-drive、lark-doc、lark-shared 及对应命令参考，先确认用法，全程显式 `--as user`。这是一轮可重复运行的编排，不自带定时调度。

## 优先交给 Document Sync
本次指定或已安装 document-sync 时，先读取其实际版本的 SKILL.md，提供本地成果清单、已核验的逐类目录映射、已有文档完整链接/稳定标识、适用规范以及每对文档独立的 receipt。交付使用 `direction: upload`、`conflict: stop`、`delete: false`，不因统一归档开启双向下载。配置相对路径按 document-sync 配置文件所在目录解析，不能直接照搬项目配置的相对路径。

由 Document Sync 处理两端快照、基线、引用与资源、冲突和写后回读；本技能保留会议身份与来源，以“实际场次 + 成果种类”分别配对和保存 receipt，并汇总实际返回状态。来源未变仍检查云端改动，冲突不重写成功基线。同步失败保留本地成果，不能重新生成纪要或绕过冲突再导入一份。

指定依赖缺失或版本能力不足时停止受影响交付，不自动安装或切换其他路径。未指定依赖且未安装时，下文保留独立飞书交付方式。两种路径一次只采用一种，均须按本次授权执行。

## 目标与范围
- 目标来自用户本次指定的飞书目录，或其已确认的配置。明确的 `/drive/folder/` 链接取得 folder_token；类型不明用 `drive +inspect` 核对。知识库节点走 lark-wiki，不把 Wiki token 当 Drive 文件夹 token。
- 列取实际目标及相关子目录，取全分页；可列取只证明可读，创建和编辑权限看实际结果。沿用项目既有分类、命名和目录，不能凭本地同名目录猜云端位置，也不移动已有资源来迁就新结构。
- 会议记录、纪要及建议是否上传，由本次要求或已确认项目配置决定；不能以通用的“默认纪要”省略已明确要求的原文，也不自动上传未列入范围的原文。会议记录保留实际取得的转写、笔记类型、范围和来源，不能补造完整逐字稿。录音、视频、简历及其他附件另行确定，不因上传会议记录而整包外发。
- 各成果分别核实目录及受众，不把纪要目录或“会议总结”父目录自动当作原文目标。只有纪要目标明确时，仍可处理纪要，将记录留本地并登记待确认。面试等受限内容按对应归档规范核对访问范围，原文的受众也须适用，不能只凭纪要可写认定原文可共享。不自动创建未确认目录、改变共享权限或通知他人。
- 上传前核对标题、正文和来源，避免标题重复。按项目上传规范处理原生文档引用及本地链接；无法确认云端对应资源时保留引用并说明限制，不编造链接。不为上传而改写本地原件。

## 找到已有成果
先读本次来源清单中“日程实例／实际 meeting_id + 成果种类 → 目标 docx token”的映射，再分别列取对应目标目录核对位置。已有纪要不能替代同场会议记录的查找与去重。无映射时按标题召回候选并读取正文核对来源、实际时间及场次；标题或修改时间不能单独证明同源。

```powershell
lark-cli drive files list --params '{"folder_token":"<folder_token>","page_size":200}' --as user
lark-cli drive +search --query "<30字以内的标题片段>" --only-title --doc-types docx --folder-tokens "<folder_token>" --as user
lark-cli docs +fetch --doc "<文档链接或token>" --detail full --as user
```

`files list` 按 `has_more`、`next_page_token` 续页。搜索未命中仍要结合目录与已有映射判断，避免检索遗漏造成重复。多个候选无法唯一匹配时保留待确认，不覆盖、不再新建一份。

## 创建或更新
首次创建前确认该实际场次、该成果种类没有同源成果。本地 Markdown 默认转换为在线文档，显式给定标题和目标文件夹，同一位置串行导入：

```powershell
lark-cli drive +import --file ./minutes.md --type docx --name "<正式标题>" --folder-token "<folder_token>" --as user
```

从零在线创作、需原生引用或复杂排版时按 lark-doc 创建流程处理，直接创建在已核对的目标。`+import` 不更新已有 docx，不能用重复导入代替修改。

已有文档写前重新读取，与上次已验证版本及新稿比较。来源未变仍检查云端人工改动；内容一致则跳过。只更新确定无重叠冲突的局部，保留人工补充与更正，重叠差异列待确认。采用 lark-doc 的 `+update` 及刚读取的区块标识；结构变化后重新读取，不用旧区块 ID 继续写。

影响评论锚点时，按项目上传规范保存正文、版本、完整评论及回复的恢复依据。`docs +fetch` 默认评论不能代替全量备份：用 `drive +list-comments --solved-status all --need-relation`，处理列表分页和各评论卡片内部回复分页，必要时 `+list-replies`。保留承载评论的区块，不自动重建文档、删评论或解决评论。

## 结果核验与恢复
- 检查退出码、`ok`、身份、警告及部分成功信息。导入仅返回 ticket 时，用 `drive +task_result --scenario import --ticket <ticket> --as user` 继续查询该任务，不再次创建。
- 创建或更新超时、结果不明时先核对已知 token、导入任务、目标目录和正文；确认未成功才有限重试。仍无法判断则记录“结果待核对”并停止该场写入，不盲目重发。部分成功只修失败部分。
- 成功后回读正文，检查实际内容、标题、表格和来源引用，再列取目标目录确认 token 的位置。采用平台实际返回或复制的链接。接口回读不能宣称客户端渲染已核验。
- 网络或限流可有限重试；身份、scope、资源权限问题分别报告，不换机器人、不换目录或自行申请共享。单场失败不阻塞其他已授权场次。
- 在本次任务的独立清单按来源实例、实际会议 ID 和成果种类分别记录原文哈希、本地文件、目标目录和 docx token、已验证内容／版本、独立 receipt 及上传状态。原文和正式纪要长期保留，临时响应与恢复快照放任务 tmp。重跑按当前所需成果核对清单和实际目标；本轮范围内旧“完成”场次缺记录时，只补记录，不重生成或重传已有纪要，不改写其他成果的成功基线。某类目标不明、冲突或失败只挂起该类交付，保留其他成果的独立结果。
