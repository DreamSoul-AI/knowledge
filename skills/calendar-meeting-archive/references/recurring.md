# 定时运行与接续

本参考用于已获用户授权的重复运行。同一个 Calendar Meeting Archive 调用 Meeting Minutes 整理内容，再按明确清单调用 Document Sync；不复制内容规范或传输实现，不新增一层技能。创建、合并、改时或暂停调度任务只在用户明确要求配置任务时执行，不能在每次归档时自动做。

## 输入与既有状态
从项目配置读取本次时区、来源日历及筛选范围、首次起点或回看窗口、持久状态与锁位置、已确认目录和所需成果。配置供 Agent 阅读，不是可执行解析器，也不自行产生上传授权。手动指定日期的运行不推进定时扫描覆盖进度。

每轮先按已确认会议管理人／归档负责人和本次接管或例外判断处理资格，再检查已有稿；单纯参会或配置了日期范围不自动覆盖负责人默认规则。已知他人负责时跳过新整理及上传，责任不明集中记待核。保存责任依据与本轮覆盖范围，不把本轮例外自动固化，也不改日历或权限。

合并或替换任务时，先核对来源聊天及调度任务，暂停重叠任务，再接入所有已知逐场清单、固定云端对象、比较基线和待处理项。相同实际会议和成果种类指向不同对象时，先核对归档受众／作用域，再按 [云端多稿核对与归结](reconciliation.md) 保留正式稿与其他版本的关系，不按状态文件新旧择一覆盖，不重建文档。旧记录保留历史事实，新状态记录来源指针和本轮结果，不能把导入的旧回执标成刚刚在线核验。
已有正式文档缺实际会议 ID 时，按固定文档标识独立保留候选与来源，不把多个空 ID 归成同一会议。新场次也要查这些已知成果并核对来源，不能因实际 ID 尚未登记就直接再建一份。按当前范围逐场核对所需成果种类，不能将旧“完成”或纪要已上传视为记录已交付；本轮明确范围内缺会议记录时登记并只补该类交付，复用既有纪要。交付要求变化不自动扩展为历史全库重跑。

## 扫描窗口和补漏
每轮开始固定带时区的触发时刻及扫描截止点。来源范围为：上次已完整列举的截止点到本轮截止点，加已确认回看窗口，另加全部未完成项。首次没有覆盖进度时使用确认的起点或回看窗口，不擅自扩展到全部历史。按自然日分批时用显式时区的半开区间，并完整读取分页。

只处理实际已结束、可确认发生及身份的会议。前一日、跨日和恰在扫描边界的场次按身份去重，不按午夜拆成两场；结束时间等于截止点也要考虑，不能只依赖开始时间筛选。开始时间早于窗口但在窗口内结束的长会，需通过跨界日程或未结束事件跟踪补查。保存本轮尚未结束的事件线索供后续核实，不因中午运行忽略当天晚些时候才结束的会议。不声称覆盖无日程或无法列取的会议。

仅完整获取某段来源及全部分页后，才推进该段扫描覆盖。来源列举失败或部分分页不能记作完整扫描，但已取得的独立场次仍可接续。扫描完成不表示每场已上传：等待转写、权限不足、冲突和未知归属另存逐场状态，超过回看窗口也保留。停机漏跑从旧覆盖点分段补齐，不能以“最近几天”截掉已承诺范围。

已列举但按负责人规则不处理的场次记录筛选结果，不误记成待生成材料反复重做。以后明确接管时，在本次范围内重新判断该场资格与既有成果即可，不从零重建文档或重置全部扫描进度；接管未覆盖历史时不扩大为全系列补跑。

## 重叠与中断
同一归档范围共享一个持久运行锁。先核对状态和既有运行，再用独占文件创建取得锁，记录 run_id、承载聊天、调度任务和开始时刻；无法取得时本轮不生成或写入成果，也不推进扫描进度。手动补跑同一范围也使用此锁。锁的年龄不足以证明已失效，须核对承载聊天或进程状态；不能确认时报告阻塞，不自行删除。

逐场成功或转为待处理后，写前重读状态并合并其他已保存字段，通过同目录临时文件和原子替换保存。当前轮次只释放属于自己 run_id 的锁；异常保留中断证据和待核状态。下轮先核对已知对象及写入结果，再恢复未完成环节，不能重复创建或将不明结果提交为成功基线。

本地运行锁仅约束实际共享此锁路径的执行，不代表不同电脑或参会者不会产生云端重复稿。发现多稿后按核对与归结流程处理，不以此要求所有使用者只能由同一人归档。

## 无人回复与交付
合格场次先作逐成果复用判断：近期已有稿满足当前实质要求、来源覆盖可核对且无明确错误则复用；明确局部差异才补齐，需要重整时保存实质原因。每轮触发、更换模型、接管或回执年代本身不触发重整，也不能把“先生成新稿比一比”作为检查方法。只有离线快照时标清核验边界，保留待核项，不把它当最新在线成功基线。

归属明确且本地位置已确定时正常整理。归属不明时，将可取得原件和身份映射保存在已授权的待确认材料位置；未配置此位置则只保留状态和已有原件，不猜系列或迁移旧成果。上传位置或受众不明时保留本地成果，将原因与候选依据集中记入待确认清单，下轮有新证据再复核。无原文、部分原文和平台 AI 摘要区分记录，缺什么不补写什么。

已确认系列沿原目标，新增未知系列不能按相似标题、可写权限或同名本地目录自动上传。Document Sync 使用 upload、conflict: stop、delete: false，发现人工修改或两端冲突时保留差异。所需会议记录、纪要和建议读取本次要求或已确认项目配置，不以会议是否例会决定原文能否交付。按成果种类分别核对目标、受众和配对；某类位置或访问范围不明时，只将该类留本地并记为待确认，其他已明确成果继续。例会、周回顾或其他专项规范仍只对匹配的会议适用，录音、视频、简历等附件不随会议记录自动上传。

无人值守运行发现多稿时，若当前配置没有明确归并场次、成果、目标和允许修改范围，只记录同源依据、候选差异与建议动作，报告待处理，并复用可确定的正式稿；不能把通常的上传授权扩展成重写其他人的稿件、切换正式入口或写入副本标识。没有确定正式稿时保留本地结果，不新建一份替代。后续获得相应范围后只接续待处理动作，不重跑无变化的会议。

状态至少保存范围与成功扫描段、未结束事件线索、逐场身份/材料/分类/本地/云端各阶段状态、各成果种类和作用域的固定配对及独立回执、多稿关系与待确认修改、运行锁归属和最近结果。结果返回承载任务聊天，沿已确认通知规则报告有意义的完成、变化、失败或待校准项；相同问题没有新信息时不反复通知。不得发布留言、改权限或日程来消除异常。

规范允许按价值省略会议建议时，保存本场材料与规则指纹、筛选原因和“不生成”的结果，将其视为本轮已处置的条件成果。未变化时不再尝试生成，不要求空文档或建议链接，也不记为记录、纪要缺项；材料或规范变化时再复核，不因规则变化自动重写已有建议。

## 每轮结果如何交付
从外部配置读取汇报范围、单独展示的会议类型、所需成果入口和适用专项规范；启动时主动读取，不依赖调度聊天的历史上下文。配置未指定时，反馈本轮有新增、变化或异常的场次；无变化沿已确认通知规则执行，不能为了输出链接重生成已有稿。

需要反馈时，按系列或类型、实际日期逐场、逐成果种类给出本地整理与云端状态及真实成果链接，区分新增上传、局部更新、复用既有稿、仅本地和待处理。指定专项会议单独展示其所需成果，其余会议也要列出。缺少链接或材料明确说明原因，附现有本地入口；总报告可补充但不能替代直接成果入口。手动查看或验证包含所请求范围内的复用场次，不能把“未变化”当成省略入口的理由。

专项规范要求的复制文案从适用规范和已归档成果读取并按要求展示，不由通用工作留言替代，不另行维护模板。仅汇报方式变化时只调整反馈；所需交付成果变化时按本轮范围补缺，内容要求未变则不重写或重传已有纪要。汇报、草稿、实际发送分别记录；传输授权不包括给同事发消息或发布留言，未明确授权不新增这些动作。
