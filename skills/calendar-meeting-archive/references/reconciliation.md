# 云端多稿核对与归结

用于多人已将同场会议的记录、纪要或建议分别上传，当前任务需要核对差异并归结正式入口的情况。先允许不同稿件存在，再根据来源与当前授权处理关系；不以唯一发布者或跨电脑锁作为使用前提，也不声称此流程提供原子去重。本地副本数量不是本流程的清理对象。

## 确认同源与作用域
先在本次已授权、当前身份可读取的目录和既有清单中查候选，保留完整文档标识、真实链接、版本、来源和位置。按“平台＋实际会议身份＋成果种类＋已确认归档受众／作用域”归组。实际会议 ID、来源绑定及发生时间共同支持同场判断，标题相似、日期相同或两个空 ID 不证明同源。记录、纪要和建议分别核对。

归档作用域同时考虑业务归属、用途与允许受众，不仅比较目录名称或当前可写权限。同场的人事受限稿、全体摘要和个人记录可有不同作用域，不能跨范围合并或复制内容。信息不足或部分文档不可读时明确缺口，不将“未见到”当作不存在，也不申请共享、改权限或搜索未授权范围来补齐。

## 原始依据与内容判断
读取可取得的原始记录、补充材料、适用规范和候选正文，保留实际版本及阅读边界。原始材料与已确认更正用于判断事实，多个 AI 稿彼此一致不等于独立证据。逐项保留决定、汇报、设想、否定、条件及行动的边界，不以篇幅较长、更新时间较新或创建人身份自动认定正确。

| 关系 | 核对后如何处理 |
| --- | --- |
| 等价重复 | 内容与必要资源确实等价时记录关系，沿正式入口复用，不生成第三份。只有文字相同而资源、评论或覆盖未核清时，不宣称整份文档等价 |
| 有效互补 | 将原始依据支持、属于同一作用域且不改变原意的缺失内容列为局部补充，保留来源定位，不整段拼接重复内容 |
| 原文可裁定的差异 | 根据原始发言及后续更正形成校订建议，记录依据；有本次相应修改范围时局部校订，不把旧 AI 表述当作事实依据 |
| 待核冲突 | 原文不足、身份不明或同级依据矛盾时保留不同说法及影响，指出具体待核项，不折中编造数字、日期、负责人或结论。独立可确认内容继续处理 |
| 不同受众／作用域 | 分开归档关系和正式入口，不视作可清理副本，不通过合并扩大信息可见范围 |

会议记录保留实际取得的来源导出及覆盖，不能将不同人的转写自由拼成未说明来源的“完整原文”。确需补足覆盖时先核对同场、顺序及重叠，明确各段来源，不改写原始导出。会议建议则核实其问题背景与事实前提，区分 AI 提议和会议决定；新想法不必已在会上提出，按传入专项规范筛选互补与重复，不复制另一套建议模板。

## 选择正式入口
优先沿用用户已确认或既有有效配对中的正式文档，保留其稳定链接。内容有缺失时可在本次授权范围内吸收其他版本的有效内容，不因另一稿较长就切换链接。有多个候选而未确定正式稿时，说明各候选的来源覆盖、事实质量、既有使用入口及评论资源，提出选择依据；正式入口的确定或切换须在当前明确范围内，不能将候选推荐记作已确认结果。

同一作用域可指定一份正式稿，同时保留其他云端文档的历史链接与讨论。正文归结、正式身份确认和副本处置分别记录；“只有一份正式稿”不意味着已经删除其余对象。

正式入口已确认只表示沿用该对象，不表示其中每条事实均已核清。若正式稿自身含未裁定的数字、日期等表述，在本轮已授权修改范围内将受影响正文局部标为待核，并保留具体分歧；未获该修改范围时，交付中明确指出正式稿仍含哪些未核项，不能仅在旁表登记后宣称内容已统一。

## 权限与局部修改
区分读取比较、形成方案、修改选定正式稿、切换正式入口、在其他稿写入状态链接，以及删除或移动。只执行本次明确的相应范围，已有上传配置不自动授权重写其他人的稿件或标注副本。未授权修改时仍可完成可读材料的核对、提出逐项方案并复用确定的正式稿。

已授权归并时，以刚读取的正式稿为基础形成最小修改，保留双方有效内容及每项判断的原文依据。将选定正式稿的本地结果、固定云端标识、适用规则与独立回执交给 Document Sync，沿其现有冲突与写后验证流程执行。若仍有两端冲突或观察后并发修改，保留差异并重新核对，不通过伪造成功基线、换目标或重复导入绕过。

写前重读目标及受影响资源、评论和版本。保留原链接、承载评论的区块、完整回复及资源，按项目上传规范保存必要恢复依据；无法保真时停止受影响修改。不默认把另一文档的评论迁移到正式稿或冒充原作者，原评论继续留在原对象。资源来源、适用范围或访问权限不明时，不随归并自动复制附件。

只有本次明确允许在其他版本标识正式入口时，才作必要的局部增补并回读真实引用和链接；不删除原文，不搬迁对象。没有执行该标识时，报告“清单已确定／提出正式关系”，不能声称云端所有读者已看到统一入口。新出现的重复稿重新核对即可，不因有人再次上传而覆盖正式稿。

## 记录、重跑与交付
沿用现有逐场记录、索引和独立回执即可。可按实际需要补充：正式文档固定标识及确认依据、其他版本及关系、候选来源位置、待核主张、建议／已授权／已执行动作、实际回读结果。不要为此另建数据库或把每份候选共用同一成功基线。

字段示例仅帮助表达，不是新增解析器接口：`canonical` 记录固定文档与 proposed／confirmed 状态，`variants` 记录文档及 equivalent_duplicate、complementary_variant 或 conflicting_variant 关系，`pending_actions` 记录具体差异、原文依据和未完成动作。不同作用域另组保存。身份、关系与动作状态不能仅凭自动评分或文件修改时间填定。

重跑沿已确认正式对象和每份实际文档查差异，不重复插入状态入口或创建新稿。只更新实际完成且回读通过的成果基线，其他版本的旧回执和评论保留原义。按场次、成果种类和作用域报告正式入口、其他版本关系、已合并内容、待核差异及未执行动作；来源不可读、资源无法保真、传输冲突和缺少修改范围分别说明，不阻塞无依赖的其他会议。
