# 日历会议归档

从本人日历或已有来源清单查找已结束会议，先判断本轮由谁负责、已有成果能否复用，再按需要补充或整理。适用于评审、研讨、项目沟通、例会和面试等会议，来源获取与交付按实际需要和授权执行。

## 安装与环境
安装整个 `skills/calendar-meeting-archive` 目录，保留 `SKILL.md`、`agents/` 和 `references/`。需要已有 lark-cli、相关飞书日历／会议／文档／云盘技能，以及当前用户对来源和目标的权限；这些服务集成不包含在本仓库中。

本技能可独立运行，已安装或本次指定 meeting-minutes 时传入材料与规范，已安装或指定 document-sync 时复用其文档交付流程。指定依赖缺失时报告缺口，不静默换版本。项目已有模板、归档目录和访问规则优先。

## 使用
```text
使用 $calendar-meeting-archive 整理我本周已结束会议的纪要，并上传到这个飞书文件夹：<本次目标文件夹链接>。
```
可指定日期范围、时区和会议筛选条件。未给日期时从用户当地今天的已结束日程开始；未给目标时先整理本地成果并询问位置，不上传到云盘根目录。每个人使用自己的登录账号和目标目录，无需读取邀请人的整个日历。

## 处理责任与例外
默认由已确认的会议管理人或归档负责人整理和交付。日历组织者、受邀身份、录制所有者或文档所有者只是线索，不自动等于归档负责人；以用户明确要求或已确认项目责任映射为准。负责人不清时说明缺口，不因此另做正式稿。他人负责的会议，可在本次范围内复用可读取成果，不另起一套归档。

用户可指定本轮、单场或已确认系列由自己接管，也可明确例外处理，记录实际范围与依据。一次性接管不自动变成长期负责人。责任与实际会议身份、归档分组、目录及平台权限分别判断；接管不改变这些信息，也不自动授权上传、搬迁、改权限或发消息。

```text
这轮 HR 会议归档由我接管。沿用已有纪要、文档链接和位置，先判断能否复用，只对有依据的缺项局部补充。先只在本地处理。
```

## 先判断复用，再决定是否整理
先读已有稿、其来源与覆盖说明，以及实际适用的实质要求。近期已有总结且内容适用、材料没有实质变化时直接复用；整理时间只帮助判断新鲜度，不单凭修改时间或固定天数判质量。两个 AI 的措辞、布局、模型或作者不同，本身不构成重做理由。已有材料指纹和核对记录可供比较，没实际检查的不声称已核验；已知稿件不可读是材料缺口，不等于不存在。

选择必要的最小动作：已有稿可用就复用；明确缺项或错误有依据时只补充、校订对应段落；新材料、实质要求或已确认错误确实影响内容时，再补做缺失内容或复核受影响部分。按判断所需查原始材料，不先完整重跑一次总结再决定有没有必要。保留人工修改、未裁定事项及原有阅读边界。负责人变化本身不是内容变化。

确需新做完整总结时，仍须完整阅读可取得原文；局部校订则读取相关发言及上下文，不把局部检查写成全场重新复核。

## 项目目录配置
可传入外部 [归组与要求配置](placement.md)，也可在消息中补充负责人、接管范围、别名归并、归档分组、补充材料与专项规范。已有系列配置继续有效，临时会议可无系列，使用已确认的共享分组。分组不等于项目，未知责任、业务归属或冲突只暂停受影响场次。配置不携带上传授权，也不启动自动化。

例如：将两个已确认名称归入同一系列；例会使用其专项规范；无固定系列且已确认属于外部协作的零散会议，放入指定共享组；本轮只放本地。Agent 先逐场解析范围、位置与适用规范，再整理。一次性要求留在本轮清单，不自动固化。

## 流程与成果
确认负责人及本次覆盖要求 → 检查已有成果 → 复用、局部补齐或必要的新整理。需要整理时才按 [来源获取](sources.md) 取得并阅读本次所需原始材料，获得交付授权后再做 [上传与增量归档](upload.md)。原文及来源映射长期保存，云端是否交付会议记录、纪要和适用建议，按本次要求或已确认项目配置确定，不以“默认纪要”省略明确要求的记录；未要求的原文、录音、视频、简历和其他附件不自动加入。各成果分别核实真实目录和受众，不把纪要目录或其父目录自动当作原文目标。某类目标不明时只将该类留本地，其他已确认交付继续。面试等特殊类型按项目对应规范整理，受限记录不能统一放入受众过宽的目录。

按实际场次与成果种类分别配对、去重和保存目标、文档标识、独立回执及状态。重跑核对当前所需成果、来源和目标实际内容；旧“完成”或纪要已上传不能代替会议记录交付，本轮明确范围内缺记录时只补记录，复用已有纪要和成功基线，不扩大为历史全库重跑。同源内容未变则跳过，人工修订保留，冲突列待确认。返回逐场状态、真实成果链接及失败原因。上传任务超时先查已有任务，不重复创建。

## 多人形成的云端稿件
发现同场会议多份云端稿时，将 [云端多稿核对与归结](reconciliation.md) 作为补救流程，不再先生成一份。确认实际会议、成果种类和归档受众／作用域，对照原始材料区分等价重复、有效互补、原文可裁定的错误和待核冲突；不同受众材料分别保留。沿用已确认正式稿的稳定链接，按本次明确的范围局部校订，保留其他文档的链接、评论和资源，默认不删、不搬、不新建第三份。未授权实际归并或在其他版本写入正式入口时，只给出方案并复用确定的正式稿，不把上传授权扩展成这些动作。多稿关系可记入现有逐场清单，无需另建数据库；默认负责人及可指定例外并不保证跨电脑原子去重。

## 自动化
一次调用处理一轮，手动和定时触发使用同一技能。定时任务传入范围、时区、持久状态、已确认责任、目录与交付配置，每轮同样先判断责任及能否复用，一次性接管不延伸到后续触发。按 [定时运行与接续](recurring.md) 补查漏跑日期和全部未完成项，继承已有成果与比较基线。白天运行也覆盖前一日已结束会议；遇到责任、归属或位置不清时保留已有材料，登记待确认，不猜目标、不阻塞其他场次。重叠运行不得同时写入。定时触发需另按用户要求配置；安装不会启动任务、录制会议、申请共享或发送消息。定时发现多稿而配置未明确归并范围时，保留核对依据并报告，不擅自合并、清理副本或切换正式稿。结构检查和隔离演练不能证明实际权限或定时执行已成功，首次运行仍需实际回读验证。

## 仅本地运行
可以提供已有转写与来源响应，在 execution.mode: local_only 下先完成本地归档。禁止平台读取时不联网补材料，不要求云端位置，也不调用文档传输。重复运行比较本地实际材料和成果，保留人工修改。

会议系列不等同于项目：旧标题可归并为同一系列，一场可以关联多个项目，原件仅按实际场次保留一份，纪要按议题注明项目关系。云端交付另按当次明确范围执行。

## 逐场交付
输出按系列或类型、实际日期逐场列出本次要求的会议记录、纪要和适用建议各自的本地整理状态、云端新增／更新／复用／仅本地／待处理状态和直接成果链接，缺失记录也说明本地位置和原因，总报告只作补充。外部规范或配置可要求例会等专项会议单独展示纪要、建议、原始记录入口及复制文案；其他会议仍逐场反馈，专项模板继续维护在原规范。手动核对包含范围内的复用成果；定时运行沿已确认通知规则反馈变化和异常。汇报规则调整不会触发纪要重写或重复上传，传输不包含向同事发消息或发布留言。
