# 日历会议归档

扫描本人飞书日历中自己组织或受邀的已结束会议，获取原始记录，按实际类型整理纪要并上传到指定位置。适用于评审、研讨、项目沟通、例会和面试等会议。

## 安装与环境
安装整个 `skills/calendar-meeting-archive` 目录，保留 `SKILL.md`、`agents/` 和 `references/`。需要已有 lark-cli、相关飞书日历／会议／文档／云盘技能，以及当前用户对来源和目标的权限；这些服务集成不包含在本仓库中。

本技能可独立运行，已安装或本次指定 meeting-minutes 时传入材料与规范，已安装或指定 document-sync 时复用其文档交付流程。指定依赖缺失时报告缺口，不静默换版本。项目已有模板、归档目录和访问规则优先。

## 使用
```text
使用 $calendar-meeting-archive 整理我本周已结束会议的纪要，并上传到这个飞书文件夹：<本次目标文件夹链接>。
```
可指定日期范围、时区和会议筛选条件。未给日期时从用户当地今天的已结束日程开始；未给目标时先整理本地成果并询问位置，不上传到云盘根目录。每个人使用自己的登录账号和目标目录，无需读取邀请人的整个日历。

## 项目目录配置
可传入外部 [归组与要求配置](placement.md)，也可在消息中补充别名归并、归档分组、补充材料与专项规范。已有系列配置继续有效，临时会议可无系列，使用已确认的共享分组。分组不等于项目，未知归属或冲突只暂停受影响场次。配置不携带上传授权，也不启动自动化。

例如：将两个已确认名称归入同一系列；例会使用其专项规范；无固定系列且已确认属于外部协作的零散会议，放入指定共享组；本轮只放本地。Agent 先逐场解析范围、位置与适用规范，再整理。一次性要求留在本轮清单，不自动固化。

## 流程与成果
[来源获取](sources.md) → 完整原文整理 → [上传与增量归档](upload.md)。原文及来源映射长期保存，默认云端只上传本次纪要。面试等特殊类型按项目对应规范整理，受限记录不能统一放入受众过宽的目录。

重跑会核对来源和目标实际内容；同源内容未变则跳过，人工修订保留，冲突列待确认。返回逐场状态、真实成果链接及失败原因。上传任务超时先查已有任务，不重复创建。

## 自动化
一次调用处理一轮，手动和定时触发使用同一技能。定时任务只传入范围、时区、持久状态、已确认的目录与交付配置，按 [定时运行与接续](recurring.md) 补查漏跑日期和全部未完成项，继承已有成果与比较基线。白天运行也覆盖前一日已结束会议；遇到归属或位置不清时先保留本地，不猜目标、不阻塞其他场次。重叠运行不得同时写入。定时触发需另按用户要求配置；安装不会启动任务、录制会议、申请共享或发送消息。结构检查和隔离演练不能证明实际权限或定时执行已成功，首次运行仍需实际回读验证。

## 仅本地运行
可以提供已有转写与来源响应，在 execution.mode: local_only 下先完成本地归档。禁止平台读取时不联网补材料，不要求云端位置，也不调用文档传输。重复运行比较本地实际材料和成果，保留人工修改。

会议系列不等同于项目：旧标题可归并为同一系列，一场可以关联多个项目，原件仅按实际场次保留一份，纪要按议题注明项目关系。云端交付另按当次明确范围执行。

## 逐场交付
输出按系列或类型、实际日期逐场列出本地整理状态、云端新增／更新／复用／仅本地／待处理状态和直接成果链接，总报告只作补充。外部规范或配置可要求例会等专项会议单独展示纪要、建议、原始记录入口及复制文案；其他会议仍逐场反馈，专项模板继续维护在原规范。手动核对包含范围内的复用成果；定时运行沿已确认通知规则反馈变化和异常。汇报规则调整不会触发纪要重写或重复上传，传输不包含向同事发消息或发布留言。
