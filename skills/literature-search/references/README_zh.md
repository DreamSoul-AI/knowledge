## 从检索到正式综述

用户要求 survey／review／文献调研时，应交付有综合论证的正文，论文候选表只是支撑材料。先读本次适用的研究规范、文档呈现规范及课题已有成果。大型课题先形成有实质内容的大纲，明确研究问题、纳入边界、信息截止日、按机制划分的方法主轴、代表文献、比较维度，以及图示和适用数学表达。

围绕核心比较阅读原论文的方法、实验及必要附录。按共同问题合并讨论各论文，展开机制、差异、证据与成本、适用边界和当前判断；解释研究矛盾怎样推动路线变化。判断研究空白前核查近期直接近邻，区分作者当时留下的问题与阅读时点已经取得的进展。

未传入其他结构时，正文覆盖范围与定义、研究脉络、方法家族、必要的其他分析轴、评价比较、综合判断与开放问题、参考资料。对齐大纲与正文，正文完成后回写执行摘要。引用量及细分收录价值在书目或索引中保持显著，正文负责综合论证。

摘要集中呈现结论，正文展开综合论证。重复的检索、核验和入库过程归入已有支撑记录，在影响判断处保留简短范围说明。保留必要的科学配置与具体研究资产细节。

交付前重新对照外部文档规范，按阅读顺序检查开篇、密集段落、图表前后和参考文献，删去重复解释与过程表述，核对标题层级、段落负担和强调方式。内容阅读检查、解析检查和实际目标预览检查分别说明真实范围，解析通过或本地预览不代表已确认其他平台的显示效果。公司的具体排版设置留在外部规范中。

文末另列常规格式的可读参考文献，包含作者、完整题名、渠道／年份、实际来源版本和原文链接或DOI。详细阅读定位与核验说明保留在已有表格或证据记录，不在每条书目里重复，也不将题名全部加粗。要求紧凑书目时，条目连续排列，以明确换行区分，不插空段或横向分隔线。价值排序表是辅助材料，纯URL或Markdown定义不能代替书目。正文按本次要求保持简洁，要求纯数字引用时使用 `[n]`，链接放文末；修正文末书目不自动要求改写正文引用。编号和论文身份保持不变，检查实际渲染。作者可以据已核信息简写，不编造信息。

例如：“从现有 Skill Tuning 调研出发，按传入文献调研规范更新大纲，形成截至指定日期的完整综述。比较机制、实验证据、基线、成本和边界，先给本地 Markdown；不发布、不安装技能、不训练。”交付的是正式正文、需要的大纲及真实证据缺口，测试报告不能替代正文。明确只要求检索清单的小任务仍可采用下文轻量表格；调研不自动授权重排论文库或运行作者实现。

## 从单篇分析到可复用研究资料

原文献条目的目标、方法、创新、数据、指标、结果、代码，以及身份版本、引用影响力和收录价值都要保留。综述大纲负责组织这些信息，不能取代科学内容。

对核心论文，先接入已有 paper-analysis 输出；缺少关键事实或配置时，再做必要的针对性分析。提取实际实验配置及原文定位，不只填方法名称。例如，已有 LoRA+ 分析可提供 GLUE 任务／划分、RoBERTa／GPT-2／Llama 适配配置、Flan-v2 到 MMLU 的数据流、优化器分组与定版代码限制。复用这些证据不算新运行或独立重读。

把内容串到三层：单篇主张与实验条件、跨论文机制与协议比较、具体研究资产归并。数据／模型／算法／指标／基线／代码按对象进入正文或既有索引，列明实际配置、哪些论文怎样使用、真实入口、可复用用途及阻塞缺项。论文实际报告的基线、引用别人的结果与本课题建议对照分别标注；同名数据或模型不代表相同 split、checkpoint 和评价版本。

验收要能回答“下一项实验选什么、为什么、还缺什么”。仅有六类泛论或仓库链接不够；不强制数据库、每篇完整阅读文档或自动运行。正文引用按传入规范呈现，保留与内部稳定身份的映射。

## 传入材料、规范和轻量依据

例如：“从这份已有 LoRA 清单出发，按提供的文献调研规范，检索2021—2024年的相关工作。突出高影响力论文，给出引用量及来源日期，列补充候选和阅读顺序，不改名已有 PDF。”先读传入材料和规范，说明实际采用范围；领域规范及输出规则留在外部，本教程不覆盖本次任务和项目约定。

小任务可只写一段检索说明（日期、来源、关键查询、时间范围及限制），加一张包含论文身份、既有材料关系、收录价值等级及理由、阅读状态和引用量来源的表，不另建日志。论文或权威元数据用于核对身份，DOI 存在不代表支持正文主张。查不到的引用数和未核实版本明确保留。保存、改名、索引及复现按本次范围和项目当前规范执行。

## 简介

进行彻底的文献搜索是学术和专业研究的基本步骤。它有助于了解现有的知识体系，识别空白，并在前人的工作基础上进行研究。本文教程将指导你如何找到相关论文，有效整理它们，并复现关键结果，以加深你对该领域的理解。

## 使用 Google Scholar

### 关键词搜索
- 从与你感兴趣的主题相关的广泛关键词开始。
- 如有必要，使用附加关键词来缩小搜索范围。
- 使用 Ctrl + F 在文章中搜索引用的论文。
- 使用“被引用次数”和“在引用文章中搜索”来查找后续论文。

你可以在[这里](https://scholar.google.com)访问 Google Scholar。

### 用 Browser Use 核对引用量

逐篇查询，核对并保存当前结果后再继续。连续查询默认两次新检索提交至少间隔15秒，用户或服务有更长间隔要求时从其要求；不快速连发或并行查询 Scholar。放慢不能保证不再出现验证码，遇到验证码或访问阻断仍停止并按工具规则交接，不继续重试。

少量论文可通过当前可用的 Browser Use 工具，在 Google Scholar 输入完整标题，核对实际查询、作者和原论文链接，再读取该条结果的“被引用次数”。每次清空上一条查询，结果表保留实际数值、Scholar来源链接和查询日期。不要拿搜索命中总数代替引用量，也不要累加可能重叠的版本簇或仅引文条目；缺链接不等于零。遇到验证码、限流或访问阻断停止受影响查询，按工具规则交给用户处理，不绕过限制。该方式可按用户要求或API不可用时用于交互核对，不捆绑浏览器，也不作为批量抓取接口。

### 筛选论文

交付前逐项核对书目与引用量查询覆盖。正文显示数值、来源和实际观测日期，沿用旧值保留原日期；证据记录分别说明查询失败和因访问限制尚未尝试的条目，不用“本轮／复用”等批次标签替代来源与日期。

- **引用次数:** 引用量是判断影响力的重要指标，尤其对奠基论文和成熟方法，应主动寻找高引用工作，并突出展示引用次数、来源和查询日期。结合相关性、贡献与证据判断，新论文考虑发表年限和领域差异。查不到不填零，不累加重叠的预印本与正式版引用数。
- **出版场所:** 优先选择在知名场所发表的论文。你可以使用[Google Scholar metrics](https://scholar.google.com/citations?view_op=top_venues&hl=en)来确定这些场所的排名。
- **出版时间:** 时间范围随研究问题确定。最新进展重视近期工作，基础与历史路线仍需重视较早的高引用论文。

## 了解出版场所

### 场所类型

#### 会议
- 有特定的截止日期。
- 论文由其他作者进行同行评审。
- 通知接受通常在大约3个月后。
- 被接受的论文在会议上展示，提供了网络交流的机会。

#### 期刊
- 没有特定的截止日期，但通常有特殊主题。期刊可能会定期发布关于特定新兴趋势的论文征集。
- 论文经过编辑初审，然后是同行评审。
- 审核过程可能需要6个月到一年以上，可能涉及多轮修订。
- 在 AI 领域，顶级会议优于顶级期刊，而在其他领域，情况通常相反。

## 论文类型

### 综述论文
- 总结和组织以往的研究。
- 这些是理解一个领域的理想起点。
- **筛选重点:** 先看范围和分类是否适合当前问题，再结合时效、引用影响力与发表场所；不能仅因较新就判定更有用。

### 创新论文
- 提出新的发现，可以分为理论、方法和应用论文。有些论文可能涉及两到三个因素。
- 其中一些论文往往是一个领域的基石，引用次数高，发表在知名场所。
- **筛选重点:** 对成熟贡献，引用量具有重要权重，同时结合相关性、贡献及证据。不为所有研究目的规定同一固定排序。
- 对于最先进的进展，出版日期至关重要。

## 下载论文

1. API 只返回元数据、摘要，或 PDF 链接失效时，用 Browser Use 打开 DOI 或正式论文页面，核对标题、作者和标识。原站没有可访问的全文时，查会议论文集、[arXiv](https://arxiv.org/) 或机构仓储。记录实际下载来源，以及取得的是正式版、接收稿还是预印本。
2. 使用页面正常的 PDF 或下载入口。浏览器无法交付可读取的本地文件时，可把已核实的 PDF 直链交给可用下载工具，并遵守来源的访问限制。遇到访问阻断或仍拿不到文件时，记录来源并标记待下载。
3. 打开下载的文件，确认是真正、完整的 PDF，核对题名、作者和版本。登录页、伪装成 PDF 的 HTML 和未下载完的文件不入库。入库前按 DOI／arXiv ID 和既有文件查重。
4. 本次要求入库时，先从项目约定或现有索引定位已确认的论文库和课题，按现有命名规则保存，按需更新课题索引和入库记录，核对最终路径。位置拿不准时，先放在本次任务的工作目录，标明待入库。

## 论文整理

### 收录价值分级

阅读／筛选表默认按课题综合价值排序，先按收录等级，再综合相关性、知识依赖、引用影响力、已有证据支持的贡献差异与近期进展。成熟基础及同类成熟方法的引用量保留重要权重；能改变新颖性或可行性判断的最新直接近邻，即使低引也可前置。新近发表不自动代表新颖。用排序说明或现有理由列解释主要选择，不增加数值打分；重排行不改变引用编号或论文身份。需要展现时间脉络时另用日期顺序。

优先使用传入分级规范，未指定时采用 **A+ 决定性核心、A 核心主干、A- 紧邻支撑、B+ 重要对照、B 重要参考、B- 分支参考、C 背景补充**。A+只保留直接决定核心新颖性、方法选择或验收的少数文献；A为主线方法与必要基础；A-支撑关键环节或强替代方案。B+为具体重要对照或评价协议，B提供按分支使用的证据／资产，B-涉及可选子问题，C提供背景与外围信息。相关、最新或基础文献的标签不自动使其进入A；高档拥挤时重新判断实际作用，不只是加上加号。成熟工作的引用影响力仍保留重要权重，不做数值打分、引用分位映射或等级篇数配额。

**既有材料关系、收录价值等级、等级依据、实际阅读状态、引用量及来源日期分别记录。** 既有种子不自动为 A，新候选也不自动降级。只读摘要得出的等级属于初筛判断，深入阅读后可调整。材料不足以判断时标待定并说明原因，不直接归 C。

例如，低秩适配组合课题中，LoRA可作为基础列A，直接相关组合研究视主线作用列A或A-，只充当优化控制的细节列B或B-。若课题转向优化设计，应重新评估。实际引用数及来源日期另记，不编造示例数值，也不把初筛写成已精读。

推荐紧凑列为：**论文／引用量（来源、日期）／既有材料关系／收录价值等级／等级依据／阅读状态**。沿用当前 Markdown 清单即可，下方电子表格建议为可选形式，不额外要求建表。

- **创建电子表格:** 这是一个系统化地组织和管理文献收藏的工具。为了提高可读性并突出关键概念，建议在电子表格中**加粗重要关键词**。这些关键词可以包括关键概念、方法、数据集、评估指标或任何创新贡献。加粗关键词有助于一目了然地突出关键信息，便于在重读文献时快速查找具体细节。
  
- **建议列（默认按综合价值排序，时间轴可按日期）：**

  - **标题:** 论文的标题，通常反映了核心研究问题或贡献。

  - **引用量:** 显著展示引用次数、来源链接和查询日期。查询失败明确标待核，不填零，不累加同一工作多个版本的重叠引用数。
  
  - **作者与可选机构:** 保留作者、标题和 DOI/arXiv ID 以核对论文身份。机构可作背景，不替代作者，也不作为质量排名。
  
  - **出版地点:** 论文发表的会议或期刊。这可以指示论文的可信度和影响力，因为有些会议或期刊更具权威性。
  
  - **日期:** 论文的发表日期。按日期排序有助于追踪研究主题的时间发展脉络。
  
  - **目标:** 对研究主要目标的概述，详细说明论文解决的问题。
  
  - **方法:** 对论文中使用的方法的简要描述，包括任何算法、模型或理论方法。通常可以从摘要中提取此信息。

  - **创新点:** 总结论文相较于之前工作的独特或创新之处。这可能是新方法、新应用或现有方法的重大改进。
  
  - **数据集:** 论文中使用的数据集，对于建立标准基准以与其他方法进行比较非常重要。

  - **评估指标:** 用来评估所提出方法性能的评估指标，如准确率和F1分数。

  - **结果:** 论文的主要贡献，通常突出所提出方法根据所选指标的表现。可以从摘要、引言和结论部分提取这些贡献。
  
  - **链接:** 访问论文的在线URL，无论是通过出版商网站、arXiv或其他资源库。
  
  - **代码:** 链接到与论文相关的任何代码库（如GitHub）。访问代码对于复现结果或在此基础上进行进一步研究非常有帮助。

## 复现结果

以下为另行要求复现时的后续建议，不是文献检索后自动执行的步骤。

- 选择一篇基础论文来复现其结果，最好是有可用实现的。
- 尝试找到包含旧基准论文的基准代码库。
- 使用此过程来加深你对该领域的理解，并集思广益，产生新想法。
