# 目录比较和更新

先固定来源、范围和真实安装位置。新装技能可用skill-installer；升级已有安装时，保留当前版及旧采用来源，比较完整包。

## 固定版本

Git来源先解析完整commit，再从该commit导出需要的整个技能/工具目录。ZIP或其他发行包按原说明取得并核对版本/哈希。仓库根、下载缓存和实际安装目录不是同一对象，不能用未提交源码冒充正式版。

旧版从已有采用记录、固定commit或保留包定位。来源不明的能力先报告缺口，不猜目录对应关系；已知的其他项继续。

## 便携脚本

[update_package.py](../scripts/update_package.py)只接受已经准备好的目录，不联网、不发现全机安装、不改采用记录或安装环境。

```text
python scripts/update_package.py --current <实际目录> --base <旧来源包> --incoming <目标固定包> --work-dir <本轮临时目录>
python scripts/update_package.py --current <实际目录> --base <旧来源包> --incoming <目标固定包> --work-dir <本轮临时目录> --apply
```

从本技能目录运行，或使用脚本的实际完整路径。省略apply是检查，目标不写入；work-dir用于保留备份，放在包目录之外。没有旧版可省略base，差异文件需要进一步判断，脚本不会直接覆盖。

状态包括updated、unchanged、changes、conflict、failed。冲突时整份选定包保持原状，其他包可继续。原有额外文件保留；非重叠UTF-8/UTF-16文本借助Git三方合并，保留目标编码及换行。重叠、二进制或缺少Git时列冲突，交给Agent按本轮范围处理。

文件和目录互换会列为冲突，由Agent结合引用和本地内容处理迁移，不在通用脚本里隐式改目录类型。

包内符号链接/Junction等重解析点会被拒绝，先核实其实际用途和更新范围，不跟随到共享数据。根目录可按已确认实际入口解析。脚本不声称提供跨进程事务或运行中服务热更新。

应用前复查输入，写后回读；普通失败恢复已写文件，若期间出现他人改稿则保留并报告recovery_conflicts。备份和输出含实际本机位置，留在本地，不作为共享规范或发布包内容。

同版本重跑使用上轮已采用的目标包作为base。保留本地定制的安装与上游字节不同是正常情况，按采用版本和保留差异判断，不为追求字节相等覆盖定制。
