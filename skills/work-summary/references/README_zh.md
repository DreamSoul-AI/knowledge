# 工作总结 work-summary

盘点一个或多个对话中的工作，归并成果、未收尾项、待核问题和下一步。可单独用于收工、阶段回顾或交接，也可作为工作留言的输入。

## 使用

安装时保留整个 `work-summary` 目录及其引用文件。可以这样要求：

```text
用 $work-summary 汇总这段工作的成果和未完成项。跨对话时间范围先列出来让我确认，先不发布。
```

每轮全局盘点先确认具体起止时间、时区和来源，同轮继续校准不重复问。可传入指定对话、材料、补充背景和适用规范。总结保留事实全貌，不因某项暂不适合分享而漏掉。

独立来源较多时可按[来源收集](collecting.md)分工并行，主代理核对覆盖、纠正及证据后按事项去重。一次扫描所得总结供下游复用，不按每块留言板重复扫描；是否实际提速以整体耗时为据。

## 保存位置

在 `工作总结/作者姓名/` 下直接保存 `工作总结 日期.md`，不再套日期目录；飞书文档名对应为“工作总结 日期”。作者真名从当前 `USER.md` 或本次指定信息读取，不采用 GitHub username。本地根与飞书根分别从当前配置定位，尚无云端入口时先交本地成果。具体定位、同轮接续和相对引用见[归档参考](archiving.md)。

```text
用 $work-summary 汇总指定材料，按 USER.md 中的作者真名和工作总结本地入口保存。沿用本轮归档日期，把覆盖依据和留言候选与总结关联，先不上传。
```

文件名日期采用本次指定的工作归属日期，未指定时沿用适用的本人日期规则，不能直接取生成日。同轮修改沿用原稿，分别记录工作归属日期、实际覆盖范围和最近更新时间，跨日不另建一份，也不把后来取得的结果回填为原截止点已完成。既有材料不因采用新约定自动移动；需要迁移或同步时，核对现有对象和引用。

## 与工作留言衔接

总结交付前对照已取得来源检查成果是否呈现；项目未结束，也保留已经完成的独立成果。用户指出某项遗漏后检查同类问题，按实际事项组织，不机械按举例顺序排列。

```text
先用 $work-summary 整理完整工作情况，再用 $work-message 根据这份总结与我校准分享事项，写齐选定留言板的正文，先不发送。
```

工作留言可以接收总结正文、文件或可读链接，复用范围和证据，不重复全部盘点。总结本身不授权选择发布对象、上传原文或修改日志和总表。安装工作总结不要求同时安装工作留言；需要该下游流程时再准备对应技能。

完整总结按读者的工作结构归并，多部门材料可用“部门 → 项目”，各项目内说明成果、未完和待核；不在总结阶段按下游分享对象删事实。留言反馈若改变成果或状态，回查并修正总结中对应事实；仅改变称呼、标签或分享取舍时由工作留言处理，不反向改写工作事实。

另有日志更新要求时，先定位对应使用者的实际日志。本次明确指定优先，否则沿该使用者的USER入口和已有索引查找，核对作者后读近期结构、状态与习惯，只补授权差异并保留人工内容。普通总结不强制读日志，也不默认使用Agent当前用户的日志；涉及总表时接project-progress-sync。
