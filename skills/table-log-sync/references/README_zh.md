# 总表与日志双向整理

沿用你现有的日志分类和层级，对照项目总表，先看具体改动，再决定是否写入。支持单向整理，也支持两边一起比较。

## 安装与使用

安装整个 `table-log-sync` 目录，保留 `agents/` 和 `references/`。在 Codex 中可以说：

```text
用 $table-log-sync 对照这份总表和日志，先拿几条记录试一下，按原分类和层级列出补在哪里、原来是什么、建议改成什么，先不写入。
```

提供总表、日志的链接或本地路径，并说明人员、时间或记录范围。对话或项目入口中已经有的资料，技能会先主动查找。只取得旧快照时会注明日期，不将它当成最新数据。

## 预览的样子

以下是合成示例，不代表真实项目数据：

- **总表到日志：** 日志路径为“阶段安排 → 管理 → 办公 → 工具教程”。总表已有“包含技能安装指南”的说明，预览将原条目“工具教程”改为“工具教程（含技能安装指南）”，原位置和未勾选状态保留。
- **日志到总表：** 原始日志记录了设备清单核对工作，且已唯一匹配任务“办公设备维护”。预览列出该任务的记录 ID、任务描述原文、建议追加的具体范围及原始日志链接；未获得实际完成依据时保留原进度。
- **待核：** 总表的预计日期已过，但实际完成情况未确认，只在对应日志条目建议加核对提示，不改成已完成，也不猜新的排期。

预览中的每项有编号、准确位置、原值、建议完整值、依据链接和实际改动范围。想法、当前待办、季度或其他阶段安排、远期、对齐和每日历史按你原来的用法保留。同一事项在多天出现不会被简单删重；季度任务也不会自动排进今天。

## 确认后写入

看过预览后，可以明确说：

```text
按刚才预览执行第1、3项，其余先不改。
```

只会写入确认的项目和字段。同意执行预览只是写入授权，不替代对完成情况、日期等业务事实的确认。写前若发现相关内容被别人修改，会保留新内容，重新展示受影响项并等你确认。已成功的项目不会重复追加；部分成功或结果不明时会分别说明，并先核对实际状态。

总表生成的日志草稿不会被反向当成新进展证据。日志勾选不直接换算成总表完成度；未知进度、实际完成日期和父项进度不自动补写。

制作、发布或安装技能不等于授权修改总表或日志。这个技能不自带定时任务，也不发布留言；一句话留言与沟通原文归档分别处理。
