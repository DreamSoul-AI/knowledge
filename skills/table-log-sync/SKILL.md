# 总表与日志双向整理

把两边需要补充或核对的内容整理成可审阅的差异，默认只读。制作、安装或发布这个 skill，不构成修改业务数据的授权。

## 读取现状和建立对应

- 从当前对话和项目入口找到总表、日志及适用规范；已知目标和链接主动沿用，不要求用户重复提供。身份、负责人或目标无法唯一确定时再核对。
- 读取目标的最新内容、日志分区与层级、总表字段及相关记录。保存读取时间、版本、记录 ID 和可取得的区块 ID；按用户要求先取少量记录，注明范围和分页情况。旧导出和历史报告只作带日期的依据，不能称为当前状态。
- 飞书任务遵循项目工具约定，使用 lark-cli，并配合可用的 lark-base、lark-doc 技能。先读相关命令说明，代表用户显式使用 --as user。认证失败先区分执行环境、登录和资源权限，不静默换成机器人或浏览器。
- 根据事项内容、负责人、周期、项目和上下级关系匹配，不能只凭同名或相似技术词关联。候选不唯一、读取失败或依据矛盾的项放入“待核”，不混入确定修改。
- 主动带上对应文档、表、任务或成果的已知真实链接；缺少入口时先只读查找并核对。保留完整飞书分享 URL 和定位锚点，不拼接地址。没有记录级链接时，用已核实的文档或表入口加准确路径、记录 ID 定位，不为补链接创建资源或改权限。

## 沿用原分类和层级

- 按日志现场的分类、缩进和日期组织内容。区分想法、当前待办、阶段或季度安排、远期、对齐与每日历史；这些是常见区域，不是要求新建的固定模板。
- 同一事项跨区域、跨日期出现不等于重复任务。保留原位置和历史痕迹，优先修改对应叶子条目；不因同步重建目录、重排层级、把季度任务自动放进今天，或把想法自动升级为正式任务。
- **总表到日志：** 补充总表已明确的任务范围、计划或核对提示。给出应补的现有路径及具体文字；总表状态不生成“今天已经做过”的事实，已完成任务不自动重新加入待办。预计日期已过，只能据实提示核对，不能编造新日期或判定实际未完成。
- **日志到总表：** 从独立原始日志和本人明确确认中识别实际变化，优先补到已有任务的相应字段。区分计划、当日处理、阶段结果和完成；日间勾选、重复提及、代码提交或文件日期不足以单独推定完成度、完成日期或人员入职等业务结果。未知保持未知，最新人工值保留，父项手填进度不随子项自动重算。
- 标明依据来自原始日志、总表摘录还是生成草稿。由总表生成的日志、其副本或回读结果，不能再作为独立进展证据反向回填；需要新的真实记录或明确确认。

## 先给具体修改预览

预览使用简短自然的文字，逐项编号并注明方向。每项包含：

| 内容 | 要交代清楚的事项 |
| --- | --- |
| 目标 | 日志完整分类路径及已有区块位置，或总表表名、记录名、ID 与字段 |
| 原值 | 当前条目或字段原文；新增时明确原来没有，并给已有插入锚点 |
| 建议值 | 可直接核对的完整新文字；追加时同时说明保留的原文与追加内容 |
| 依据 | 对应原始内容、日期或版本及可点击入口；区分事实与归类建议 |
| 改动范围 | 哪个字段或区块会改；保留原勾选、样式、进度、日期和关系中的哪些值 |

只列本次实际差异；已经一致的写“无需改动”，歧义与无法读取的另列待核。不把整篇日志塞进任务描述，不为制造差异而改写。发布预览后等待用户确认；没有本轮具体预览的确认不写入。用户明确说“按这份预览执行”且范围唯一时可直接沿用，不重复询问；只确认其中几项就只执行这些项。对写入操作的同意不替代任务完成情况、日期等业务事实的确认。含糊的同意不扩展为其他字段、合并、删除或全量同步授权。

## 确认后局部写入并回读

1. 写前重读已确认项的目标字段、定位锚点及影响判断的来源。相关原值、位置或依据变化时保留最新内容，重新展示该项差异并取得确认；其余未受影响且仍在授权范围的项可继续。无关字段的新修改也要保留，不整行或整篇覆盖。
2. 仅提交确认的字段或区块；新增前按负责人、周期、归属和相近名称再查重。保留未涉及的文字、链接、样式与关联。飞书正文按适用规范使用原生文档引用；影响评论锚点的修改按当地恢复规范处理。
3. 有条件更新或版本保护时使用；没有时采用小批局部写入并及时回读，不能承诺跨总表和文档的原子事务。
4. 每项回读目标值及必要关联，分别记录已写入且核验、结果待核、失败和未执行。超时或结果不明先查实际状态，不盲重试整批；已经成功的项不重复追加。重试仅覆盖仍未生效、依据未变且仍在确认范围的项，不自动回滚他人后续修改。
5. 返回实际改动及对应链接，说明未执行或待核项目。不要把保存预览、接口受理或部分成功写成全部同步完成。
