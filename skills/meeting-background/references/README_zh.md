# 例会背景 meeting-background

从个人日志整理例会中的本人背景，交付“总结、上周、本周”，可先看完整稿，再按本次授权更新已有文档。它处理会前准备，不代替会后会议总结，也不负责清理日志或更新总表。

# 一、配置入口

从当前 `USER.md` 或本次传入信息取得以下内容。可以沿用自然语言、已有表格和项目配置，不要求新建固定 JSON。

| **内容** | **用途** |
| --- | --- |
| 作者真名、章节别名 | 定位本人章节 |
| 个人日志入口 | 读取每日记录和最新 TODO |
| 时区、指定周次 | 确定回顾与计划范围 |
| 会议系列或当期对象 | 定位正确文档 |
| 项目命名、文档规范 | 保留本人展示习惯 |

**参数示例。** “作者用 USER.md 中的本人。整理指定周一至周日的进展，本周从下周一开始。当期会议背景从系列入口核对，先只给稿。”明确要求更新时，还要核实写入的具体对象和本人范围。

历史来源中的月份标题、会期和项目名称仅解释原流程，不是新调用的固定默认。跨月要读全两侧记录，有多个候选时只问影响对象选择的缺口。

# 二、怎样调用

**准备稿。** “用 $meeting-background 整理这次例会背景，回顾到本周日，依据个人日志的月度记录和最新 TODO，先给我完整三段，别上传。”

**更新。** “把已确认背景更新到这次会议文档的本人章节，其他章节别动，改完回读并给我链接。”身份、日期或授权已经明确时直接沿用本轮确认。

**接续。** “刚才这个周次又补了两项进展，接着同一份背景更新。”读取当前版本，只更新差异。新的一周必须重新定位当期对象，不能沿用上周 URL。

# 三、阅读结果

本人姓名用一级标题，总结、上周（日期范围）、本周（安排起点）用二级标题，按此顺序呈现。总结每类一段，加粗分类名，段内用 `1)`、`2)` 区分事项，标签用普通文字，不用斜体或另起编号清单。研究课题归研发，默认不写外部协作，本次明确要求时再纳入。上周、本周保留具体事项，使用紧凑嵌套圆点列表，父子项及相邻项间不插空行。必要分段不转换成飞书空白文本块。已勾选事项仍可能是持续推进，不能由此声称整个项目完成。计划中的延续工作不因一次日勾选自动消失。

本周计划采用会议准备时点有效的材料，回放旧周一不能倒用后来 TODO。来源核对与待核缺口另行回报，不夹入本人正文。

仅出稿时返回完整可复制 Markdown。已授权更新后返回实际目标、更新范围和回读结果。访问失败或缺少当期链接时，已有草稿仍然交付，并说明哪一步尚未完成。

个人版本沿本人已登记的长期分支维护。完整安装时应包含 SKILL、agents 和 references，具体分支与安装位置按当前采用记录选择。推送个人技能不等于已经安装或更新真实会议背景，实际会期使用仍需按当期材料核对，不自动创建定时任务。
