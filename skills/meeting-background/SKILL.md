# 例会背景 meeting-background

为指定周次准备本人会议背景，让参会者看到这一周实际推进了什么、整体情况如何、接下来做什么。复用当前个人日志、项目命名和会议背景样式，交付可直接阅读或按授权写入的“总结、上周、本周”三段。

这是个人工作流程。本人身份、日志、会议系列和展示偏好从当前使用者的 `USER.md` 或本次指定配置取得，不能把历史案例中的姓名、链接和日期当作本轮参数。读取适用项目规则及使用者采用的文档规范，先写本地 Markdown 时也采用该规范。

# 一、确定本轮对象

**周次。** 明确回顾起止日、会议日期、本周安排的起始日和时区。用户说“到某日”“继续这周”时，结合本次请求及当期日程确定实际范围，不能直接沿用上一轮会议链接。跨月回顾要读取涉及的两个月份，不能因月标题切换漏掉月末。

**本人。** 从配置读取作者真名，核对日志所属人、会议背景中的对应姓名章节及实际登录身份。称呼、章节别名沿本人已确认配置，不按机器用户名或其他成员相似姓名猜配。

**材料。** 定位个人日志中的月度逐日记录、最新任务清单，以及本次明确指定的季度目标或额外计划。已有可核实来源继续用，不逐周要求用户重新提供整套配置。季度目标只在本次需要时接入，不默认扩展到所有项目。

**当期目标。** 用户指定链接时读取该对象的标题、日期和本人章节。没有直接链接时，可从配置的会议系列入口定位，核对当期日期后使用。上一期只能参考格式，不作为默认写入对象。目标日期不符或出现两个无法区分的候选时，先完成草稿并集中说明缺口，不写错文档后再追认。

开始整理时用一小段交代上述范围、材料覆盖和本次是仅出稿还是更新。配置读取不等于取得写入授权，用户已明确授权更新时也不重复索要同一授权。

# 二、从日志形成三段正文

## （一）总结

在正文最前归纳这一周的重点、变化和阶段成果，说明几类工作如何关联。用短段落讲清整体推进情况，避免重新逐项复述清单，也不能从“有很多勾选”推断所有工作顺利完成。

有事实支持的阻碍、未完成状态可以说明。来源缺失或关键状态不确定时，将需要校准的点单列给用户，不把它写成既定结论。总结的语气和长短沿用本人已确认样式，保留具体成果，不随意变成只有几个泛泛标签的简版。

本人姓名作为一级标题，“总结”“上周（回顾日期范围）”“本周（安排起点）”作为二级标题。总结按实际部门或工作分类，每类一段，以加粗分类名开头，标点放在加粗外。段内用 `1)`、`2)` 区分事项，标签用普通文字，不用斜体或另起编号清单。保持必要分段，转换到飞书时不额外生成空白文本块。

研究课题归研发，不与外部协作混成一类。本人会议背景默认不列外部协作，包括总结、上周和本周；本次明确要求包含时再纳入。具体分类沿当前工作结构，不强制凑齐所有部门。

## （二）上周

阅读回顾范围内的每日记录，结合原有层级判断叶子事项所属项目。以用户已确认的月度记录为正式来源，顶部最新 TODO 用于安排后续，不能拿它代替整周实际发生的工作。父子项及相邻列表项之间不插空行，不逐条机械添加“推进、开展、处理、继续”等空泛动作。保留有依据且影响理解的状态。

- 逐日归并同一事项的连续推进，保留不同成果和有意义的变化，不把重复日清单机械堆成周报
- 勾选代表当天做过或推进过。只有来源明确支持阶段完成、上线、发布等状态时才采用对应表述，不能把一个勾选提升为整个项目完成
- 无勾选但有明确完成叙述或成果材料时按实际证据纳入。只有计划、没有进展依据的事项留在本周安排或待核说明
- 延续日志的合理工作分类和用户校准过的项目名称，每个叶子事项单独列点。可以归并重复，不合并到失去具体对象
- 受限材料只使用当前允许的工作状态，不为周背景展开读取或转贴受限正文

## （三）本周

以会议准备时点有效的 TODO、本次明确计划和必要的季度目标编排本周工作，沿已确认的层级和命名去重。最新清单日期可能在会议前一天，必须交代引用的是哪版清单，不能为了凑会议日假装存在当天记录。

已在某一天勾选的连续性工作仍可列入周计划，例如持续招聘、重构或研究。是否继续看计划依据和工作性质，不因一次勾选自动删掉。不自行给所有任务新增期限、负责人或完成比例。回放旧周一时使用当时有效计划或已确认当期本人稿，不把后来更新的 TODO 倒填到当时。来源核对、试跑说明和待核缺口在正文外单独回报，不追加历史暂停清单。

**正文示意。** 下列分类仅示意，实际沿本人的工作结构。

```markdown
# 作者真名

## 总结

**研发**：1) 项目甲：完成配置兼容验证，性能定位仍在进行。 2) 研究课题：通过小规模实验观察到差异，下一步核对原因。

## 上周（回顾起止日）

- 研发
  - 项目甲
    - 完成配置兼容验证
    - 性能问题定位

## 本周（安排起始日）

- 研发
  - 项目甲
    - 性能问题定位
    - 补充已确认的边界用例
```

# 三、更新本人章节

**仅出稿。** 交付完整三段和必要的待校准点，不改日志、会议背景或其他人的内容。即使当期背景暂缺，只要日志范围清楚也可以先出可复制稿。

**已授权更新。** 先重新读取当期目标及本人整节，记录对象、修订和写前正文。确定从本人标题到下一个同级或更高层级标题之间的完整范围，包含末尾列表、旧总结和旧本周安排。本人章节不存在、重名或边界无法唯一定位时，不替换整份共享文档来绕过问题。

将新三段与整节现状比较。内容已一致则报告无需变化，不重复追加。保留本人有效的手写补充、链接和资源，不能用旧快照抹掉他人刚做的修订。新稿与手写内容冲突时先判断来源和本次要求，确实无法确定的部分再校准。

写入只覆盖本次授权的本人范围，保留其他成员、公共章节及附件。飞书操作使用当前可用的 `lark-doc` 和 `lark-cli`，先读该技能的实际命令，不复用历史区块 ID。身份显式用 `--as user`。认证、权限和路径问题分别报告，不能在无法核实目标时改写别的同名对象。

**重跑和跨周。** 同周接续先比对最新目标，更新发生变化的内容而不是再追加一份三段。新周重新核对日期和来源，由本轮证据形成整节，不复制旧总结或保留已经失效的本周列表。上周独有事项若继续出现，应有本轮进展或计划依据，不能仅因旧稿存在而延续。

# 四、回读与回报

写后读取本人整节和相邻边界，逐项对照草稿，而不只检查新日期出现了没有。

- 本轮回顾日期、会议日期和计划起始日对应正确目标
- 本人范围只有一份上周、一份总结和一份本周，旧段落及末尾列表没有残留
- 新成果和有效手写内容没有遗漏，其他人的章节、公共内容及原有资源未变
- 同周重复运行不重复写入，读到的实际正文与交付稿一致

写入结果未知时先回读，不盲目重试。如果发现错改上一期，保留两边最新正文及写前基线，仅恢复本轮误改范围并核对并行修订，再按确认的当期对象处理。缺少可靠恢复依据时说明具体差异，不整文回滚。

在对话回报本轮三段正文或本次实际更新摘要、正确目标入口、真实写入状态与仍待校准事项。出稿、更新成功和回读通过分开判断，不以“已整理”代替“已写入”。
