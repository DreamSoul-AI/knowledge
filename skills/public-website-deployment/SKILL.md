# 公开网站部署 Public Website Deployment

发布已有完整静态站点，支持首次发布、原网址更新和双端验收。新配置默认 `china → ESA`，海外使用 Cloudflare；网站上传默认 CLI。本次明确要求优先，已有配置按迁移规则保留。

执行顺序：读取配置 → 核对身份与项目 → 准备完整产物 → 发布并回读 → 验证原网址。仅绑定已有项目时直接进入域名流程，无需重新构建或上传。安装和常用请求见[中文指南](references/README_zh.md)或 [English guide](references/README.md)。

## 选择目标并读取配置

按[配置规则](references/configuration.md)读取实际加载的 SKILL.md 同级 CONFIG.md，以这一份文件提供默认值。账号、项目和环境整体核对，不从其他配置副本拼接。

| 本次明确目标 | 使用配置字段 | 按需读取的执行流程 |
| --- | --- | --- |
| 阿里云、ESA、ESA Pages | esa.* | [ESA](references/esa.md) |
| 国内、中国大陆 | china.provider 所选平台 | 对应平台参考 |
| 海外、国外、Cloudflare | cloudflare.* | [Cloudflare](references/cloudflare.md) |
| 国内和海外、两边都发布 | china.provider 所选平台与 cloudflare.* | 对应两份流程 |

本次明确的平台覆盖 china.provider，明确的地区覆盖 default.target；值为 ask 时补问缺少的目标。china 是平台路线，实际加速区域另按站点核对。明确请求 ESA 与海外时使用 ESA 和 Cloudflare。旧配置按[兼容规则](references/configuration.md#迁移与保留)处理。

ESA 默认按 [ESA CLI](references/esa-cli.md)执行，已有 console／github 选择继续保留；Cloudflare 默认按 [Wrangler](references/cloudflare-cli.md)执行。本次指定控制台时采用对应流程。CLI 缺工具、认证或权限时补齐该入口，失败先查原因，不静默切换平台或发布方式。

发布前说明配置来源、操作、平台、项目和环境。新建为各端确定未占用名称；更新必须找到原项目，查不到时先解决目标问题。用户指定其他项目时完整回读其信息；修改默认配置须有明确要求。仅检查、预览刷新和恢复按各自范围执行。

## ESA Demo 组织方式

选择 ESA 后，按本次要求和项目用途组织：

- **独立 Demo**：使用独立 Pages 项目和专用子域名，方便独立更新与恢复；更新复用原项目、域名和环境。
- **小实验合集**：共用项目域名，各实验使用稳定子路径，如 `/calculator/`。先定位合集；新合集单独确定项目和域名，现有独立 Demo 保留原用途。

核对项目、域名和目录冲突；同名路径须确认是否属于本次更新。合集保留入口和其他实验，新增入口链接，检查资源相对路径、导航、深层刷新及 SPA 回退规则。路由冲突先解决再发布。站点、DNS、HTTPS 与共享额度见 [ESA 参考](references/esa.md)。

## 首次绑定自定义子域名

支持已有项目首次绑定，以及新项目发布成功后绑定新子域名。目标由用户指定：ESA 使用本次明确值或 `esa.domain.name`，Cloudflare 由本次请求提供；示例域名不作为默认值。项目、环境与域名整体核对，绑定公开生产入口前先确认生产版本。

先检查域名归属、权威 DNS、已有记录与绑定、配额和证书权限，再按 [ESA 域名流程](references/esa.md#自定义域名与-https)或 [Cloudflare 域名流程](references/cloudflare.md#首次绑定自定义子域名)执行。相同绑定已存在时复用并验收；目标已被其他项目或业务使用时停止，不覆盖。域名更换、项目间改绑、旧域名跳转及停用不在本流程内。

网站上传仍默认 CLI；域名、DNS、证书分别使用对应参考中已核验的入口和权限。完成后检查解析、证书、HTTPS、HTTP 跳转及完整页面，再交付固定网址。已有入口保持原用途；部分完成时记录成功步骤与阻塞原因，不自动删除项目、记录或证书。

## ESA 迁移与续订

- 明确要求将旧入口迁往新域名或路径时，读取[旧域名迁移](references/esa-domain-migration.md)：先验证新入口，再启用逐页跳转，保留查询参数及旧 DNS、证书和恢复基线。
- 检查服务期限或处理自动续订时，读取[订阅与续订检查](references/esa-renewal.md)：分别核对计算订阅与站点套餐，设置按已授权范围及费用条件执行，配置成功与实际续订成功分别记录。

这两项按本次请求开展，普通内容上传不默认更改域名规则或续订设置。

## 共用产物流程

需要把多个独立来源合并到同一站点的不同路径，或更新其中一个专题时，先读[多来源静态站点组装](references/multi-source-sites.md)。按项目选定的路径记录来源版本、公开文件清单与摘要，适配链接后生成完整产物；源仓库可以继续独立维护。

1. **整理目录**：单 HTML 带齐依赖；源码按项目现有命令构建；ZIP 检查根入口、条目和体积，拒绝绝对路径、向上穿越及范围外链接后解压。保留中文和空格路径，只上传公开产物目录。
2. **核对范围**：排除 CONFIG.md、USER.md、Git 历史、环境文件、账号缓存、凭据和部署记录。发现 SSR、Functions、`_worker.js`、数据库或服务端 API 需求时，另行确认运行时与发布范围。
3. **本地检查**：验证样式、图片、脚本、JSON、中文、主要交互、子页刷新及外部资源。保留必要的 404、重定向和标头规则，分别核对两端支持情况。
4. **保留基线**：更新前保存当前线上对应的完整产物、清单与摘要。合集在该基线上合入新实验，保留原入口、其他目录和共享资源；删除须有明确要求。缺少完整基线时先补齐，禁止用单个实验覆盖整个项目。新包另存，双端复用同一完整产物，平台差异单独记录。

## 单端与双端执行

先核对登录身份、资源账户、项目类型、区域／分支和权限，通过后执行已授权操作。同一项目串行发布。复用官方 CLI 或控制台认证；登录过期由用户完成授权，禁止从任意缓存提取凭据。账号、区域、平台、匿名发布与付费方案的变更须有明确要求。

双端分别认证、上传、回读部署并验收，记录各自项目和部署标识。一端受阻时继续另一端已授权且独立的工作，分别报告成功、失败或待验证，保留已成功的部署。上传状态未知时先查远端记录，再决定是否重试。

仅检查不上传；限时预览刷新只生成并验证新链接；恢复使用用户指定的项目和历史版本，不删除项目。ESA 自定义域名与 Cloudflare 普通生产网址沿用固定入口。

## 共同验收与交付

- **访客访问**：用无平台登录信息的会话检查原生产入口、实际版本、HTTPS、资源、交互、中文路径、子页直接访问与刷新、预期 404；同时核对状态码和内容。
- **同址更新**：确认原网址显示新版本。合集逐个检查新旧实验及入口；删除路径核对实际响应。分别记录普通网址、诊断请求和历史部署的缓存表现，内容撤回以实测为准。
- **链接交付**：提供访问网址、版本、项目／环境、部署入口、访问条件和实测网络。ESA 长期交付使用已验证的自定义域名；Cloudflare 交付原生产网址。使用 ESA 短时测试链接时，按 [ESA 交付规则](references/esa.md#交付)附完整参数及生成／到期时间。
- **证据与费用**：记录产物摘要、部署标识、结果和未覆盖项，分别说明部署成功、公开访问和地区验收。临时参数、Cookie、Token、真实配置留在本次私人交付范围，排除于网站、Skill 和长期共享记录。配额与费用按实际套餐核对；域名、DNS、备案、付费服务、后端和无人值守凭据按任务范围处理。
