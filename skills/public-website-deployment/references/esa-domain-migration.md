# ESA 旧域名迁移

用于用户明确要求把旧静态网站入口迁往新域名或新路径，并继续支持原链接。先确认旧主机、目标项目与环境、目标 URL、路径对应关系及永久或临时迁移意图。仅检查时不写规则；已有明确迁移授权时按该范围执行。

本流程基于 ESA 请求重定向；Cloudflare 迁移需另核对其规则入口与能力。内容合并先按[多来源静态站点组装](multi-source-sites.md)准备，新子域名首次绑定见 [ESA 域名流程](esa.md#自定义域名与-https)。根域名接入或项目间改绑需单独核对 DNS 冲突与平台要求，不照抄子域名绑定步骤。

## 迁移前的基线

读取旧入口的项目、环境、生产版本、绑定、权威 DNS、证书及重定向规则；保存本次可能修改的配置和完整产物。核对目标入口的实际归属与内容，避免覆盖同名业务。已有规则可满足目标时复用；需要修改时保留原规则标识、状态、优先级和恢复值。

先让新入口的 HTTPS、内容、资源及深层页面通过检查，再启用旧址跳转。新入口尚未就绪时，可保存本次规则草稿或关闭状态的规则，不能先把访客导向不可用页面。规则生效顺序须结合已有规则检查。[ESA 请求重定向](https://help.aliyun.com/zh/edge-security-acceleration/esa/user-guide/request-redirects)

旧域名的解析与有效证书需要保留：访问旧 HTTPS 地址时，TLS 握手发生在收到 HTTP 跳转之前。旧项目和产物按恢复方案保留，迁移不自动授权删除旧资源。

## 逐页映射

整站迁入一个新前缀时，可采用以下示例，域名和路径均替换为本次目标：

| 配置 | 示例与检查 |
| --- | --- |
| 匹配条件 | `(http.host eq "old.example.com")`，精确匹配旧主机 |
| 目标类型 | 动态 |
| 目标表达式 | `concat("https://www.example.com/topics/alpha", http.request.uri.path)` |
| 查询字符串 | 开启保留查询字符串，API 对应 `ReserveQueryString=on` |
| 状态码 | 已确认永久迁移的静态页面使用 301；临时迁移使用相应临时状态码 |

上述前缀不带尾斜杠，由原路径的起始 `/` 衔接；原首页 `/` 对应新前缀的目录首页。页面结构发生变化时，按实际对应关系映射，不把所有旧子页跳到首页。检查匹配范围、尾斜杠、编码路径和跳转链，避免重复前缀或循环。

ESA 的“保留查询字符串”默认关闭；开启后，原请求带查询参数时会覆盖目标表达式中的查询参数。因此上述目标不附加额外查询参数；需要组合参数时先明确合并规则并验证。POST 等非 GET 请求不能直接套用静态页面的 301 方案，应另核对请求方法与请求体语义。[官方配置与状态码说明](https://help.aliyun.com/zh/edge-security-acceleration/esa/user-guide/request-redirects)

浏览器片段 `#section` 不发送给服务器。目标 `Location` 不带片段时，浏览器按规范继承原片段；实际页面是否仍有对应锚点需要浏览器验收，HTTP 检查不能替代。[RFC 9110：Location](https://www.rfc-editor.org/rfc/rfc9110.html#name-location)

## 启用与验收

使用已有授权的官方 API 或控制台管理规则；控制台入口为目标站点的“规则 → 重定向规则”。回读规则标识、匹配条件、目标、查询参数策略、状态码和启用状态，保留其他规则。

| 检查范围 | 核对内容 |
| --- | --- |
| 旧址 HTTP 与 HTTPS | 记录首跳状态、Location、完整跳转链及最终内容 |
| 首页、子页面、资源 | 逐页到正确目标；覆盖原 `.html`、目录入口及平台实际规范化路径 |
| 查询参数与片段 | HTTP 检查参数，浏览器检查最终 URL 与锚点落点 |
| 新站与未迁移入口 | 新站仍正常，其他主机和路径不被本次规则匹配 |
| 未知路径 | 保持项目预期的 404 行为，不通过跳回首页掩盖缺失页面 |

启用后再次从旧址访问，区分规则配置成功与访客访问成功。记录实测网络及首次失败；仅针对失败项复查时保留首次结果，不据此判断长期稳定性。

## 恢复与验证范围

执行恢复时，先回读现状，再关闭本次新规则或恢复被修改规则的原值，并核验旧入口及内容版本。旧项目可能保留的是迁移前旧内容，恢复旧入口不代表保留迁移后的更新。

301 可能被客户端或中间缓存复用，关闭服务器规则不能保证所有访客立即回到旧站。恢复验收需要同时观察新会话与已有会话，记录残留缓存及仍需处理的入口；保留旧版本本身不等于完成恢复演练。[RFC 9110：301](https://www.rfc-editor.org/rfc/rfc9110.html#name-301-moved-permanently)

2026-11-20 来源项目已验证 ESA 按旧主机逐页跳转、查询参数、浏览器锚点及原资源保留。真实恢复、跨天与多地区访问仍未验证。具体域名配置、网站代码和原始回执留在来源项目，通用流程不依赖这些私人材料。以上官方机制于同日核对。
