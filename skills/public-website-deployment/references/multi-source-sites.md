# 多来源静态站点组装

用于用户已选择将多个静态网站或专题放到同一发布项目的不同路径，或更新合并站点中的一个专题。源仓库可以独立维护；路径沿用目标项目约定，例如 `/topics/alpha/` 与 `/topics/beta/`，不要求所有站点采用同一栏目结构。

本流程准备完整静态产物。上传与路由支持分别按 [ESA](esa.md) 或 [Cloudflare](cloudflare.md) 核对。域名更换、项目间改绑和旧域名跳转另按本次任务处理；ESA 旧址跳转见[迁移流程](esa-domain-migration.md)，组装本身不改变域名配置。认证与公开文件边界沿用 [主流程](../SKILL.md#共用产物流程)。

## 固定来源与目标路径

为每个专题记录下列信息，复用项目已有清单格式即可：

| 信息 | 用途 |
| --- | --- |
| 源仓库与固定提交，或可定位的产物版本 | 明确本次采用的来源；不要只记录会变化的分支名 |
| 允许发布的文件、相对路径与 SHA-256 | 确认输入完整，避免把源码、私人配置或临时文件带入网站 |
| 目标路径前缀、入口与共享资源归属 | 检查专题之间及与门户已有文件的冲突 |
| 构建方式或链接改写规则 | 记录来源如何变成目标路径下的文件 |

从源码构建时，沿用该项目的固定依赖、构建命令和环境要求；同时记录源提交与构建后静态文件摘要。从现成产物组装时，核对其版本和文件清单。对输入先做路径与摘要校验，缺文件或摘要不符时解决来源问题后再继续，不从线上 HTML 临时拼凑缺失内容。

## 适配子路径

1. 核对每个目标前缀的现有内容与归属，以及门户入口、共享资源和路由规则。同一输出路径被多个来源使用时，明确共享或替换关系后再组装，不能以复制顺序决定覆盖结果。
2. 框架站点优先使用其已有的基础路径配置重新构建；现成静态页面按明确映射调整相关站内链接。检查 HTML、CSS 和脚本中的资源地址、导航与数据请求，避免原站的根路径指向新站根目录。
3. 链接改写保留原有查询参数和片段，保留仍应指向外站的链接。逐项核对改写范围，避免全局替换域名造成正文或外链误改。
4. 为新产物保留“来源文件 → 输出文件”的映射和改写记录，分别计算输入与输出摘要。改写后的文件不再宣称与源文件字节一致；源文件保持原样。

站点级 404、重定向、标头及 SPA 回退规则需统一核对。不能假定每个专题原有的根配置放进子目录后仍有效，也不能让一个专题的回退规则接管其他专题。按所选平台的实际响应验收。

涉及浏览器存储或 Service Worker 时，检查合并到同一来源后的存储键名与缓存作用范围。原域名下的本地状态不会随静态文件迁移，相关数据迁移需求由网站项目处理。

## 生成完整产物与更新专题

在源目录和历史发布目录之外生成新的完整产物目录，保留门户文件、全部专题与共享资源。部署配置、构建清单和运行回执放在公开目录之外；公开版本信息按项目需要提供，不包含私人来源或账号信息。

更新一个专题时：

1. 定位当前线上版本对应的完整产物及各专题清单，保留为恢复基线。
2. 核对被更新专题的新版本、公开文件和路径适配；保留其余专题的固定版本与清单。
3. 重新组装完整站点，对照上一版清单检查差异。其他专题保持不变；本次需要调整的门户导航或共享资源单独记录其影响。涉及删除的文件沿用主流程的授权要求。
4. 校验完整产物后，以同一目标项目和环境发布整个公开目录。只上传被更新专题会遗漏同项目的其他内容，不能作为完整站点更新方式。

组装工具沿用网站项目的实现，数据条数、特定栏目和业务断言由该项目维护。本技能提供方法，不要求复制示例项目的代码或固定数据校验。

## 验收与证据

- **发布前**：按清单检查输入与输出摘要、资源引用、门户导航、每个专题入口、主要交互、深层页面直达与刷新及预期 404。对照差异确认更新范围和保留内容。
- **发布后**：回读实际部署版本，在目标站点检查完整资源及各专题，覆盖本次改动和保留内容。核对实际路径、查询参数和锚点；有平台 URL 规范化时，检查最终页面及内容，不只看首个状态码。
- **恢复与网络范围**：保存上一完整产物及部署标识；实际执行恢复并验收后才标为恢复验证通过。分别记录 HTTP 与浏览器所用网络，保留首次失败和针对性复查结果。

方法依据为 2026-11-20 的 ESA 项目案例：固定来源、路径适配、首次合并发布和访问验收已有证据。合并站点上线后的单专题更新、Cloudflare 多来源组合发布及真实恢复仍待实测，见[验证状态](../SKILL.md#验证状态)。具体网站代码、来源数据和原始回执保留在来源项目；安装本技能无需取得这些材料。
