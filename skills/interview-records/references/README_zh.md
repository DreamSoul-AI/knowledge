# 日历驱动的面试记录

从飞书日历找到已结束的面试，取得关联原始记录，再按实际岗位和轮次整理。候选人自述、面试官观察、直接材料、评价、更正及待核事项分别保留。

## 安装与环境
安装整个 `skills/interview-records` 目录。获取来源的说明已随包提供，不要求另外安装 `meeting-minutes`。

飞书读取需要已有 `lark-cli`、对应日历/会议/文档/共享技能及当前用户权限，这些服务集成不包含在本仓库中。也可直接提供本地面试材料。岗位现行流程和模板优先，不把公司默认维度或其他岗位权重机械套用。

## 使用
```text
使用 $interview-records 从今天的日历找到已结束的面试，获取关联原始记录，并按实际岗位和轮次整理。
```
可补充日期范围、候选人、岗位、日程或材料链接。未给日期时默认从用户当地今天已结束的日程开始，DreamSoul 默认 Asia/Shanghai。

## 获取与匹配
日程实例 → 实际会议 → Note 逐字稿、Minutes 文字记录或明确绑定的面试笔记。[来源链路](sources.md) 与 [记录写法](record.md) 随包保存。

排除已取消的面试及面试培训会。已有明确材料链接就直接读取，不补造会议ID。同名或相邻场次关联不唯一时列待确认，不自动拼接或选择最近一场。材料仍在生成、无记录、无权限分别说明。

## 成果
保存原始依据和来源映射，再按岗位整理交流内容、本人贡献、证据、更正、冲突条件和核验问题。缺项不自动给低分，默认不生成总分、跨人排名或录用决定。

检查摘要、表格和派生清单中的隐私信息。交接只保留任务必要信息，内部原件按既有访问范围保存，不把正则命中数当作完整脱敏证明。

## 自动化边界
一次调用完成一次获取整理，不自动安排定时任务、联系候选人、改动招聘总榜、发布记录或启用录制。已做格式和合成场景检查，真实日历和转录获取仍需在目标环境实际验证。
