# 定时电子邮件总结 scheduled-email-summary

[English](README.md) | 简体中文

按使用者选择的邮箱和范围，整理需处理、待跟进及重要知会，提供真实邮件入口。任务定义见[提示词](prompt.md)，账号、兴趣、规则和输出位置从[外部配置](config.example.yaml)传入。

## 报告归属和接续

`reporting.period` 默认 `incremental`，保持原成功覆盖接续；选择 `natural_day` 时，用本次计划触发时刻及实际业务时区确定前一自然日和排他截止，不按执行结束日命名。人工明确的日期或窗口只用于本次且优先，手动预览不自动推进生产游标。计划时刻缺失且影响归属时先核对，不凭执行日猜。

主报告按已固定的自然日展示，补漏扫描仍继承旧成功游标、回看与未完成项。晚到材料和此前漏项注明其原业务日期；不能因换目录另起状态、倒退已有游标，或只读新一天。部署频率、时刻及时区继续由使用者选择，共用定义没有固定每日或00:01默认。

## 配置和试跑

1. 将配置复制到实际项目的本地配置位置，填写项目根、平台、连接、预期账号、文件夹、时区、输出及状态路径。保持凭据由连接自身管理
2. 接入实际可用的邮箱读取工具。Outlook 可以使用连接器的 get_profile、list_messages 或 search_messages，必要时 fetch_message；飞书可使用 lark-mail 的 profile、+triage 和按需 +messages。其他平台需要提供等价只读能力，配置一个名称不代表已经支持
3. 请求 Agent 读取本目录提示词和实际配置，明确日期范围，执行一次 manual_preview。先看摘要、原邮件链接、完整分页和重跑结果，再考虑定时安排

Outlook 为本轮真实验证的平台，邮箱平台不固定。使用多个邮箱时各自填写配置、核对身份并保存扫描进度。文件夹范围必须明确，不能将整个账号的查询结果宣称为收件箱结果。过滤和重点规则可因使用者调整，默认兼顾已读和未读。

## 摘要怎样写

每项采用 **主题或发件方｜你要做什么／当前状态。** 后接一个短段落，交代具体问题、最新变化、已处理内容、期限和原邮件链接。已回复的不再列作待回复，等对方的说清等待谁，重要知会点明变化。通常选3至6项，数量按实际内容调整。

例如「**专利代理｜需要确认答复建议。**」接具体材料及答复期限，「**客服工单｜等技术部门反馈。**」接本人已补充的信息和客服状态。研究邮件要讲具体反馈与剩余问题，不能只输出“某论文有几封通知”。这是一种表达方式，具体主题和动作仍依据本次来源。

## 配置字段

| 配置 | 填写要点 |
| --- | --- |
| project_root | 实际项目根，或相对配置文件的项目路径 |
| mailboxes | 每个账号单独一项，不共用身份和扫描进度 |
| provider、connection | 平台名称和当前可用连接，不填密码或令牌 |
| expected_account | 用连接的身份查询返回值核对 |
| folders | 实际文件夹标识，或明确选择 all_visible |
| scan.timezone | 报告和扫描日界线所用时区 |
| scan.start、end_exclusive | 固定试跑窗口，两项同时填 |
| selection | 兴趣、重点发件人、排除项及简报长度 |
| output | 当前聊天，或实际允许的本地报告位置 |
| state | 本任务独立进度和互斥位置 |
| retention | 默认不保存原邮件和来源清单 |
| deployment | 实际启用状态和确认后的执行时刻 |

**先核对邮箱身份。** Outlook 用 get_profile 获取实际账号，再与 expected_account 比较。连接未加载时说明缺失能力，不因为配置写着 outlook 就认定可读，也不改用另一账号。多个账号需要各自可用的连接，不能只增加一个配置项就认定已切换成功。

**文件夹必须与工具能力一致。** list_messages 没传 folder_id 时查询的是账号默认消息范围，本轮观察到其中包含已发和疑似广告，不能称作仅收件箱。选择文件夹时先从实际文件夹查询取得 ID，再交给支持该范围的接口。all_visible 是显式选择的读取范围，不是一个要传给 Graph 的文件夹 ID。发件箱只在配置允许时读取，用于避免把本人已回复的事项再报为待回复。

**试跑和定时分开。** manual_preview、enabled: false、advance_checkpoint: false 用于手动核验，不创建或更新调度。先填固定时间窗口并检查分页和摘要，随后再讨论执行时刻、时区、通知位置及进度接续。示例不预设所有人都在00:00运行。触发频率与扫描范围是两件事，漏跑后仍需从上次成功位置补齐。

**对接现有任务。** 先核对它当前的读取方式、有效要求和覆盖记录，保留可用的做法。调度提示词可以引用本地本目录 prompt.md 和实际配置的绝对路径，但承载环境必须能读取这些文件、拥有对应连接。仓库链接本身不会自动挂载 automation。迁移、跨设备接入或变更运行环境时重新验证，不能只复制提示词就称为已部署。

可这样发起一次试跑，配置路径和日期换成实际值：

```text
读取 <定时邮件总结目录>/prompt.md 和 <实际配置文件>。
先检查邮箱身份、文件夹和时区，再按指定窗口手动总结。
给出核心事项和原邮件入口，报告完整分页及不可读内容。
这轮不修改现有定时任务，也不推进原任务覆盖记录。
```

## 验证状态

首版可复用任务定义，启用和配置由使用者决定。已两次联网核对同一 Outlook 完整日期窗口，验证身份、分页、时间边界和归组，第二轮关闭正文落盘及进度写入；随后使用同一批材料验证了「主题加下一步行动或当前状态」的写法。不同平台、多账号切换、实际调度及真实中断恢复仍待验证。既有个人定时任务保持原状，不能把它的运行成功当作这套新定义已部署。具体结果见[运行记录](<../../docs/运行记录 Run Record/2026-11-20 每日电子邮件总结验证.md>)。本任务不会自动回复、转发或整理邮箱。
