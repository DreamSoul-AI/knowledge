# 每日会议总结提示词

使用部署时提供的配置文件执行一轮每日会议总结。先读取当前项目 AGENTS.md、配置、三个指定技能的正文及所需引用，核对实际身份、可读来源、本地输出位置和本轮授权。配置路径由部署者提供。project_root 为相对路径时，相对实际配置文件所在目录解析；其他配置路径以解析后的项目根为基准。另一个规则文件内的相对引用按该文件自身约定解析。本提示词按项目配置适配，任务时间和平台通知偏好由调度器提供。

若配置仍为示例、部署启用标记为 false，或关键身份、输出位置仍为空，本轮只报告配置缺项。平台读取、本地生成和云端写入分别按配置及当前授权核对。配置中的空专项清单表示本项目尚未接入专项要求，不能据此认定已迁移原任务的全部行为。

已有部署可以沿用自己的配置结构。接入时从实际字段解析同一组输入，例如顶层 timezone、rules.general、rules.placement 或 classification.placement_rule、outputs.artifact_naming、confirmed_cloud_routes、state 和 reporting。专项内容及补充材料从相应规则和项目配置读取。确认解析出的实际语义及执行范围，保留既有配置作为维护入口。历史资料中的旧执行开关只按其声明的适用范围读取。

## 一、本轮目标

对范围内实际已结束、归档责任明确且有可用原文的会议，完成所需的本地会议记录和会议总结，适用建议、周回顾及复制文案按专项规范处理。已有合格成果直接复用，缺什么接续什么。归属、权限、来源或内容冲突影响哪份成果，就记录哪份的具体阻塞，继续其他可独立处理的场次。

## 二、调用技能

用 calendar-meeting-archive 统筹来源、责任、归组、已有成果判断及逐场进度，遵循其 recurring.md 的扫描、补漏、持久状态和重叠运行规则。核实其他任务及本轮运行是否会写同一范围，继承配置指定的历史索引、固定正式稿、配对和比较基线。

对确需整理或局部补齐的内容，把原始材料、补充材料、适用规范、现有稿、修改范围和本地输出位置传给 meeting-minutes。执行专项规范的建议构思和价值筛选，记录实际筛选结果。有价值的建议按规范交付，无候选时保留依据，复用这一结果。

补充材料包括专项规范要求的本周相关会议、近期建议、可取得的采纳反馈，以及需要核对的个人日志或待办。按规范判断哪些是新增行动、哪些已在现有安排中，保留实际查阅范围。成果命名读取 rules.artifact_naming 或项目现有命名入口，保持本地与云端的对应关系，历史成果的改名另按本轮范围处理。

本轮确认允许云端写入时，把已核验的明确成果清单、逐类目标和独立回执交给 document-sync，使用 upload、conflict: stop、delete: false。将任务配置转换为该技能要求的实际配置，按其路径解析规则核对位置。缺少指定技能或规范时说明受影响步骤，保留已完成结果。

## 三、扫描和去重

固定本轮开始时刻为扫描截止点，按配置时区读取完整范围和分页。首次采用配置的回看天数，随后覆盖上次完整扫描截止点到本轮截止点、配置回看窗口和全部未完成项。零点触发也须覆盖前一日及此前漏跑的会议。保留跨窗口仍未结束的日程线索，补查开始早于窗口但在窗口内结束的会议。

按实际会议身份、成果种类和受众范围查已有成果，缺实际会议 ID 的旧正式稿仍按固定文档标识核对来源。近期稿来源可核对、符合当前要求且无明确错误时复用，局部缺漏只补受影响内容。保存原文的正式位置及来源映射，复用已下载且来源已校验的材料。扫描失败时保留该段覆盖进度，等待转写和超过回看窗口的未完成项继续接续。

## 四、分类和交付

默认按已确认会议管理人或归档负责人判断处理资格，允许配置或本次要求中的明确接管和例外。一般会议使用通用内容规范，匹配的会议再叠加专项规范。实际会议日期决定周回顾等要求是否适用。建议只按规范和实际价值生成，招聘等专业会议使用自己的规则。

按项目配置中的系列、别名、临时归组及逐类云端目标处理，保留已确认正式稿的位置和身份。分类不明确时把原件及来源保存在配置允许的待确认位置，明确本地归档后再整理。某类上传目标或受众未核实时保留对应本地成果并集中报告，其余明确成果继续。

会议记录、总结、适用建议分别核对完成状态，已经交付总结也要检查所需记录是否缺失。目录创建、云端多稿归并、移动或删除按本轮明确范围执行。没有正式配对或并发冲突无法裁定时，保留双方和待处理依据。云端交付遵循实际项目文档及上传规范，保留原链接、评论和资源。结果不明时先查已知对象，再接续，回读通过后保存逐份成功基线。

如配置明确允许补建会议记录子目录，先核实父目录、会议归属和受众，再复用或补建指定子目录。按确认范围使用原始记录局部校订正式稿时，保留未解决的来源差异；其他稿的入口标识、移动、删除分别判断授权。飞书访问使用对应 lark 技能和 lark-cli，显式 --as user，并与配置中的实际使用者核对。认证问题先区分运行环境、登录和资源权限。

## 五、状态和结果

逐场保存来源、责任、分类、本地整理及逐类云端状态。写前重读并原子保存，只释放本轮自己的运行锁。运行中断后依据已知对象核对实际写入，继续未完成环节。正式原件长期保存，临时输出放项目指定的临时目录。

按系列或会议类型及实际日期，逐场列出所需会议记录、总结和条件成果的本地状态、云端状态及真实链接。区分新增、更新、复用、仅本地和待处理。配置指定的专项会议单独展示，包括适用的原始会议、建议及复制文案入口。手动核对包含复用成果，日常运行按已确认平台通知设置交付有意义的变化和异常。

结束前检查本轮已取得原文的应处理场次，完成可独立推进的内容整理和已授权交付。只有下载、登记待办或总报告时，要准确说明尚未完成的环节。遇到具体阻塞时记录原因及接续点，保留成功成果。

本轮访问资源限于配置和当前授权。日历、总表、日志、共享权限、技能源码、规范本身及其他任务的修改另按明确请求处理。复制文案交付到承载任务聊天，留言板发布和向他人发消息需要对应授权。
