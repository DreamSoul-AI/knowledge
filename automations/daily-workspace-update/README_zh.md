# 每日工作区更新

[English](README.md) | 简体中文

以workspace-update为入口，每日处理配置范围内已采用的工作区模板、规则和配套使用入口，并默认同轮调用knowledge-update一次处理已采用技能及工具。它是一轮工作区更新，不是只更新技能。

这里维护每日任务的可复用定义，示例本身不注册或启用调度。先用[提示词](prompt.md)和[配置示例](config.example.yaml)核对实际采用范围，再通过调度平台接入已有任务或创建任务，按用户确认的时间及更新方式启用。身份、项目、承载对话、个人分支和机器路径留在实际运行配置，不放入可分发示例。

部署时记录已采用的仓库、固定提交及本目录入口，让实际任务读取对应提示词和本地运行配置。定义放在GitHub不等于调度器已自动加载；承载对话需能取得正式文件，调用完整已采用技能，并回报实际读取版本。仓库示例中的空时间和停用标记不是个人实际任务的状态。

## 配置

沿已有采用记录填写工作区、已采用项及实际目录、来源和定制。通用能力取正式来源，个人能力取本人已采用的个人来源；个人分支继承其他通用文件不代表它们都应从个人分支更新。没有实际接入的工具不纳入，不默认安装所有技能。检查模式不写目标或升级依赖。

默认路径是本地工作区更新。`deployment.enabled` 控制定时是否启用，`execution.mode` 控制检查或更新，`github_distribution.enabled` 单独控制是否同时分发到组织仓库，默认关闭。选择组织分发后，从已有采用记录或配置的organizations、repositories取得仓库、目标分支和排除项，由workspace-update沿原PR流程处理。可以自然地说“同时更新组织仓库”，不必每次手写配置或重列清单；仅存在仓库清单不代表开启分发。GitHub来源读取、云端交付及ZIP发布分别按实际范围处理，不与此开关混同。

## 试跑与验收

刷新是外部可选接入项。实际配置要求刷新且更新回读通过后，再接已采用或明确配置的refresh-chat入口，先筛选当前执行对话及本轮范围内的明确关联目标，仅刷新实际需要的对话，已有当前版本读取回执的不重复刷新。请求只附技能入口、本次变化及必要线索，不重述完整技能步骤。区分更新成功、刷新已请求、目标已读及待接续。刷新只重读规则和入口，保留原任务状态，不代表宿主已热加载新版技能。已要求刷新但入口不可用时保留更新结果并说明缺口，不把依赖未就绪写成已联动成功，也不为此安装未知技能。

固定来源后比较完整分发包，区分内容变化、换行差异、定制、额外文件和缺基线。需要实际更新时仍按原技能范围处理、备份与回读。同版本重跑无需变化，冲突逐项保留。技能文件已安装、运行器发现及实际调用分别报告。

此前能力子步骤检查六项完整包均无需内容更新。后续已对一个明确资料工作区核对正式源、模板采用入口和个人适配，没有新增适用模板正文，未写目标。当前没有真实更新后刷新或定时触发的验收；refresh-chat仍以实际采用/配置入口为准，未安装的本地候选不当作已部署依赖。

依赖入口：[workspace-update](../../skills/workspace-update/SKILL.md) / [knowledge-update](../../skills/knowledge-update/SKILL.md)。可选刷新入口：[refresh-chat](../../skills/refresh-chat/SKILL.md)，以实际已采用或明确配置的可读版本为准。需要安装时保留使用者确认版本的完整包，定义中的入口不代表宿主已经加载。
