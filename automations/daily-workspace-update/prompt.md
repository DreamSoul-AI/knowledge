# 每日工作区更新

读取本任务实际配置、适用项目规则及已有采用记录。先确定检查或更新模式，实际任务没有确认时使用检查。默认只处理明确目标工作区的本地规则、模板和已采用能力，不因周期运行或采用清单列有其他仓库而扩大写入范围。

组织仓库分发由独立的github_distribution.enabled或本次明确选择控制，与调度enabled、检查/更新模式分开。选择同时分发时，沿已有配置及采用记录取得organization、repo、目标分支与排除项，交workspace-update走原有PR、检查、合并和回读流程；未选择时不写远端。来源可从GitHub读取，不等于选择了向GitHub分发。云端和ZIP等只在本轮另有对应交付范围时进入，不要求用户重复已知清单。

只处理已安装、已采用或本次明确指定的Knowledge技能和已接入工具。固定各自来源版本，分别选择通用正式来源和个人已采用来源，定位实际安装目录，保留本地定制、额外文件和未发布草稿。不默认全装，不升级整个运行环境。

以workspace-update作为本任务入口，检查或更新配置范围内已采用的工作区模板、规则和配套使用入口，由它默认同轮调用knowledge-update一次，复用相同目标、来源、授权、排除项和已有结果。能力更新是工作区更新的一部分，不把本任务缩成只检查技能，也不重复比较或安装。采用范围暂缺时明确哪部分待补，其余明确项继续。

在检查模式使用完整包比较或现有helper预览，不写目标、不安装、不发布。字节差异须区分实际内容和原编码/换行，不为追求字节一致覆盖有效本地格式。缺少旧基线的真实内容差异保留具体待核，不把它直接判成可覆盖漂移。

同轮重复运行复用固定版本和已检查项，仅补变化或失败，不重复安装。报告检查范围、实际来源、更新/无需变化/冲突失败、保留定制和必要重载说明。未查的依赖、工具、项目安装、模板或运行器优先级如实注明。

刷新按外部运行配置接入。配置要求刷新且有实际更新并回读确认后，调用配置或已有采用记录中可用的refresh-chat，先按变更和可靠读取回执筛选当前执行对话及本轮范围内明确的关联目标，再只刷新实际需要的对话。短请求保留技能入口、变更文件/版本和必要线索，不复述完整技能步骤，复用同轮已完成刷新。只检查、无需变化、未写成功或仅有待处理冲突时不触发刷新；部分更新成功时只处理已核实成功的部分。刷新保留各对话任务断点和暂停状态，不等于恢复业务；跨对话按实际读取与回执分别报告，不能以请求已发送代替完成。技能文件已更新但宿主尚未重载或发现的状态单列，refresh-chat不冒充重启或强制热加载。已要求刷新但refresh-chat不可读或关联目标确实不明时，报告“更新完成、刷新待接续”及具体缺项，保留已成功更新，不另装未知技能或全账号群发。

更新模式只有在本任务已明确授权具体范围时采用原技能执行与回读流程。检查通过不自动授权更新、提交、平台发布、云端同步或创建定时任务。个人运行配置和原始回执留在使用者环境。
