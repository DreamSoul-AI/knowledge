# 每周会议背景

复用个人已采用的meeting-background，为例会准备本人“总结、上周、本周”。总结前置，按实际部门或分类说明重点、关联和有依据的状态，再列上周记录及本周安排。定义不创建定时任务，频率、作者、来源及目标由使用者配置，不能沿示例猜个人信息。

先填写[配置](config.example.yaml)的来源、周次和本地输出，使用[prompt](prompt.md)手动出稿。核对逐日覆盖和当前TODO版本，同周接续不重复追加。本地稿与自动写云端是不同模式，默认仅本地；未来更新须指定当期文档和本人章节，依原技能回读。

出稿前读同系列既有本人章节，沿原分类使用事项名或短结果，不逐条套“推进”等空动词。保留会改变理解的准确状态，撰写和审核分清，日志勾选不提升为项目完成；已暂停的旧计划不作为本轮执行建议。

本周安排以会议准备时点有效的计划为准，回放旧周一不能倒用后来的TODO。本人姓名用一级标题，总结、上周（日期范围）、本周（安排起点）用二级标题。总结每类一段，加粗分类名，段内用 `1)`、`2)` 区分事项，不用斜体或另起编号清单，避免机械复述长清单。研究课题归研发，本任务默认不列外部协作，除非本次明确要求包含。上周、本周用紧凑的嵌套圆点列表，父子项及相邻项之间不插空行。Markdown 必要分段不转换成飞书空白文本块。来源和试跑核对放单独记录，不在本人章节附加历史暂停清单。

准备真实调度前确定例会时间、时区、触发频率和承载对话，确认运行环境能读取定义和完整技能。未填写的schedule不表示已启用。运行记录及私人配置保留使用者环境，不进入分发包。
