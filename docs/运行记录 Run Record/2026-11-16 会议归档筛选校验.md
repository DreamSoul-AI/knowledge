# 会议归档筛选校验

## 范围

核对 [技能入口](../../skills/calendar-meeting-archive/SKILL.md)、[来源获取](../../skills/calendar-meeting-archive/references/sources.md)、[定时接续](../../skills/calendar-meeting-archive/references/recurring.md) 及中英文指南。仅修改技能指令及引用，没有新增执行程序。

## 情景推演

由本轮 Agent 阅读修订说明后，对以下合成输入逐项判断。本表是指令行为审查，不是自动化测试、独立 Agent 评估或真实会议归档。

| 输入情景 | 本轮判断 | 后续处理 |
| --- | --- | --- |
| 只有邀请和组织者身份，合理查询无来源，参与未证实 | 筛选结束，参与情况仍未知 | 保存查询依据，不创建长期材料缺口 |
| 上轮已筛选结束，本轮无新信息 | 沿用筛选结果 | 不重复同样的来源追查 |
| 筛选结束后出现发言等参与依据，负责人明确且已有总结 | 重新核对范围、责任和来源 | 先复用已有稿，只接续实际缺项 |
| 已确认参与，转写生成中，日期已超回看窗口 | 真实待处理 | 保留标识、阻塞和下一步，跨窗口接续 |
| 用户明确指定本轮负责归档，参与情况未知但原文缺失 | 范围已明确，材料待补 | 不套用仅有日程的停止条件 |
| 已确认参与，但归档负责人另有其人且无例外 | 不新整理或上传 | 在允许范围内复用可读取入口 |
| 查询超时或权限受限，未完成来源核查 | 报告实际读取限制 | 不伪称已完整查询或据此断言无来源 |
| 只指定日期，候选参与未证实且合理查询无来源 | 日期不等于逐场明确归档要求 | 记录筛选结束，保留既有历史 |

上述判断均可沿修订后的入口、来源筛选和接续说明得到。新材料触发的是资格复核，不自动授权整理、上传或改变责任。旧清单的单项复核应保存新判断及旧历史，本轮没有批量删除或迁移真实状态。

## 结构和安装检查

在 Windows、现有 Python 环境中，从仓库根执行 skill-creator 的 `scripts/quick_validate.py skills/calendar-meeting-archive`，结果为 `Skill is valid!`。另核对技能内相对引用和 UTF-8 编码。

安装前比较仓库和本地安装目录：文件清单一致，Markdown 正文一致，仅换行格式不同。安装交付保留完整技能目录，逐文件核对 SHA-256；安装路径和原始回执只保存在本地核验资料中，不随仓库分发。

没有查询真实日历或会议来源，没有生成、上传或删除会议成果，没有修改定时安排、运行游标或历史待处理状态。自然定时触发和真实平台读写仍需在对应授权范围内另行验证。
