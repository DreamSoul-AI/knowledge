## 实验执行

**结构化回复和文件**

给出要求 `status` 和 `observations` 字段的 JSON Schema，要求 Agent 实际写入并回读两行纯文本。最终回复为符合字段要求的 JSON，实际 `receipt.txt` 字节为 `status=done\nformat=plain-text\n`，退出码为 0。父任务另行读文件和 JSON 核对，没有只采用子会话的完成自述。

这验证了本次 CLI 路径中，最终结构化回复与工具生成的纯文本产物可以并存；文件格式仍需单独验收。[官方非交互执行说明](https://learn.chatgpt.com/docs/non-interactive-mode) 将 schema 描述为最终回复约束，与该观察范围一致。

**从一句问题自主探测**

任务只询问：从两个不同工作目录执行同一个 Python 脚本时，`Path.cwd()`、`Path(__file__).parent` 和相对文件读取分别跟谁走。未提供预期答案或脚本。Agent 自主在脚本目录及两个工作目录放入不同的合成文件，以相同解释器、绝对脚本路径运行并断言实际输出。

| 表达式 | 从目录 A 运行 | 从目录 B 运行 |
| --- | --- | --- |
| `Path.cwd()` | A | B |
| `Path(__file__).parent` | 脚本目录 | 脚本目录 |
| 相对读取 `input.txt` | `FROM_A` | `FROM_B` |

最初选择解释器时，PowerShell 返回多个候选，命令失败；Agent 保留错误，改为选择首个应用路径后成功执行，未重装环境。父任务检查实际脚本、三份输入和工具结果，并独立复跑脚本核对结果。该样本体现了设计、准备、执行、纠错和判读链条，未要求生成完整报告或新建研发项目。
