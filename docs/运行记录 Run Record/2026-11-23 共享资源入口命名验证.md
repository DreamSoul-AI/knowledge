# 共享资源入口命名验证

## 变更范围

本轮将通用和研发配置示例的推荐仓内入口从 `.local/` 改为 `.shared/`，实际资源根推荐使用仓库外的 `shared/`。`.shared/` 是普通容器，下面的资源入口是目录符号链接。工具双语说明、研发示例、根双语入口和接入计划同步更新。

通用实现 `link_shared.py` 未修改。资源类型、目标位置和每个仓库的入口仍由配置决定，旧配置和自定义路径继续可用。项目采用新命名时，目标是替换相应共享入口和使用路径，不以永久双入口并存为完成标准；改名和消费者适配由项目或工作区维护流程负责。

本轮不包含真实项目迁移、共享资源载荷、个人配置、技能安装、飞书或 ZIP 分发，不创建新的共享资源技能。

## 环境和命令

Windows、Python 3.13、Git。测试仅在任务临时目录创建合成资源和临时 Git 仓库，通过当前进程真实创建符号链接验证行为。

```text
python -B -X utf8 tools/shared-repository-resources/tests/test_link_shared.py
```

使用 `SHARED_RESOURCES_TEST_ROOT` 指定隔离目录，`SHARED_RESOURCES_TEST_REPORT` 保存逐项 JSON 结果。原始回执和机器路径只留本地，不随本记录分发。

## 实际结果

受限进程首轮为5项通过、9项失败、5项错误，主要受 Windows 符号链接权限 `WinError 1314` 限制，目录联接点用例也被拒绝。保留了原失败记录，没有把环境失败改记为通过。

通过执行环境审批后，以当前用户正常权限重跑相同测试，19项全部通过、零跳过。没有以复制或 Junction 代替正常符号链接。

| 检查 | 观察 |
| --- | --- |
| 推荐研发配置 | 两仓库共享数据和模型，项目产物目标保持不同 |
| 新入口重跑 | 正确识别已有链接并复用，不重复追加忽略规则 |
| 通用配置 | `.shared` 和任意自定义入口可指向同一资源 |
| 旧配置兼容 | 旧新入口可临时并存，原资源字节和无关本地文件保留 |
| 占用冲突 | 新入口被实体目录占用时拒绝写入，保留原入口和忽略内容 |
| 原有回归 | 预览不写、越界、错误目标、损坏链接、Git 跟踪和中断接续通过 |
| Windows 重定向 | 符号链接和 Junction 父目录均按原边界拦截 |

旧新并存用例只证明兼容性和迁移过渡时不会损坏资源，不证明真实项目完成改名。目录可读也不等于业务程序已使用新路径。

## 验证边界

仅覆盖所测 Windows 环境和隔离样例。其他设备、其他操作系统、并发写入及真实业务消费者未在本轮测试。发布前逐份核对配置、文本引用和既有在途修改，提交范围不包含其他技能或草案。
