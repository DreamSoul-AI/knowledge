# 多仓库共享资源接入通用调研

## 问题和机制

多个仓库需要共享一部分目录内容，同时保留各自程序需要的访问路径。目录符号链接提供路径引用，资源仍保留在实际目标目录，链接本身不执行内容复制、跨设备传输或消费者配置修改。

Python 标准库的 `os.symlink` 可以创建目录符号链接，Windows 需要明确目录目标类型，创建权限取决于实际进程和系统条件。目标设备是否具备相应能力必须实际核对，不能由另一台设备成功推定。[Python 符号链接说明](https://docs.python.org/3.12/library/os.html#os.symlink)

## 配置和采用方式

本工具采用显式 JSON：资源名对应目录，仓库名对应实际根和逐入口映射。所有相对路径相对配置文件，配置不从脚本所在仓库推断其他项目位置。资源名可以是语料、字体、图标、参考材料或项目结果，目录命名不属于通用实现的前提。

Workspace 原有 `工具/本机共享目录/link_shared.py` 是固定研发布局的初始化来源，其默认位置推断及三类资源接口不适合作为通用配置合同。研发惯例保留为可选示例，通用实现由 knowledge 工具维护，Workspace 研发入口只说明如何采用，不复制新的执行逻辑。

## Git 和冲突边界

Git 忽略只影响未跟踪项，不能用新增忽略规则替代已跟踪内容的处置。以 `/` 结尾的忽略模式针对目录，符号链接需要按实际入口验证是否被忽略。工具使用精确入口规则，并通过 `git check-ignore` 核查实际效果。[Git 忽略规则说明](https://git-scm.com/docs/gitignore)

选择预检全部映射、显式执行、保留冲突入口的方式。正确链接复用，实体占用、指向错误、损坏链接和 Git 跟踪均停止。已有链接失去目标与用户明确允许创建的新资源是两种情况，不能混作一次初始化。

## 当前结论和限制

通用配置加小型标准库 CLI 足以承接当前目录接入需求。Agent 按实际项目判断映射和适用范围，工具负责预检、创建、Git 忽略及目标核验。实现见 [工具](../../tools/shared-repository-resources/link_shared.py)，实际测试见运行记录。

本轮范围不包含实体迁移、跨机器复制、多个写入者协调、运行环境二进制兼容或任意文件链接。其他操作系统、权限和项目消费者需分别验证。
