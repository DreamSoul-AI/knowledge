# 多仓库共享资源接入架构设计

## 目标和职责

主要服务于多仓库共享研发数据、模型及权重，以及集中管理和按需复用运行产物。把资源类别、目录位置和各仓库入口从程序中移出。使用者或 Agent 提供明确配置，工具在所选 Git 仓库内创建目录符号链接。共享配置与真实资源分别维护，工具不包含个人路径、身份或真实数据。

```mermaid
flowchart LR
    C[本机配置] --> P[完整映射预检]
    P --> V[预览 JSON]
    P --> A[显式执行]
    A --> L[创建或复用链接]
    L --> G[核对目标和 Git 忽略]
    G --> R[结果与已完成项]
```

## 执行约束

先预检所选仓库的全部映射，再写入。执行前再次核对实际入口、跟踪状态和父目录，创建操作不替换已有入口。资源目录仅在配置明确允许时新建。符号链接的实际目标与忽略效果核验通过后，才计入完成项。

遇到已知配置或路径冲突时预检失败，不开始其他映射。执行中断保留已完成部分，依靠真实链接状态重跑接续。批次不提供跨文件系统事务或自动回滚，多个进程不应同时修改同一批入口。

## 集成和差距

knowledge 提供通用 CLI 和示例，Workspace 研发模板提供可选采用说明及研发配置。REPO.md 记录项目实际消费者及配置入口，个人机器位置留在本地配置或 USER.md。

当前仅接入目录资源，不迁移、删除、上传内容或改消费者。Windows 两种合成场景已验证，其他系统及真实应用接入仍需对应环境证据。设计不包含已实现的实体迁移或跨设备同步能力。
