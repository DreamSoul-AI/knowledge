# 研发资源共享示例

多个研究或开发 repo 经常使用同一份数据和模型，也可能复用其他项目的实验结果、检查点或图表。本示例通过目录符号链接，让资源保留在明确的真实目录，各仓库仍有自己的访问入口，减少重复存放。

[研发配置](research.config.example.json) 中，两个仓库共享 data 和 models，artifacts 则按项目分别保存。这种组织便于区分产物归属。需要共享某份产物时，可把相应目录声明为一个资源，再将多个仓库的入口映射到它。共享哪些产物由配置明确，工具不会默认把所有结果混在一起。

示例的真实资源位于 `shared/data/`、`shared/models/` 和 `shared/artifacts/<项目名>/`，仓内入口使用 `.shared/data`、`.shared/models` 和 `.shared/artifacts`。`.shared/` 本身是普通目录，其下的资源入口才是符号链接。data 按数据集名、models 按模型名组织，不增加课题名层级。

配置中的路径和名称只是研发惯例，使用者按本机实际目录填写。个人路径留在本地配置，项目采用的入口及消费者可写入 REPO.md。其他资源类型使用相同映射机制，详见 [工具说明](../README_zh.md)。

工具建立的是路径关系，不会同步两台机器、迁移已有数据或自动改变程序的读取位置。先预览，再核对资源、权限和消费者，最后按明确范围执行。

旧配置仍可使用；采用新命名时，由项目或工作区维护流程将相关共享入口从 `.local/` 改为 `.shared/`，同步配置、消费者和 Git 忽略。资源目标不变，其他用途的 `.local/` 保留，详见[已有入口调整](../README_zh.md#已有入口调整)。
